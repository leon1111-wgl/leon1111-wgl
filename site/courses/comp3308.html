Model a problem, then choose a frontier

01 / The story

Imagine a delivery robot inside a museum. A state might record only its room, but that description fails if some doors require a key: two visits to the same room can have different futures. Recording the room and key status repairs the model. The robot then keeps a tray of unfinished routes. A queue explores nearby rooms first; a stack follows one corridor deeply; a priority tray follows the cheapest journey so far. The analogy separates two decisions: describe enough of the world to predict legal moves, then choose which unfinished route deserves attention.

02 / The principle

A search problem specifies an initial state, actions, a transition model, a goal test and path costs. Search nodes also store parent links and accumulated cost; multiple nodes may represent the same state. Breadth-first search uses a FIFO frontier and finds a shallowest goal with finite branching, giving minimum cost when steps have equal cost. Depth-first search uses a stack, needs little frontier memory, but can follow an infinite branch and is not generally optimal. Depth-limited search can miss deeper goals. Iterative deepening repeats increasing limits, retaining depth-first memory with shallowest-goal completeness under finite branching. Uniform-cost search removes the smallest accumulated cost and tests goals on removal; on infinite spaces its usual completeness guarantee needs costs bounded below by a positive number.

03 / The formula

g(n) = Σ edge costs along the route to n
BFS: minimum depth; DFS: maximum current depth; UCS: minimum g(n)
BFS tree frontier: O(bᵈ); DFS tree frontier: O(bm); IDS: O(bd)

The symbol g(n) is the cost already paid to reach search node n. The summation adds every edge on that route, not just the last edge. Here b is the finite branching factor, d the shallowest solution depth, and m the maximum search depth. The memory bounds describe conventional tree-search frontiers; a graph-search visited set adds storage. Frontier order describes which node is expanded next, not the final path itself.

04 / A worked example

A robot has routes S→A costing 1, A→G costing 9, S→B costing 4 and B→G costing 2. Both goals lie two edges away. If A is generated first, breadth-first search can return S→A→G, costing 10. Uniform-cost search removes S, then A with cost 1, then B with cost 4. Its goal candidates have costs 10 and 6, so it removes the cost-6 candidate and returns S→B→G. Parent links reconstruct that route. The expansion list S,A,B,G is not itself a legal route.

Watch out. Calling depth-limited search complete merely because it terminates confuses termination with finding an existing goal. Its limit must reach a solution, and cycle handling must match the chosen state representation.
Check your understanding: When does breadth-first search behave like uniform-cost search?

When every step has the same positive cost and tie handling is aligned: accumulated cost is a constant times depth, so both expand layers in the same order.

A* and trustworthy lower bounds

01 / The story

Suppose a courier chooses between partly completed journeys. Looking only at money already spent rewards cheap starts that may have expensive endings. Looking only at a map estimate rewards routes that appear close to the destination despite costly detours already taken. A* writes both numbers on each route card. Its remaining-cost estimate must behave like a defensible lower quote, not an optimistic marketing promise with arbitrary values. A relaxed map, where some obstacles disappear, supplies such a quote. Better lower quotes save exploration, although calculating them can itself be expensive.

02 / The principle

A* expands the frontier node minimizing accumulated cost plus estimated remaining cost. Admissibility means the estimate never exceeds the true cheapest remaining cost. Consistency additionally bounds each estimate by one step plus the successor estimate; with zero goal estimates it implies admissibility and nondecreasing f along paths. Tree-search A* is optimal with an admissible heuristic under the usual termination assumptions. Graph search can safely close nodes permanently with a consistent heuristic; an admissible but inconsistent heuristic can require reopening a state when a cheaper route appears. Test the goal when selected for expansion. Finite branching and a positive lower step-cost bound support completeness in infinite spaces. Memory is often the practical bottleneck; IDA* trades repeated work for bounded depth-first storage.

03 / The formula

f(n) = g(n) + h(n)
Admissible: 0 ≤ h(n) ≤ h*(n)
Consistent: h(n) ≤ c(n,n′) + h(n′)
hmax(n) = max(h₁(n), …, hₖ(n))

Here h(n) estimates the remaining cost and h*(n) is the true minimum remaining cost. The edge from n to n′ costs c(n,n′). Thus f is a lower bound on a solution through n when h is admissible. Taking the maximum of several admissible heuristics preserves admissibility; summing them generally does not. A dominating heuristic is at least as large everywhere, but total runtime also depends on its computation cost and tie handling.

04 / A worked example

Consider S→A of cost 2, A→G of cost 3, S→B of cost 1 and B→G of cost 8. Set h(A)=3, h(B)=1, h(S)=2 and h(G)=0. After expanding S, A has f=5 while B has f=2. Expanding B generates a goal with g=9, but A remains at f=5. A is expanded next and creates a better goal with g=5. Only when this goal is removed does search finish. All heuristic values are admissible and consistent; stopping at the first generated goal would return the wrong answer.

Watch out. Admissibility alone does not justify discarding every later route to a closed state. Use consistency or implement cheaper-path reopening correctly.
Check your understanding: For a sliding-tile puzzle, why is Manhattan distance admissible when the blank is excluded?

Each move shifts one numbered tile by one grid step. Every tile must cover at least its Manhattan displacement, so the sum cannot exceed the number of required moves. Counting the blank as well can double-count progress.

Hill climbing, restarts and beam search

01 / The story

A venue planner adjusts a seating arrangement to reduce awkward pairings. The route taken through previous arrangements is irrelevant; only the final arrangement matters. Hill climbing resembles keeping one layout on the desk and accepting the best nearby improvement. A local beam keeps several candidate layouts, but if they all look almost identical, the extra desks provide little exploration. Random restarts resemble beginning with a fresh seating plan rather than endlessly rearranging a stubborn one. This analogy fits optimization of complete configurations, but it does not establish that nearby layouts reveal the quality of distant arrangements.

02 / The principle

Local search evaluates complete candidate states with an objective and a neighborhood relation. For minimization, steepest descent chooses the neighbor with smallest objective, moving only when improvement is allowed. It can stop at a local minimum, stall on a plateau or struggle on a ridge whose useful direction is absent from the allowed moves. Sideways moves, richer neighborhoods, limited lookahead and random restarts alter this behavior. Local beam search expands successors of k current states and retains the best k globally; it is not simply k independent hill climbers. A levelwise beam search similarly discards candidates outside its beam. Permanent pruning saves memory but can remove every route to a goal, so neither ordinary beam search nor ordinary hill climbing is generally complete or optimal.

03 / The formula

snext ∈ argmin{V(u) : u ∈ N(s)}
Restart success probability after r independent runs = 1 − (1 − p)ʳ

V(s) is the objective value of configuration s, with smaller values preferred here. N(s) is the set of allowed neighboring configurations. The argmin notation means a state attaining the lowest score, with a separate tie rule. In the restart expression, p is one run’s probability of reaching a desired solution and r counts independent runs with the same success probability. The expression does not apply unchanged to correlated restarts or changing budgets.

04 / A worked example

A current timetable scores 12 conflicts. Its neighbors score 9, 10 and 14, so steepest descent chooses the score-9 timetable. Its next neighbors score 11, 12 and 9. A strict-improvement rule stops, although another distant timetable scores 0. A beam of width 2 would initially retain scores 9 and 10, potentially exploring an escape through the second candidate. Suppose independent random restarts each find a zero-conflict timetable with probability 0.2. Five runs succeed with probability 1−0.8⁵=0.67232, about 67.2%. This quantifies improvement in chances without claiming certainty after five runs.

Watch out. Keeping the best k successors of each beam member creates up to k² candidates and describes a different algorithm from retaining the best k across the combined successor pool.
Check your understanding: Why can allowing unlimited equal-score moves make hill climbing worse?

It can cycle indefinitely across a plateau. Bound sideways moves, track repeated states or use a deliberate stochastic exploration policy.

Simulated annealing and genetic search

01 / The story

A landscape photographer wants a high viewpoint but must sometimes walk downhill to reach a better ridge. Early in the day, exploration is affordable; near sunset, risky detours become less attractive. Annealing captures that changing willingness to accept a worse step. Genetic search instead resembles maintaining many candidate itineraries, combining promising segments and occasionally making a surprising change. The biological language is only a design metaphor: crossing two good itineraries can create an impossible trip, and a fitness score can reward the wrong thing. Both methods depend on how candidates, neighborhoods and objectives are encoded.

02 / The principle

Simulated annealing samples a neighbor and always accepts an improving move; a worsening move is accepted with a probability controlled by its loss and the current temperature. Cooling reduces exploratory moves. Asymptotic convergence results require restrictive cooling and connectivity assumptions and do not guarantee an optimum for an ordinary finite run. A genetic algorithm maintains a population, selects parents according to fitness, recombines their encodings and applies mutation. Selection intensifies exploitation; mutation and population diversity support exploration. Constraints may require a representation that always remains valid or an explicit repair or penalty method. Elitism can retain the best candidate but does not prove global optimality. Always report the best objective found and the computational budget, rather than presenting one stochastic run as a proof.

03 / The formula

Δ = V(candidate) − V(current)
P(accept) = min(1, exp(−Δ/T)), T > 0
Fitness-proportional selection: P(i) = Fᵢ / Σⱼ Fⱼ

V is an objective to minimize, so a positive Δ means deterioration. T is the positive temperature on the same scale as the objective difference. The exponential gives a number between zero and one for worsening moves. Fᵢ is a nonnegative fitness to maximize for individual i; the selection denominator must be positive. Objective values and fitness are different conventions, so a cost may need a justified transformation before fitness-proportional selection.

04 / A worked example

A routing candidate costs 40 and a proposed neighbor costs 44, so Δ=4. At temperature 8, acceptance probability is exp(−0.5)≈0.6065; at temperature 2 it is exp(−2)≈0.1353. A uniform random draw of 0.3 accepts the first proposal but rejects the second. Separately, three genetic candidates have fitnesses 2, 3 and 5, giving selection probabilities 0.2, 0.3 and 0.5. Crossing bit strings 1100 and 0011 after the second position produces 1111 and 0000. Their fitness must be evaluated afresh: parent quality does not determine child quality.

Watch out. Do not state that annealing is always complete and optimal because a slow-cooling theorem exists. Its limiting assumptions and infinite-time statement differ from a practical schedule.
Check your understanding: What happens if a fitness-proportional scheme is given negative fitness values?

They cannot define selection probabilities. Use an appropriate nonnegative transformation, rank selection or another explicitly defined selection scheme, and examine how the transformation changes selection pressure.

Minimax and alpha–beta bounds

01 / The story

Two players alternately choose which corridor a token follows through a maze. At the exit, one receives the number printed there and the other loses the same amount. A tempting corridor may contain a wonderful exit that the opponent will never permit. Minimax evaluates what each player can enforce, working backward from exits. Alpha–beta pruning is like closing a corridor after proving that an earlier choice already guarantees something better. It is a proof that further inspection cannot change the present decision, not a guess that an unexplored corridor probably looks uninteresting.

02 / The principle

For a finite deterministic two-player zero-sum game with perfect information, minimax backs up maximum values at MAX nodes and minimum values at MIN nodes. Exact terminal utilities yield an optimal strategy against optimal opposition; a weaker opponent cannot force a worse value if MAX continues to follow a minimax strategy. Alpha–beta performs the same depth-first backup while carrying bounds from ancestors. Alpha is a lower bound already available to MAX, and beta an upper bound available to MIN. Once alpha is at least beta, remaining siblings cannot improve the relevant ancestor’s decision. The root value equals full minimax, although tied move selection can differ. Move ordering changes pruning efficiency; worst-case work remains exponential, while ideal ordering can roughly double reachable depth for a fixed budget.

03 / The formula

V(s) = U(s) at terminal states
V(s) = max V(child) at MAX; min V(child) at MIN
Prune when α ≥ β
Full-tree time O(bᵐ); depth-first space O(bm)

U(s) is a terminal payoff measured from MAX’s perspective. V(s) is the backed-up value, and child ranges over legal successors. Alpha and beta describe bounds relevant to the current search path, not independent global scores for all nodes. Here b is branching factor and m the searched depth. The storage expression assumes depth-first traversal with successor lists; storing the whole game tree would have a much larger memory cost.

04 / A worked example

MAX has three moves leading to MIN nodes. Their leaves, visited left to right, are A:[5,7], B:[3,100], and C:[6,4]. A returns 5, so root alpha becomes 5. At B, seeing its first leaf 3 sets beta to 3. Since beta≤alpha, leaf 100 can be skipped: MIN can already limit B to at most 3. At C, the first leaf 6 does not permit pruning, so inspect 4 and return 4. MAX chooses A, guaranteeing 5. The pruned leaf could be enormous without changing the choice.

Watch out. Use the same utility perspective throughout the tree. Alternating the sign informally while also applying MIN can reverse the decision twice.
Check your understanding: Does alpha–beta make a shallow heuristic evaluation more accurate?

No. It preserves the minimax result for the same searched tree and leaf values. Saved work can fund a deeper search, but pruning itself does not improve the evaluation function.

Cutoffs, chance nodes and multiple players

01 / The story

A board-game program has ten seconds to move. It cannot inspect every ending, so it stops at a horizon and estimates the unfinished positions. A position that looks profitable immediately before a forced loss illustrates the danger of a horizon. Dice add a different complication: the player cannot choose which number appears, so outcomes must be averaged according to their probabilities. Adding a third player changes the incentives again, because two opponents need not want the same outcome. Time limits, randomness and multiple interests require separate changes to the model rather than one universal game-search shortcut.

02 / The principle

A depth cutoff substitutes a heuristic evaluation for terminal utility, sacrificing exact-game optimality. Iterative deepening retains the last completed search when time expires. Quiescence search extends tactically unstable positions using selected forcing moves, but still needs termination controls. A linear evaluation combines features and may miss interactions. Expectiminimax adds chance nodes whose values are probability-weighted expectations, while MAX and MIN backups remain unchanged. Expected-utility decisions require cardinal utility: a positive affine transformation preserves preferences, but an arbitrary increasing transformation need not. Ordinary alpha–beta reasoning cannot simply ignore chance outcomes; valid pruning needs bounds on unseen values and probability mass. For more than two players, a Max-n backup carries a utility vector and each player selects its own component, without the two-player zero-sum guarantee.

03 / The formula

E(s) = Σᵢ wᵢ φᵢ(s)
V(chance) = Σⱼ pⱼ V(sⱼ), Σⱼ pⱼ = 1
Utility-preserving affine change: U′ = aU + b, a > 0

E(s) estimates the value of an unfinished state using features φᵢ and weights wᵢ. At a chance node, pⱼ is the probability of successor sⱼ and the probabilities cover all outcomes. The constants a and b rescale and shift utility; using the same transformation everywhere preserves expected-utility comparisons. A probability is not an opponent’s adversarial choice. A utility vector needs one component per player and a stated tie-breaking convention.

04 / A worked example

A player chooses a safe action worth 3 or a gamble worth 10 with probability 0.4 and 0 otherwise. The gamble’s expected utility is 0.4×10+0.6×0=4, so a player maximizing these utilities chooses it. Adding 2 and multiplying all utilities by 3 gives safe utility 11 and expected gamble utility 14, preserving the choice. Squaring the original nonnegative utilities instead gives 9 versus 40; that still agrees here, but need not for other lotteries. At a three-player node, vectors (5,1,0) and (2,4,3) make player two choose the latter because 4>1.

Watch out. A large estimated reward just beyond a cutoff is not a proven win, and a high raw neural output is not automatically a calibrated probability.
Check your understanding: A lottery pays 0 or 4 equally; a sure option pays 1.5. Does taking square roots preserve the preferred option?

No. Original expected utilities are 2 and 1.5, favoring the lottery. After square roots they are 1 and about 1.225, favoring the sure option. The nonlinear transformation changes risk preferences.

Learning tasks and nearest neighbors

01 / The story

A repair workshop estimates a new bicycle’s service time by finding similar past jobs. If past records include actual repair times, averaging nearby records is supervised regression; if they include repair categories, voting is classification. Grouping unlabeled jobs into types is clustering. Learning which repair action earns a later reward is reinforcement learning, and discovering which replacement parts co-occur is association learning. The workshop’s similarity ruler matters: measuring price in cents can overwhelm frame size in centimeters. Nearest-neighbor learning makes this choice visible because prediction is built directly from the selected examples.

02 / The principle

A supervised learner uses input–target pairs to predict unseen targets. K-nearest neighbors stores training examples and delays most computation until prediction, making it a lazy learner. Classification uses a vote among k closest examples; regression typically averages their targets, optionally with distance weights. Euclidean, Manhattan and general Minkowski distances encode different geometry. Fit scaling on training data only and apply it unchanged to validation and test data. Nominal features need a meaningful mismatch or encoding rule; arbitrary integer labels introduce false distances. Missing values require an explicit policy rather than an assumed universal penalty. Small k can follow noise, large k can blur real boundaries. Irrelevant dimensions can weaken useful neighborhoods, so feature selection and validation are important.

03 / The formula

dq(x,z) = (Σⱼ |xⱼ − zⱼ|ᑫ)^(1/q), q ≥ 1
xscaled = (x − mintrain)/(maxtrain − mintrain)
Regression: ŷ = (Σᵢ wᵢ yᵢ)/(Σᵢ wᵢ)

Vectors x and z contain corresponding features; j indexes features. Setting q to 1 gives Manhattan distance and q to 2 gives Euclidean distance. Training minima and maxima define min–max scaling; a constant feature needs a separate convention because its denominator is zero. In the regression average, i indexes selected neighbors, yᵢ is their target and wᵢ a positive weight. For inverse-distance weighting, explicitly handle an exact zero-distance match.

04 / A worked example

A one-dimensional archive contains jobs at complexity scores 1, 3, 6 and 9 with service times 10, 18, 30 and 50 minutes. A new job scores 5. Distances are 4, 2, 1 and 4, so k=2 selects scores 6 and 3. Their unweighted prediction is (30+18)/2=24 minutes. Inverse-distance weights 1 and 1/2 give (30+9)/1.5=26 minutes. These are predictions rather than guaranteed durations. With n stored jobs and d features, a brute-force query computes n distances, costing O(nd) before neighbor selection; storing the archive costs O(nd).

Watch out. Fitting normalization on the entire dataset leaks information into validation. Refit all preprocessing within each training fold.
Check your understanding: Why can converting colors red, green and blue to 1, 2 and 3 harm k-NN?

It invents an ordering and makes red twice as far from blue as from green. Use a categorical distance or justified encoding consistent with the intended notion of similarity.

1R: a useful one-feature baseline

01 / The story

A librarian wants a quick rule for predicting whether a returned item needs repair. They could inspect dozens of attributes, but first try a single one, such as binding type. For each binding type, they write the most common outcome observed in past records. They then repeat with age group and cover material, keeping the attribute that makes the fewest mistakes. This is a deliberately modest benchmark: if a complicated system cannot beat it on new records, complexity needs justification. One feature can generate several branches, so “one rule” does not mean one literal sentence or one outcome.

02 / The principle

For each candidate attribute, 1R partitions the training data by attribute value and predicts the majority class in each group. It selects the attribute whose complete rule has the smallest training error. Ties need a deterministic convention. A missing value can be treated as a distinct category, provided that policy makes sense for the data-generating process. Numeric attributes require intervals: sort values, propose boundaries and avoid tiny intervals that memorize individual labels. Minimum bucket sizes and merging adjacent same-label intervals can constrain complexity. A 1R model is interpretable and supplies a strong sanity-check baseline, but interactions between attributes are invisible to it. Attribute and discretization selection are training decisions, and final performance must be assessed on held-out observations.

03 / The formula

prediction(v) = argmax꜀ count(attribute=v, class=c)
Errors(attribute) = Σᵥ [count(v) − max꜀ count(v,c)]

The value v ranges over one attribute’s categories or numeric intervals, and c ranges over classes. Count(v,c) counts training records with both that value and that class; count(v) counts all records in the group. Subtracting its majority count gives the unavoidable training mistakes for a constant prediction in that group. Sum those mistakes across groups and compare attributes. The rule for a previously unseen category must also be specified, such as a training-set majority fallback.

04 / A worked example

Eight devices have a target label repair or keep. For cover type, metal contains three repair and one keep, while plastic contains one repair and three keep. Predicting repair for metal and keep for plastic makes one error in each group, two total. For age band, young contains two repair and one keep; old contains two repair and three keep. The best age rule makes one plus two errors, three total. The chosen 1R model therefore uses cover type, achieving 6/8=75% training accuracy. A new plastic device is predicted keep regardless of its age, exposing the model’s deliberate limitation.

Watch out. Choosing an attribute with one unique value per record can create zero training errors and useless predictions. Treat identifiers and overly fine numeric intervals with particular care.
Check your understanding: Can 1R express a rule that predicts true exactly when two binary inputs differ?

Not with either input alone on the complete balanced XOR table. Each single-feature group contains both labels equally, so interactions require a richer model.

Naive Bayes and smoothed likelihoods

01 / The story

An inbox filter combines clues such as a special offer word and an unfamiliar sender. First it asks how frequent spam is before reading either clue. Then it asks how expected each clue would be if the message were spam or ordinary mail. Combining those answers reverses the direction of reasoning from “what spam tends to contain” to “what this message probably is.” The naive step treats the clues as independent once the class is known. Repeating the same clue in several correlated forms can therefore make the filter more confident without supplying much genuinely new evidence.

02 / The principle

Naive Bayes models a class prior and one conditional feature distribution per class, then multiplies them using conditional independence given the class. This is not an assumption that every feature is equally informative: different likelihood ratios can have very different influence. For categorical data, frequency estimates need smoothing so an unseen value does not force a whole class score to zero. Numeric features can use a Gaussian density with class-specific mean and variance, or another suitable distribution. Evaluate products in log space to avoid numerical underflow. Missing observed features can be marginalized away under the model, but the winning class can change and informative missingness needs extra modeling. Normalize class scores when probabilities are required, while recognizing that a misspecified independence model may produce poorly calibrated probabilities.

03 / The formula

P(c|x) ∝ P(c) Πⱼ P(xⱼ|c)
P(xⱼ=v|c) = (N꜀ᵥ + 1)/(N꜀ + kⱼ)
Gaussian density: exp(−(x−μ)²/(2σ²))/(σ√(2π))

Here c is a class, xⱼ the jth observed feature, and the proportionality omits a denominator shared by all classes. N꜀ᵥ counts class-c records with value v; N꜀ is the number with observed values for that feature, and kⱼ is its possible category count. Laplace smoothing adds one to every category. The Gaussian expression is a density, not the probability of one exact real number; μ and positive σ are class-specific parameters.

04 / A worked example

Suppose P(spam)=0.25 and P(ordinary)=0.75. Given spam, an offer word occurs with probability 0.8 and an unfamiliar sender with probability 0.6. Given ordinary mail, the corresponding probabilities are 0.1 and 0.2. For a message with both clues, the naive scores are 0.25×0.8×0.6=0.12 and 0.75×0.1×0.2=0.015. Dividing by their sum 0.135 gives a spam posterior of 8/9≈0.8889. Separately, an unseen value among four possible categories in six class records receives smoothed probability (0+1)/(6+4)=0.1, rather than zero. Both class scores use the same evidence, so their normalization denominator is shared. A prediction compares those scores before normalization as well.

Watch out. Dropping a missing feature does not guarantee the class ranking stays unchanged. Its likelihood ratio may have been the deciding evidence.
Check your understanding: Why is multiplying P(feature) values different from naive Bayes?

Naive Bayes uses P(feature|class), so the evidence changes each class score differently. Unconditional feature probabilities would be identical factors across classes and would not provide class-specific evidence.

Validation, cross-validation and comparisons

01 / The story

A chef tunes a recipe with one group of tasters and reserves another group for the final tasting. Asking the reserved group after every adjustment turns them into tuning tasters, even if nobody changes their name. Machine-learning evaluation has the same problem: repeatedly inspecting a test score makes it part of development. Cross-validation rotates the tasting role so limited data contributes to several training runs, but recipes trained on overlapping ingredients are not statistically independent experiments. Good evaluation begins by defining which future customers the result is intended to represent, then separating development choices from the final estimate.

02 / The principle

Training estimates model parameters; validation selects hyperparameters, features, preprocessing and stopping rules; a test set estimates performance after those choices are fixed. Holdout uses one split, repeated holdout explores split variability, and k-fold cross-validation rotates the held-out fold. Stratification approximately preserves class proportions but does not solve leakage from repeated people, time order or related records; those need group-aware or chronological splitting. Fit every learned preprocessing operation within each training fold. Leave-one-out trains n models and can be expensive. Compare models on identical splits using paired differences. A classical paired t interval assumes approximately independent differences with an appropriate distribution; ordinary cross-validation folds overlap in training data, so its naive interval can be overconfident. Retraining for deployment changes the fitted model and does not create a fresh test estimate.

03 / The formula

CV score = (1/k) Σᵢ scoreᵢ for equally sized folds
d̄ = (1/k)Σᵢ dᵢ
sd² = Σᵢ(dᵢ − d̄)²/(k−1)
Classical paired interval: d̄ ± t* sd/√k

k is the number of paired evaluations and dᵢ is model A’s score minus model B’s score on the same evaluation data. The bar denotes a mean and sd the sample standard deviation of differences. The critical value t* depends on the confidence level and k−1 degrees of freedom. This interval is a statistical model with assumptions, not an automatic certificate of superiority. Unequal fold sizes can require weighting when estimating pooled per-example performance.

04 / A worked example

A dataset has 120 independent observations. In six-fold cross-validation, each run trains on 100 and evaluates on 20. Every observation is evaluated once, although training sets overlap. Suppose two models’ paired score differences across five separate, suitably independent experiments are 0.02, 0.04, 0.03, 0.01 and 0.05. 02 / The principle

Accuracy counts all correct decisions, precision asks how trustworthy positive predictions are, and recall asks how many actual positives are recovered. F1 is their harmonic mean and does not use true negatives. Class imbalance can make accuracy high for a useless majority predictor. Define what to do when a metric denominator is zero, and choose macro, micro or weighted averaging deliberately in multiclass tasks. 03 / The formula

Accuracy = (TP+TN)/N
Precision = TP/(TP+FP); Recall = TP/(TP+FN)
F1 = 2TP/(2TP+FP+FN)
Total error cost = cFP·FP + cFN·FN

TP counts true positives; FP false positives; FN missed positives; TN true negatives; N is their sum. The positive class must be named before computing the metrics. cFP and cFN are application-specific costs per corresponding mistake, assumed constant in this simplified expression. Decision trees, entropy and information gain

01 / The story

A museum guide identifies an artifact by asking a sequence of questions. A helpful first question divides the collection into groups that are much easier to identify. A question that almost always receives the same answer teaches little; a question that identifies every item by its catalogue number memorizes the collection without helping with new arrivals. Decision-tree learning formalizes this choice by measuring uncertainty before and after a question. Each branch then asks its own follow-up question using only the artifacts that reached it. This local process creates a readable decision procedure, although locally useful questions need not produce the globally smallest tree.

02 / The principle

A classification tree tests an attribute or threshold at each internal node and predicts a class at a leaf. ID3 greedily chooses high information gain, partitions the data and recurses on each subset. Entropy measures uncertainty in the class distribution; information gain subtracts the size-weighted child entropy from parent entropy. Pure nodes have entropy zero. If no informative split remains, predict a majority class rather than continuing forever; empty branches need a fallback based on available parent data. Numeric threshold tests produce axis-aligned boundaries, whereas categorical tests branch on values. A tree can represent complex finite mappings, but conflicting labels for identical features cannot be perfectly classified by a deterministic function. Learning a compact generalizable tree requires more than reducing training entropy.

03 / The formula

H(Y) = −Σ꜀ p꜀ log₂ p꜀, with 0 log₂ 0 defined as 0
IG(S,A) = H(S) − Σᵥ (|Sᵥ|/|S|)H(Sᵥ)

p꜀ is the fraction of observations in class c. The logarithm base two measures entropy in bits; the zero-probability term is defined by its limit, not by claiming log₂0 equals zero. S is the current training subset, A a candidate attribute and Sᵥ a child subset. Its weight |Sᵥ|/|S| is the fraction routed to that branch. Information gain therefore averages uncertainty over examples, not equally over differently sized branches.

04 / A worked example

A node contains eight artifacts: four class A and four class B, so entropy is 1 bit. A proposed question creates one child with three A and one B and another with one A and three B. Each child has entropy −0.75log₂0.75−0.25log₂0.25≈0.8113 bits. The weighted child entropy is also 0.8113, giving gain 0.1887 bits. A second question creates two pure four-item children, giving child entropy 0 and gain 1. On this training data, the greedy rule selects the second question. Whether it generalizes depends on how the question was obtained and validated.

Watch out. Do not average child entropies without weighting by child size. A tiny pure branch should not outweigh a large mixed branch.
Check your understanding: What is the entropy of four equally likely classes, and why?

It is −4×(1/4)×log₂(1/4)=2 bits. There are four equally plausible labels, so two binary bits are needed on average in the ideal coding interpretation.

01 / The story

An automated gate awards points for several badge features, adds a baseline adjustment, and opens when the total reaches a threshold. Each feature’s weight determines how strongly it pushes the decision. When a known valid badge is rejected, a perceptron update nudges the scoring rule toward that badge; when an invalid badge is accepted, it nudges the other way. Geometrically, this rotates or shifts a separating boundary. A single boundary cannot isolate every possible pattern: accepting two opposite corners of a square while rejecting the other two demands more than one straight dividing line.

02 / The principle

An artificial neuron computes a weighted input sum plus a bias, then applies an activation function. A perceptron uses a hard threshold and therefore forms a linear decision boundary. With binary targets 0 and 1, its error is target minus prediction; each mistaken example changes weights in proportion to its input and updates the bias. An epoch is one pass through the training data. For a finite linearly separable dataset, standard perceptron learning converges after finitely many mistakes under its usual update conditions. Nonseparable data need a stopping budget or another objective. The algorithm finds a separator, not necessarily the largest-margin separator. A multi-neuron hidden layer can combine linear tests to represent nonlinear patterns such as XOR, but the original single-perceptron update does not directly solve multilayer credit assignment.

03 / The formula

z = w·x + b; a = 1 if z ≥ 0, otherwise 0
e = t − a
w ← w + ηex; b ← b + ηe
Boundary: w·x + b = 0

x is the input vector, w a matching weight vector, b the bias, z the pre-activation and a the binary output. The target t uses the same 0/1 convention. Eta, written η, is a positive learning rate. The dot denotes a dot product. Weight updates must use the prediction made before the update. The normal vector w is perpendicular to the decision boundary, while b moves that boundary without changing its orientation.

04 / A worked example

Take x=(2,−1), target t=1, initial weights w=(0.2,0.4), bias b=−0.3 and learning rate η=0.5. The score is 0.2×2+0.4×(−1)−0.3=−0.3, so prediction a=0 and error e=1. Update weights to (0.2,0.4)+0.5×(2,−1)=(1.2,−0.1), and bias to 0.2. Re-evaluating this example gives 1.2×2+(−0.1)×(−1)+0.2=2.7, hence output 1. This example is now correct, but previously correct examples may have changed sides. Check the full training set before claiming an epoch has achieved separation. The update changed both orientation and offset of the boundary. Keeping the bias fixed would describe a different algorithm with a different sequence of future classifications.

Watch out. A zero score needs an explicit threshold convention. Switching between greater-than and greater-than-or-equal during a trace changes updates.
Check your understanding: Why can a perceptron without a bias fail on data separable by an ordinary straight line?

Its boundary is constrained to pass through the origin. A bias supplies the offset needed for separators that do not pass through the origin.

Multilayer networks and backpropagation

01 / The story

Imagine a workshop with several processing stations. The final product is wrong, but blaming only the last station misses how earlier stations shaped its input. Backpropagation traces how a small change at each station would influence the final error. Each station receives downstream sensitivity and multiplies it by its own local sensitivity. This is a chain-rule calculation, not an instruction to send the original target unchanged to every hidden unit. The forward pass saves intermediate values; the backward pass reuses them. All gradients describe the same current workshop configuration before the optimizer changes any of its settings.

02 / The principle

A multilayer perceptron composes affine transformations with nonlinear activations. Without nonlinearities, stacked affine layers collapse to one affine map. Categorical inputs often use one-hot encodings or learned embeddings; output choices depend on the task, with one sigmoid common for binary classification and softmax common for exclusive multiclass classification. Backpropagation efficiently differentiates a chosen loss through the computation graph. For sigmoid units and half squared error, output sensitivities combine prediction error with the sigmoid derivative; hidden sensitivities combine downstream sensitivities through outgoing weights. Compute all gradients using the forward-pass parameter values, then update. A universal approximation theorem concerns the existence of sufficiently large networks under stated function and domain conditions; it does not guarantee that a particular architecture or training run finds suitable parameters.

03 / The formula

σ(z) = 1/(1+exp(−z)); σ′(z) = σ(z)(1−σ(z))
L = ½Σᵢ(aᵢ−tᵢ)²
δᵢ = (aᵢ−tᵢ)aᵢ(1−aᵢ) at output
δⱼ = aⱼ(1−aⱼ)Σᵢ wᵢⱼδᵢ at hidden unit
∂L/∂wᵢⱼ = δᵢaⱼ; w ← w − η∇L

a denotes a unit’s activation and t its target. Delta, δ, is the derivative of loss with respect to a unit’s pre-activation. The weight wᵢⱼ connects source j to destination i. A hidden unit has no direct target, so its sensitivity sums downstream contributions. The gradient symbol ∇ collects partial derivatives of the loss. These delta expressions specifically assume sigmoid activation and half squared error; another activation or loss changes the local derivative.

04 / A worked example

A tiny network has input x=1, one sigmoid hidden unit with input weight 0 and bias 0, and one sigmoid output with weight 2 and bias −1. The hidden activation is 0.5; the output score is 2×0.5−1=0, so output a=0.5. With target 1, loss is 0.125. Output delta is (0.5−1)×0.25=−0.125. The output-weight gradient is −0.0625. Hidden delta is 0.25×2×(−0.125)=−0.0625, which is also the input-weight gradient. At learning rate 0.1, both weights increase by 0.00625; the output bias increases by 0.0125 and hidden bias by 0.00625.

Watch out. Do not update an outgoing weight before using it to compute the hidden gradient for the same example. That mixes parameter versions and is no longer the intended gradient.
Check your understanding: Why are independent sigmoid output scores not automatically a probability distribution over mutually exclusive classes?

They need not sum to one. Softmax explicitly normalizes scores across classes; even normalized scores still require empirical calibration checks before strong probabilistic claims.

01 / The story

A hiker descending a valley chooses a direction from the local slope and a step length from a training policy. Tiny steps take a long time; large steps can jump across the valley and climb the opposite side. Momentum gives the hiker some persistence, smoothing alternating directions but sometimes carrying them too far. Neither a flat slope nor a low training loss proves the hiker has reached the best destination.

02 / The principle

Gradient descent updates parameters opposite the loss gradient. Full-batch updates average all training examples; stochastic updates use one example; minibatches trade gradient noise against efficient computation. Learning rate controls step size and can determine whether training converges or diverges. Momentum accumulates past update directions, while adaptive methods rescale updates using gradient history. Random, appropriately scaled initialization breaks symmetry between hidden units. Input scaling helps optimization, but must be learned without leakage. Deep sigmoid networks can suffer vanishing gradients because many small derivatives multiply. Monitor validation loss, retain the best checkpoint and stop after a defined patience period. 03 / The formula

vₜ = μvₜ₋₁ − η∇L(θₜ); θₜ₊₁ = θₜ + vₜ
Lregularized = Ldata + λ||w||²/2
Inverted dropout: ã = ma/q, m ~ Bernoulli(q)

Theta, θ, denotes parameters and v their update velocity. Eta is learning rate and μ the momentum coefficient, usually between zero and one. Lambda, λ, controls an L2 penalty on selected weights. This does not mean any individual training forward pass equals inference.

Watch out. Decreasing training loss while validation loss worsens is a reason to revisit complexity or stopping. Continuing until training error vanishes is not a general learning objective.

02 / The principle

01 / The story

Three weather spotters may outperform one if they make different mistakes. If they all read the same broken thermometer, their unanimous vote adds little. Ensembles depend on this distinction between multiple models and useful diversity. Bagging gives learners different resampled histories. A random forest also limits which features each split may inspect. Boosting instead builds a sequence in which later learners focus on what the current collection handles poorly. The committee analogy is useful, but models are not independent witnesses: shared training data, shared features and shared biases can make their errors strongly correlated.

02 / The principle

Bagging trains base learners on bootstrap samples drawn with replacement and aggregates votes or numeric predictions. It often reduces variance for unstable learners such as deep trees. A random forest adds random feature subsets at individual splits, aiming to decorrelate trees while keeping them useful. AdaBoost maintains a distribution over training examples, fits a weak classifier and increases relative emphasis on mistakes before the next round. Its final vote weights learners using their weighted error, rather than raw unweighted accuracy alone. Gradient boosting instead fits successive learners to a loss-related correction such as a negative gradient. Diversity and adequate accuracy can help ensembles, but neither independence nor improvement is guaranteed in practice. Extra models cost training time, storage and prediction work; noisy labels can attract harmful boosting attention.

03 / The formula

Predictions hₜ and labels yᵢ use −1/+1 values. Epsilon is weighted error and alpha the learner’s vote weight. The shown AdaBoost formula assumes 0<εₜ<0.5; zero error and non-improving learners require explicit special handling. Renormalize the next distribution to sum to one.

After exponential reweighting and normalization, the mistaken example has weight 1/2, while each correct example has weight 1/6. The next learner is trained against that changed distribution. This arithmetic explains the mechanism without assuming its future test error will decrease.

Draws use replacement. A given record is absent with probability (1−1/n)ⁿ, approaching e⁻¹, so only about 63.2% of distinct records appear on average for large n.

Joint distributions, conditioning and Bayes

01 / The story

A warehouse alarm sounds more often during equipment faults, but it also sounds occasionally during routine vibration. Hearing it changes belief about a fault; it does not prove a fault occurred. A useful calculation keeps a ledger of every combination: fault and alarm, fault without alarm, no fault with alarm, and neither. Summing rows gives overall frequencies; restricting attention to alarm rows and renormalizing answers the question after an alarm. This bookkeeping explains why a reliable alarm can still generate many false alerts when faults are rare. Conditional reasoning depends on both the evidence and the prior situation.

02 / The principle

A joint probability distribution assigns nonnegative mass summing to one across complete assignments of discrete variables. Marginalization sums over variables that are not part of a query. Conditioning restricts to compatible assignments and divides by the probability of the evidence, which must be positive. The product rule yields the chain rule, decomposing a joint into conditional factors. Bayes’ rule reverses conditioning by combining likelihood with prior probability. Independence means a joint factorizes without conditioning; conditional independence means it factorizes after a specified variable is known. Neither type generally implies the other. Normalize unnormalized class scores only after summing all relevant hidden possibilities. Probability is a formal model of uncertainty; a frequency estimate is one way to obtain it, not the only interpretation.

03 / The formula

P(A|B) = P(A,B)/P(B), P(B)>0
P(A|B) = P(B|A)P(A)/P(B)
P(A) = Σᵦ P(A,b)
A ⟂ B | C: P(A,B|C) = P(A|C)P(B|C)

A and B denote events or variable assignments; the comma means both occur and the vertical bar means given. The sum ranges over a complete set of mutually exclusive values b. C is the variable or evidence that makes A and B conditionally independent in the last expression. The independence symbol applies to the stated conditioning set only. All formulas use a consistent probability model and require conditioning events to have positive probability.

04 / A worked example

Suppose a machine fault occurs with probability 0.02. The alarm sounds with probability 0.9 during a fault and 0.05 without one. The joint fault-and-alarm mass is 0.02×0.9=0.018. The no-fault-and-alarm mass is 0.98×0.05=0.049. Thus P(alarm)=0.067 and P(fault|alarm)=0.018/0.067≈0.2687. In a hypothetical 10,000 operating periods, expected counts are 180 true alarms and 490 false alarms. The alarm raises fault probability substantially above 2%, yet most alarm periods still have no fault. These are illustrative model probabilities, not an empirical reliability claim. The two joint alarm cases are mutually exclusive and exhaust all ways the alarm can sound.

Watch out. Do not swap P(alarm|fault) with P(fault|alarm). They answer different questions and are equal only in special cases.
Check your understanding: If two variables become independent after a common cause is observed, must they also be independent before it is observed?

No. Mixing over the unobserved common cause can create dependence. Learning one effect can then change belief about the cause and consequently about the other effect.

Bayesian networks and inference

01 / The story

A building dashboard connects rain, a sprinkler and a wet courtyard. Drawing dependencies lets the engineer store local conditional tables instead of an enormous ledger of all combinations. The arrows tell the probability model how to factorize, but their direction alone does not certify causation. To answer whether it rained after observing wet ground, the engineer must consider the unobserved sprinkler states, not silently choose the most convenient one. Variable elimination reuses intermediate calculations, much as an accountant totals repeated subtables once. Sampling offers another route, approximating answers from many simulated assignments when exact calculation becomes expensive.

02 / The principle

A Bayesian network is a directed acyclic graph with one conditional probability table per variable given its parents. Its local Markov property makes each variable independent of its non-descendants conditional on its parents, producing a product factorization of the joint. Absence of a direct edge does not mean unconditional independence. A node’s Markov blanket comprises its parents, children and the other parents of its children. Exact enumeration sums over hidden assignments; variable elimination multiplies relevant factors and sums out one variable at a time, with complexity strongly affected by elimination order and intermediate factor size. Approximate methods include prior sampling, rejection sampling, likelihood weighting and Gibbs sampling. Rare evidence harms rejection efficiency; weighted or dependent samples introduce their own variance and convergence issues. Network structure and tables can come from data, expertise or both.

03 / The formula

P(x₁,…,xₙ) = Πᵢ P(xᵢ | parents(Xᵢ))
P(Q|e) = α Σhidden Πᵢ P(xᵢ | parents(Xᵢ))
Binary-node parameter count = Σᵢ 2ᵏⁱ

Q is the queried variable, e the observed evidence and alpha the normalization constant making the resulting distribution sum to one. The sum covers every hidden-variable assignment consistent with the evidence. kᵢ is the number of binary parents of binary node i; each parent configuration needs one independent probability for that node. The parameter-count expression assumes all variables are binary. Compact representation does not guarantee cheap inference, because products of factors can become large.

04 / A worked example

Let R denote rain with P(R)=0.2 and S a sprinkler with P(S)=0.3, independent roots. Wet-ground probabilities for (R,S)=(1,1),(1,0),(0,1),(0,0) are 0.99, 0.8, 0.7 and 0.05. Sum over S to obtain P(wet|R)=0.3×0.99+0.7×0.8=0.857, and P(wet|not R)=0.3×0.7+0.7×0.05=0.245. The unnormalized rain scores are 0.1714 and 0.196, so P(R|wet)=0.1714/0.3674≈0.4665. The network stores 1+1+4=6 independent parameters, compared with 2³−1=7 for an unrestricted joint distribution. The summation is essential because sprinkler status was not observed. Choosing just one sprinkler setting would answer a different conditional query. Observing wet ground makes the initially independent causes statistically coupled in general.

Watch out. An arrow is a dependency in a probability factorization. Interpreting it as an intervention-ready causal relationship requires additional assumptions and evidence.
Check your understanding: Why can elimination order change runtime without changing the exact answer?

The distributive law permits different summation orders, but the orders create intermediate factors of different sizes. Correct exact arithmetic gives the same marginal while memory and multiplication costs differ.

K-means, representatives and vector quantization

01 / The story

A ceramics studio wants a small set of standard glaze colors to approximate thousands of observed samples. It assigns each sample to its nearest current standard, then moves each standard to the mean of its assigned samples. Repeating this can reduce approximation error. A standard need not equal an existing sample, just as a centroid need not be a data point. If the studio must choose only available physical samples, a medoid is a different representative. The chosen distance also matters: numerical closeness in a color encoding need not perfectly match human perception, so a tidy mathematical cluster can still be unhelpful in practice.

02 / The principle

Lloyd’s k-means alternates assignment to the nearest centroid with updating each nonempty centroid to its cluster mean. Under squared Euclidean loss, each step cannot increase the objective, and standard finite-data implementations terminate at a locally stable partition subject to tie conventions. Global optimality is not guaranteed; multiple starts and k-means++ initialization can help. Arithmetic means specifically minimize squared Euclidean distances: changing the distance generally requires changing the representative update. Scale features appropriately, handle empty clusters explicitly and examine sensitivity to outliers. The number of clusters is a modeling choice, not necessarily a discovered natural truth. Centroids can form a codebook for vector quantization, replacing each input block with a centroid index. Storage savings require counting both indices and the codebook, and reconstruction becomes lossy.

03 / The formula

J = Σᵣ Σx∈Cᵣ ||x−μᵣ||²
μᵣ = (1/|Cᵣ|) Σx∈Cᵣ x
Naive iteration cost: O(nkd)
Fixed-length index bits per item = ceil(log₂k)

Cᵣ is cluster r and μᵣ its centroid, the coordinatewise mean of its members. J is within-cluster sum of squared errors, with smaller values preferred for a fixed k and dataset. Here n is number of points, k number of clusters and d feature dimension. The centroid formula requires a nonempty cluster. A fixed-length code for k representatives needs the stated number of bits; total compressed size also includes representative values and any format overhead.

04 / A worked example

For points 0, 2, 8 and 10, choose k=2 with initial centroids 0 and 8. Nearest-centroid assignment forms {0,2} and {8,10}; the updated means are 1 and 9. Assignments then stay unchanged. The objective is (0−1)²+(2−1)²+(8−9)²+(10−9)²=4. As a separate compression calculation, 100 four-byte blocks originally occupy 400 bytes. A four-entry codebook occupies 16 bytes, and 100 two-bit indices occupy 25 bytes, totaling 41 bytes before headers. The result saves storage by restricting reconstruction to four representative blocks, so exact original recovery is generally impossible.

Watch out. A decreasing k-means objective does not prove that the clusters correspond to meaningful real-world categories. Interpretation and stability need separate investigation.
Check your understanding: Why does comparing raw SSE across different k tend to favor larger k?

Adding centroids cannot worsen the best achievable SSE and can eventually give one centroid per point. Choose k using additional criteria, stability and the intended use, not SSE alone.

Hierarchies, thresholds and cluster quality

01 / The story

A mapmaker groups villages first into neighboring pairs, then districts, then regions. A hierarchy preserves several levels of resolution, so the user chooses where to cut the tree. But “nearby groups” has several meanings. One short bridge can connect two long chains under single linkage; complete linkage instead checks their most distant cross-group pair. A streaming grouping rule has another choice: a new village may join the cluster of its nearest already seen village if it lies within a threshold. That rule can depend on arrival order. Different algorithms answer different grouping questions, even when they use the same distance table.

02 / The principle

Agglomerative clustering starts with singleton clusters and repeatedly merges the closest pair under a linkage rule; divisive methods start together and split. A dendrogram records merge structure and heights, while a cut supplies an actual partition. Single linkage uses the smallest cross-cluster distance and can chain through bridge points. Complete linkage uses the largest distance; average linkage averages all cross pairs. Centroid and medoid distances provide other definitions. An online nearest-neighbor threshold method assigns a point using previously seen neighbors or creates a new cluster; specify whether clusters can later merge and how ties are handled. Evaluate cohesion and separation with measures such as silhouette or Davies–Bouldin, but internal scores favor particular geometries. Classical dense implementations store O(n²) distances; runtime depends on linkage and data structures rather than one universal bound.

03 / The formula

dsingle(A,B) = min{d(a,b): a∈A,b∈B}
dcomplete(A,B) = max{d(a,b): a∈A,b∈B}
s(i) = (b(i)−a(i))/max(a(i),b(i))
DB = (1/k)Σᵣ maxₛ≠ᵣ [(Sᵣ+Sₛ)/Mᵣₛ]

A and B are clusters. For silhouette, a(i) is point i’s mean distance to other members of its cluster and b(i) the smallest mean distance to another cluster; larger silhouette is usually better, with conventions for singletons. In Davies–Bouldin, Sᵣ is within-cluster scatter and Mᵣₛ the distance between representatives; smaller DB is usually better. Specify scatter, representative and distance consistently, and handle coincident representatives because a zero denominator can make the score undefined.

04 / A worked example

Consider one-dimensional clusters A={0,2} and B={5,9}. Their cross distances are 5, 9, 3 and 7. Single linkage gives 3, complete linkage 9 and average linkage 24/4=6. A threshold of 4 therefore permits their merge under single linkage but not complete linkage. For point 2 in partition {0,2},{5,9}, within-cluster distance a=2 and mean distance to the other cluster b=(3+7)/2=5, so silhouette is (5−2)/5=0.6. With centroids 1 and 7, average absolute scatters are 1 and 2; for these two clusters DB=(1+2)/6=0.5. Every quantity uses the same one-dimensional Euclidean distance.

Watch out. Neither a dendrogram nor a self-organizing map automatically supplies one uniquely correct cluster count. A cut, threshold or interpretation is still needed.
Check your understanding: Why can a single outlying bridge point dramatically change single-link clustering?

Only the nearest cross-cluster pair controls each merge. A chain of individually short links can join groups whose endpoints are far apart.
