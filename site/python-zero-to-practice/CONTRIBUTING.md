# 一起改进教材

优先修复会让初学者卡住的地方：跳过中间步骤、未说明前置知识、预期输出不一致、题意含糊、没有边界案例。一次集中解决一到两个问题，说明学习者会因此掌握什么。

## 修改流程

1. 阅读 `source/maintenance.md` 和最近的维护记录，确认问题尚未修复。
2. 在 `source/` 修改源稿。已有题号不可重排；新题接在本章末尾。用自己的数据，写清输入、逐步处理、返回结构与精确输出。
3. 新增函数题时，为空输入、边界、错误类型与重复调用编写有意义的验收断言。每一项测试必须来自题目已经说清楚的约定。
4. 运行下列命令，提交源稿及其生成结果，不要只提交 HTML。

```bash
python3 source/build.py
python3 tools/verify_examples.py
python3 tools/check_practice.py --all --solutions
python3 tools/check_projects.py
python3 tools/package.py
```

Windows 使用 `py`。代码仅依赖标准库；基础课不引入安装复杂的框架。

## 保留已有学习成果

- 不覆盖已有 `practice/`、`notes/`、项目 `starter.py`、`TASKS.md` 或输出文件。
- `tools/generated_files.json` 检测生成文件的手改冲突。发生冲突先备份、查看差异、人工合并，不能删除清单或改摘要来绕过检查。
- 保留网页的进度存储键、题号和旧进度导入能力。测试浏览器交互使用临时独立上下文，不清空个人浏览器数据。
- 分享贡献时只提交与修改有关的文件；不要包含个人作答、进度、私人笔记、密钥、虚拟环境或 `qa/` 内部证据。

## 来源与表述

参考外部项目先核对原始文件、提交、许可和前置知识。优先独立改写，记录到“开源参考与改编说明.md”。实际复用代码时保留对应许可证及署名；许可不明的材料只做链接和概念参考，不复制题目、代码或长段文字。

AI / Agent 示例说明哪些是预设规则、哪些是输入数据。不要把模拟输出叫模型推理，不把字符计数称作 token 数，不用工具执行成功证明任务正确。不得宣称 info1110 官方背书或复制未获授权的课程作业、考试、答案。

## 验证证据

更新“验证说明.md”和“维护记录.md”时写本次实际命令、结果和平台。GitHub Actions 的结果以具体运行记录为准，不把配置、历史绿灯或其他机器的结果称为本轮通过。CI 中保留只读仓库权限；不自动发布网站或 Release。
