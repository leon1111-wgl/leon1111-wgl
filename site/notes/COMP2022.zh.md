## 字符串、语言与规格

### 01 / 从一个故事开始

想象一位门卫在检查快递标签。在挑选扫描器之前，仓库必须先说清楚哪些标签是允许的，比如“任何由 A 和 B 组成、并且以 B 结尾的序列”。规格（specification）描述的就是这条规则本身，它与用来检查的设备无关。这个设备可以在面板上亮一盏小灯，可以运行一段程序，也可以去查一张对照表。

这些实现方式看上去可能截然不同，却能作出完全相同的判断。这个类比也有局限：真实的扫描器会出现机械故障，而我们研究的数学机器会严格遵守自己的规则。我们要研究的是：这些规则是否真的描述了我们想要的那一组标签。

### 02 / 理解原理

字母表（alphabet）是一个有限的符号集合；字符串（string）是由这个字母表中的符号组成的有限序列。空串 ε 的长度为零。语言（language）是所有有限字符串中的任意一个子集，它不一定是人们口头说的语言，也不一定是能用实用方法描述出来的集合。判定问题可以表示成语言的成员资格问题：答案为“是”的输入实例就属于这个语言。

规格说明的是输入范围和要求给出的答案，算法提供的则是一套求解的步骤。只有当一个实现对每一个允许的输入，其行为都满足规格时，它才是正确的。对于一般的计算问题，还要说明是否要求程序终止：只在程序碰巧结束时才答对，比“总是能给出答案”要弱。

### 03 / 逐项读懂公式

```text
Σ* = ⋃ₖ≥₀ Σᵏ;  L ⊆ Σ*;  |ε| = 0
```

Σ 是字母表，Σᵏ 是长度为 k 的所有字符串组成的集合。星号表示所有有限长度，其中包括长度为零，所以 ε 总是属于 Σ*。L 是从这个全集中挑选出来的一个语言。

这里的竖线表示字符串的长度，而不是集合的大小。这些定义只是说明了哪些输入是允许的、哪些输入的答案是“是”；它们并没有断言每一个可能的 L 都存在一台能判定成员资格的机器。

### 04 / 先看一个完整例子

取 Σ = {A, B}，并把 L 规定为以 B 结尾的字符串。B、AB 和 BAB 属于 L；ε、A 和 BAA 不属于 L。一个正确的判定过程先处理空输入，直接拒绝，然后检查最后一个符号是不是 B。

如果输入的表示方式允许，它可以直接查看最后一个字符；也可以从左到右扫描，同时记住最近读到的字符。这两种过程实现的是同一个规格。如果有一个过程只检查 B 是否在串中出现过，那么它在 BAA 上就会出错，这给出了一个具体的反例，而不只是“感觉哪里不对”的直觉。

### 先认识这些词

- **字母表:** 由允许使用的符号组成的有限集合。

- **字符串:** 由符号组成的有限的有序序列。

- **规格:** 说明允许的输入和要求的输出的一条规则。

### 一步步想清楚

**为什么要把规则和扫描器分开？**

不同的过程可以满足同一条规则，所以我们必须用同一个共同的目标来评判它们。

**用 {x,y} 能写出多少个长度为二的字符串？**

两个位置各有两种选择，所以有 2×2=4 个：xx、xy、yx、yy。

**{ε} 是空集吗？**

不是。它包含一个长度为零的字符串。

### 数一数有限的一小段

在 Σ={x,y} 上，列出所有长度至多为二、并且以 x 结尾的字符串。把 ε 也算作候选输入，但要严格按字面应用“结尾”这条规则。

**先选择方法**

按长度来划分，这样既不会漏掉候选，也不会重复计数。

1. 长度为零的只有 ε。它没有最后一个 x，所以要拒绝。

2. 长度为一的有 x 和 y。只有 x 以 x 结尾。

3. 长度为二的有 xx、xy、yx、yy。检查第二个位置，保留下来的是 xx 和 yx。

**解释最终答案**

所选出的这一小段语言是 {x,xx,yx}，共包含三个字符串。

**检验推理**

对于正的长度 n，固定最后一个 x 之后，前面还有 2^(n−1) 种选择。n=1 和 n=2 时得到 1+2=3，与上面一致。

### 修正一个错误的检查

规则是“二进制输入恰好包含两个 1”。有人提出的检查是：只要长度为二就接受。请用 10 和 101 测试它，然后给出一个正确且会停机的过程。

**先选择方法**

先把这个提议的条件和真实的计数作比较，再把条件换掉。

1. 对于 10，长度为二，所以这个提议会接受。但它的 1 只有一个，所以要求的答案是“否”。

2. 对于 101，长度为三，所以这个提议会拒绝。但它的 1 有两个，所以要求的答案是“是”。

3. 把这个有限的输入扫描一遍，每遇到一个 1 就加一。读完最后一个符号后，仅当计数恰好等于二时才接受。

**解释最终答案**

只看长度的检查既会错误地接受，也会错误地拒绝。计数的过程在读完全部输入符号之后就会停机。

**检验推理**

空串的计数为零，会被拒绝；而 11 的计数为二，会被接受。

### Leon 的进一步思考

**先检查输入是否合法**

如果字母表是 {x,y}，那么字符串 xz 就在输入范围之外。要先决定实现是报告输入错误，还是回答“否”；不能悄悄地改变数学上的语言。

**一个反例就足以定论**

只要有一次不一致，就足以推翻“该实现对所有输入都正确”这一论断。一千次测试成功，也无法覆盖无穷多个输入。

**注意这个边界:** 不要把 ε 和 ∅ 混为一谈：ε 是一个字符串，而 ∅ 里面一个字符串也没有。语言 {ε} 恰好有一个成员。

## 正则表达式：语言的代数

### 01 / 从一个故事开始

一家小玩具工厂只用三种指令来制造产品：在两种设计中选一种，把两个部件并排放在一起，或者把一个部件重复任意有限次。正则表达式就是一份类似的字符串配方。选择产生可替换的几种可能，连接把几段拼在一起，重复则允许副本的数量可以变化。

这份配方描述的是所有可能做出来的成品，而不是工厂制造它们的先后顺序。重复可以选择零份副本，这一点很容易被忽略。另外，这种数学上的配方并不包含某些程序库里那些功能强大的额外扩展，所以在讨论正则语言时，应当明确地只使用那几种基本运算。

### 02 / 理解原理

正则表达式是递归地由符号、空语言、空串、并、连接和 Kleene 星构造出来的。它的语义是给每一个表达式指定一个语言。并接受来自任意一个运算对象的字符串。连接接受那些可以拆成两部分的字符串：左边一部分来自第一个语言，右边一部分来自第二个语言。星允许把同一个语言中的零个或多个成员连接起来。

括号决定分组；按照通常的简写约定，星的优先级高于连接，连接的优先级高于并。这里所说的匹配，指的是整个字符串的成员资格。子串搜索是另一个任务，除非表达式明确允许任意的前后文本。正则表达式是一份规格，并不意味着必须采用某种特定的回溯实现。

### 03 / 逐项读懂公式

```text
L(R|S) = L(R) ∪ L(S)
L(RS) = {uv : u ∈ L(R), v ∈ L(S)}
L(R*) = ⋃ₖ≥₀ L(R)ᵏ
```

R 和 S 表示表达式，L(R) 表示 R 所代表的语言。表达式里面的竖线表示选择。乘积 uv 是字符串的连接，上标 k 表示把 k 段连接起来，而不是对字符串做数值上的乘方。

特别地，L(R)⁰ 是 {ε}。这些等式都是递归定义：先求出较小表达式的语言，再用相应的运算把它们的语言组合起来。

### 04 / 先看一个完整例子

考虑字母表 {a,b,c,d} 上的 R = (ab|c)*d。每一个重复的块要么是 ab，要么是 c，最后恰好跟着一个 d。依次选择块 ab、c、ab，得到 abcabd，它是匹配的。选择零个块，得到 d，它也是匹配的。

字符串 acd 不匹配：在最后的 d 之前，前缀 ac 无法划分成 ab 和 c 这样的块，因为它开头的 a 后面缺少必须跟着的 b。字符串 dcc 不匹配，因为 d 必须出现在末尾。把块的分解写出来，就能直接解释为什么它属于或不属于这个语言。

### 先认识这些词

- **并:** 接受来自任意一个选择的字符串。

- **连接:** 把一个字符串放在另一个字符串后面。

- **Kleene 星:** 把一个语言中的成员连接零次或多次。

### 一步步想清楚

**为什么零次重复很重要？**

即使重复的块是非空的，它也会把 ε 加进来。

**对于 (xy|x)*，xyx 可以怎样拆分？**

选择 xy，再接上 x，所以它属于这个语言。

**匹配了一个前缀，就能证明整个串匹配吗？**

不能。剩下的每一个符号也必须被这个表达式消耗掉。

### 分解一个新的模式

对于 R=(xy|z)*x，判断 xyzzx、x 和 zxy 是否属于它。要求整个字符串都匹配。

**先选择方法**

先把末尾必须出现的 x 分离出来，再去分解重复的前缀。

1. xyzzx 以 x 结尾。前缀 xyzz 可以拆成 xy、z、z，这些都是允许的块。

2. 字符串 x 去掉末尾的 x 后，前缀为空。星允许零个重复的块。

3. zxy 以 y 结尾，所以不论它前面的块怎么分，都无法提供最后那个 x。

**解释最终答案**

xyzzx 和 x 匹配；zxy 不匹配。

**检验推理**

如果把模式末尾的 x 去掉，语言就会改变：那样 ε 就会匹配。

### 比较星的位置

在 {a,b} 上，找一个属于 a*b* 但不属于 (ab)* 的字符串，再找一个属于 (ab)* 但不属于 a*b* 的字符串。

**先选择方法**

观察块的顺序：是成组的连续段，还是交替出现的配对。

1. 字符串 aab 是两个 a 后面跟一个 b，所以它属于 a*b*。

2. (ab)* 中每个非空字符串都是 a、b 交替出现，并且长度为偶数。aab 的长度是三，所以它被排除在外。

3. 字符串 abab 是两个 ab 块，但在第一个 b 之后又出现了一个 a。这违反了“所有 a 都在所有 b 之前”的结构。

**解释最终答案**

aab 见证了第一个方向的差异；abab 见证了反方向的差异。两个语言互不包含。

**检验推理**

两个表达式都仍然接受 ε，所以两者共有空串，并不能说明它们等价。

### Leon 的进一步思考

**表达式与实现**

表达式说明了哪些字符串属于这个语言。回溯和同时模拟多个状态在执行方式上可以不同，但它们对所有输入给出的答案是一致的。

**星不是加号**

“一次或多次”的重复可以写成 RR*。当 R 本身不能生成 ε 时，它是否省略 ε 就是区别所在，这一点很重要。

**注意这个边界:** 误以为 R* 不包含空串。零次重复总会带来 ε，即使 R 本身什么也匹配不了。

## DFA 状态：概括已经读过的内容

### 01 / 从一个故事开始

门口的计数器只需要两盏灯，就能报告进来的人数是偶数还是奇数。它并不保留每个人到达的时间。每来一个人，灯就切换一次，而当前亮着的灯已经概括了最终奇偶问题所需要的全部信息。

确定有限自动机（DFA）使用状态的方式也是这样：每个状态代表对已经读过的前缀的一份信息摘要。好的设计要从给每个状态命名它的含义开始。当任务要求精确地数出没有上限的总数时，这个类比就不再适用了，因为固定数量的灯无法记住任意多种不同的总数。

### 02 / 理解原理

DFA 有一个有限的状态集合、一个输入字母表、一个起始状态、一个接受状态集合，以及一个完整的转移函数。每次转移恰好处理一个符号。因此每个输入只有唯一的一次运行，是否接受取决于整个输入被消耗完之后到达的状态。设计状态时要围绕一个不变量：读完某个前缀之后，当前状态保证了什么信息？

对于奇偶问题，只需要区分偶数和奇数。对于固定的子串，状态可以概括最长的有用后缀。一个完整的定义要包含每一个状态与符号的转移，哪怕是转移到一个拒绝的汇点。证明正确性的方法是：先说明不变量在一开始就成立，并且在每一次转移之后都保持成立，然后再把接受状态与规格联系起来。

### 03 / 逐项读懂公式

```text
D = (Q, Σ, δ, q₀, F)
δ : Q × Σ → Q
w ∈ L(D) ⇔ δ*(q₀,w) ∈ F
```

Q 是有限的状态集合，q₀ 是起始状态，F 是接受状态的子集。δ 给出读入一个符号之后的下一个状态。δ* 把这个操作扩展到整个字符串：从 q₀ 出发，反复应用 δ，并且 δ*(q,ε)=q。

这里 δ 上的星号表示扩展的转移函数，而不是语言的重复。接受条件只在所有输入符号都读完之后才检查。

### 04 / 先看一个完整例子

构造一个 DFA，识别含有奇数个 1 的二进制字符串。使用状态 E 和 O，从 E 开始，只接受 O。读入 0 时，两个状态都保持不变。读入 1 时，E 变成 O，O 变成 E。对于 10110，状态序列是 E、O、O、E、O、O，所以输入被接受。

对于 ε，状态一直停在 E，所以被拒绝。这个不变量是精确的：E 表示已处理的前缀中 1 的个数为偶数，O 表示为奇数。这个不变量能证明规则对每一个字符串都成立，而不只是对几个例子成立。

### 先认识这些词

- **状态:** 对已处理前缀的有限摘要。

- **不变量:** 在每次转移之后都保持成立的陈述。

- **接受状态:** 如果输入恰好在这里结束，就接受的状态。

### 一步步想清楚

**为什么做模运算的计数器只需要很少的状态？**

这个问题不关心完整的总数，只需要一个余数。

**余数为二的状态，在模三下再读一个 1 会怎样？**

2+1=3，余数为零，所以转移到状态零。

**一个被接受的前缀能保证它的延长也被接受吗？**

不能。再多读一个符号，就可能改变所概括的性质。

### 跟踪一个余数机

用状态 0、1、2 表示 1 的个数模三的值。从 0 开始，并在 0 接受；读入 0 时保持不变，读入 1 时按模三加一。请跟踪 110101。

**先选择方法**

每读一个符号就记录一个状态，并用累计的计数来核对不变量。

1. 从计数为零、状态 0 开始。前两个 1 使计数变为 1、2，状态变为 1、2。

2. 接下来的 0 使状态保持为 2。再接下来的 1 使计数升到三，状态回到 0。

3. 倒数第二个 0 使状态保持为 0；最后一个 1 使计数升到四，结束在状态 1。

**解释最终答案**

完整的状态轨迹是 0,1,2,2,0,0,1。因为四不能被三整除，所以拒绝。

**检验推理**

直接数出四个 1：4 mod 3=1，与最终状态独立地吻合。

### 设计一个关注末位符号的机器

在 {a,b} 上，设计一个完整的 DFA，接受以 b 结尾的非空字符串。只能使用两个状态。

**先选择方法**

只记住最近读到的符号是不是 b；把空前缀与“拒绝”归为一组。

1. 把状态命名为 N 和 B。N 表示输入为空或最后一个符号是 a；B 表示最后一个符号是 b。从 N 开始。

2. 无论在哪个状态，读入 a 就到 N，读入 b 就到 B。这样四个“状态—符号”对就全部定义好了。

3. 输入结束后只有 B 接受。对于 bab，状态依次是 N,B,N,B；对于 ε，状态停在 N。

**解释最终答案**

这个完整的 DFA 接受 bab 并拒绝 ε，恰好遵循“末位符号”这条规则。

**检验推理**

在任何一个被接受的字符串后面加上 a，状态都会被迫变成 N，因为所要求的末位字符已经改变了。

### Leon 的进一步思考

**证明状态的含义**

对于余数机，初始化时计数为零。读入 0 时计数不变；读入 1 时，计数和余数一起增加。这两种情形证明了每一次转移，而不只是某一次运行。

**表示方式是一种设计选择**

如果要问最后一个符号是不是 1，奇偶状态就不够用了：10 和 1 的奇偶性相同，但最后一个符号不同。要针对实际的问题来选择摘要。

**注意这个边界:** 一访问到接受状态就立刻接受。后面的符号可能让自动机离开这个状态；必须把整个输入都消耗完。

## 非确定性与 ε 转移

### 01 / 从一个故事开始

假设一支队伍要按照一份印好的彩色门序列来探索迷宫。到了路口，队伍可以把每一条相容的分支都探索一遍。只要至少有一名探险者沿着整个颜色序列走完，并且停在一个被认可的房间里，任务就成功了。一条失败的分支不会取消另一条成功的分支。

有些走廊没有颜色，可以直接穿过而不用消耗序列中的任何颜色，它们就类似于 ε 转移。这只是一种推理的工具，并不是说计算机真的拥有无限多个实体探险者：一个有限的可达状态集合，就可以同时表示所有活跃的分支。

### 02 / 理解原理

NFA 允许一个“状态—符号”对有零个、一个或多个下一状态。ε 转移在不读入任何符号的情况下改变状态。接受是存在性的：只要存在某一条有限的路径，消耗完整个输入，并且终止在接受状态，就接受。其他路径即使卡住、结束在非接受状态，或者在 ε 转移上循环，也不会使另一条成功的路径失效。

NFA 往往比 DFA 更容易组合。并选择一条分支；连接把一台机器的接受点连到下一台机器；星允许重复经过，并带有一个空输入的选项。这些构造解释了如何把正则表达式转换成自动机。非确定性改变的是描述的便利程度和大小，但它并不会扩大正则语言这一族。

### 03 / 逐项读懂公式

```text
δ : Q × (Σ ∪ {ε}) → 𝒫(Q)
接受 w 当且仅当存在一条标签为 w 且终点在 F 中的路径
```

𝒫(Q) 是 Q 的幂集，所以一次转移返回的是一个由可能的状态组成的集合。标签为 ε 的转移不消耗任何输入符号。一条路径的标签，是把它上面的普通符号标签连接起来，并忽略 ε 标签得到的。

F 是接受状态集合。“存在”是最关键的量词：接受只需要一次成功的运行。缺少某个转移，意味着下一状态的集合为空，而不是让机器等待后面的符号。

### 04 / 先看一个完整例子

要识别 {a,b} 上以 ab 结尾的字符串，让起始状态在两个字母上都有自环。从这个状态出发，读入 a 还可以通向第二个状态，第二个状态读入 b 后到达一个没有出边的终态。

对于 baab，一条分支猜第一个 a 是后缀的开头，然后在下一个 a 上失败。另一条分支继续等待，猜第二个 a 才是开头，然后读入最后的 b，接受。对于 aba，有一条分支在读完 ab 之后到达终态，但它无法消耗最后的 a，所以整个字符串被拒绝。

### 先认识这些词

- **非确定性:** 一次转移可以提供多个可能的下一状态。

- **ε 转移:** 不消耗任何输入符号的状态改变。

- **存在性接受:** 只要有一次有限的、完整的、成功的运行就够了。

### 一步步想清楚

**为什么可以忽略一条失败的分支？**

接受只要求至少有一次成功，而不要求每条分支都成功。

**ε 会消耗一个空格字符吗？**

不会。它什么也不消耗；真正的空格字符只是字母表里的一个普通符号。

**提早到达终态就足够了吗？**

只有当某个成功的后续运行能消耗掉所有剩余符号时才行。

### 字母之前的免费分支

状态为 s、p、f。起始状态是 s，只有 f 接受。边有：s—ε→p、s—a→s、p—b→f，没有其他的边。判断 aab 和 ba。

**先选择方法**

在每个符号之前和之后，都维护包含所有免费 ε 转移的活跃状态集合。

1. 初始闭包是 {s,p}。每个 a 都沿 s 的自环走，然后再通过 ε 补回 p，所以读完 aa 之后集合仍是 {s,p}。

2. 最后的 b 把 p 移到 f，所以 aab 结束时活跃集合是 {f}，被接受。

3. 对于 ba，b 先产生 {f}。从 f 出发没有任何 a 的边，所以读入 a 之后活跃集合变成 ∅，输入被拒绝。

**解释最终答案**

aab 被接受；ba 被拒绝。读完某个前缀后处于终态是不够的。

**检验推理**

成功的字符串恰好是 a*b：任意多个 a，后面跟一个最后的 b。

### 为什么交换 NFA 的终态会失败

NFA 的状态为 s、f，字母表是 {a}，起始状态是 s，终态集合是 {f}。边只有 s—a→s 和 s—a→f。比较输入 a 在把终态交换为 {s} 前后的结果。

**先选择方法**

列出两个完整的运行；补应当反转整体的答案，而不是各条路径独立地反转。

1. 原来，输入 a 有两条运行，分别结束在 s 和 f。结束在 f 的那条运行接受，所以这个 NFA 接受。

2. 交换终态之后，这些运行仍然存在。现在结束在 s 的那条运行接受。

3. 因此两台机器都接受 a。真正的补机器应当拒绝 a，因为原来的机器接受了它。

**解释最终答案**

对于这个 NFA，交换终态得不到补语言。

**检验推理**

确定化之后，读入 a 只得到一个子集 {s,f}。把这个唯一子集的接受性翻转，就能正确地反转答案。

### Leon 的进一步思考

**同时模拟所有的可能性**

在读完每个前缀之后，记录可达状态的集合。如果两条路径到达同一个状态，并且剩下未读的后缀相同，那么它们未来的选择完全一样，可以合并。

**闭包里的 ε 环是有限的**

做闭包搜索时要标记已访问的状态。环 p→q→p 只会把 p 和 q 各加入一次，而不需要无休止地重复遍历。

**注意这个边界:** 通过交换接受状态与非接受状态来求 NFA 的补。存在性的接受使这个简单的技巧行不通；应当先转换成完整的 DFA。

会。NFA 的接受只问是否存在一条有限的接受运行；另一条分支的行为不会把它取消。

## 把 NFA 转为 DFA

### 01 / 从一个故事开始

控制室的显示屏可以用一组被点亮的房间，来代替一队迷宫探险者。每读入一种颜色，它就熄灭旧的灯，并点亮队伍现在可能所在的每一个房间。在读完某个给定的前缀之后，显示屏只有一种配置，尽管许多探险者可能走过了不同的路线。

这个配置就是一个 DFA 状态。ε 走廊需要多做一点额外的工作：在继续之前，要把所有能免费到达的房间都点亮。显示屏可能出现的配置非常多，因为只有几个房间的集合就有指数多个子集，即使在真实运行中只会出现其中很小的一部分。

### 02 / 理解原理

子集构造为每一个可达的 NFA 状态集合建立一个 DFA 状态。从 NFA 起始状态的 ε 闭包开始。读入一个符号时，从当前集合出发取所有对应的符号转移，然后再取一次 ε 闭包。

当一个子集与 NFA 的接受状态集合有交集时，它就是接受的。空子集是一个拒绝的汇点，只要它是可达的，就应当把它包括进来。正确性的不变量是：在读完每一个前缀之后，DFA 的状态恰好等于该前缀之后 NFA（允许 ε 转移）所能到达的全部状态。

这就证明了两者的语言相等。一台有 m 个 NFA 状态的机器，最多有 2ᵐ 个子集状态，不过实际实现通常应当只生成可达的子集，而不是把它们全部枚举出来。

### 03 / 逐项读懂公式

```text
S₀ = E({q₀})
Δ(S,a) = E(⋃q∈S δ(q,a))
S 是接受的 ⇔ S ∩ F ≠ ∅
```

E(S) 是状态集合 S 的 ε 闭包，它包含 S 本身，以及只通过 ε 边就能到达的所有状态。Δ 是新 DFA 的转移函数，δ 则属于原来的 NFA。

并集收集了每一个可能的普通 a 转移。F 包含原来的接受状态。最后的条件应当读作“至少有一个活跃的 NFA 状态是接受的”，这保持了非确定性的存在性含义。

### 04 / 先看一个完整例子

取 NFA 的状态 p、q 和 r。起始状态是 p，允许一个 ε 转移 p→q，让 p 在 a 上有自环，让 q 读入 b 到达 r，并且只有 r 接受。初始的 DFA 状态是 {p,q}。读入 a 时，p 移到 p，q 没有去处，然后 ε 闭包又补回 q，所以集合仍然是 {p,q}。

读入 b 时，只有 q 移到 r，得到 {r}。再读入 a 或 b，就得到 ∅。因此 aab 结束在 {r}，被接受；而 aaba 结束在 ∅，被拒绝。这个构造让语言 a*b 变得一目了然，而不需要去猜每一条单独的路径。

### 先认识这些词

- **子集状态:** 一个 DFA 状态，它表示几个可能的 NFA 状态。

- **ε 闭包:** 不消耗符号就能到达的所有状态，包括起始的那个集合本身。

- **汇点:** 每一个转移都回到自身的状态。

### 一步步想清楚

**为什么每次普通转移之后都要取闭包？**

因为 NFA 在读入下一个符号之前，还可以先做免费的转移。

**四个状态最多有多少个子集？**

每个状态要么包含，要么不包含，所以有 2⁴=16 个。

**每一个可能的子集都必须创建吗？**

不必。只构造可达子集的做法，会省略那些任何输入都到不了的子集。

### 构造四个可达子集

NFA 的状态为 0、1、2；起始状态为 0；终态为 2。边有：0—ε→1、1—x→1、1—y→2。字母表是 {x,y}；缺失的转移都是空集。请构造它的可达 DFA。

**先选择方法**

从闭包开始，不断探索新的子集，直到没有新的子集为止。

1. 起始状态 A={0,1}。读入 x 到达 B={1}；读入 y 到达 C={2}。

2. B 读入 x 时自环，读入 y 时到 C。C 没有普通转移，所以两个符号都到达 D=∅。

3. D 在两个符号上都自环。只有 C 包含终态 2，所以只有 C 接受。A、B、C、D 这四个子集是可达的。

**解释最终答案**

这个 DFA 有四个可达的子集状态，识别的语言是 x*y。

**检验推理**

最多有 2³=8 个子集。A 和 B 的行为完全一致，之后可以合并，得到一个更小的等价 DFA。

### 穿过一个环求闭包

ε 边有 p→q、q→r、r→q。唯一的 a 边是 r→f；只有 f 接受。起始状态是 p。求初始闭包，以及读入 a 之后的子集。

**先选择方法**

使用一个已访问集合，这样免费转移形成的环就只会被有限次地探索。

1. 先通过零次转移包含 p。从 p 加入 q；从 q 加入 r。

2. 从 r 出发的 ε 边回到 q，而 q 已经在集合里了。到此停止，E({p})={p,q,r}。

3. 读入 a 时，p 和 q 没有去处，而 r 贡献了 f。f 没有出去的 ε 边，所以下一个子集是 {f}。

**解释最终答案**

初始子集是 {p,q,r}；输入 a 最终停在接受子集 {f}。

**检验推理**

如果没有做初始闭包，p 就没有 a 转移，那么这个不正确的模拟会拒绝 a。

### Leon 的进一步思考

**闭包包含它的输入**

一个状态可以通过零次 ε 转移留在原地。如果忘记这个零步的选项，就可能使一个有效的起始状态消失。

**空子集是有用的**

一旦没有任何分支存活，之后的任何符号也无法让某条分支复活。空子集在每个符号上都回到自身，使得到的 DFA 是完整的。

**注意这个边界:** 忘记在开始时或者在读入一个符号之后做 ε 闭包。漏掉任何一次，都可能丢掉一条有效的接受路径。

一个同时包含接受和拒绝 NFA 状态的子集，能接受吗？

能。只要其中至少有一个状态是接受的，它就接受，因为这说明至少有一条 NFA 分支已经成功。

## 从自动机回到表达式

### 01 / 从一个故事开始

想象在交通图上去掉一个小车站之后重新画图。凡是进入这个车站、可能在本地绕着一个环走若干圈、然后再离开的路线，都必须用一条新的直达连接来表示。原来就有的直达路线仍然作为另一种选择保留下来。不断重复这个过程，最后只剩下起点和终点，二者之间用一份描述所有可能旅程的说明连接起来。

状态消除就是用边上的正则表达式来完成这样的压缩。最终的描述可能比原来的图长得多，而且不同的去站顺序，可能给出外观不同、但描述的旅程集合完全相同的表达式。

### 02 / 理解原理

广义 NFA 用正则表达式而不是单个符号来标记边。添加一个没有入边的新起始状态，和一个没有出边的新接受状态，并用 ε 边把它们与旧的起止状态连接起来。

缺失的边表示 ∅，平行的边用并合并。移除状态 k 时，要给每一条幸存的边 i→j 加上一个经过 k 的新选择：进入 k，在那里循环任意多次，然后离开。当只剩下新的起点和终点时，它们之间那条边上的表达式，就表示原来的语言。

再结合“表达式转 NFA”和子集构造，就可以确立：正则表达式、NFA 和 DFA 的表达能力相同。表达能力相同，并不意味着表示的大小相同，也不意味着实际执行的成本相同。

### 03 / 逐项读懂公式

```text
Rᵢⱼ ← Rᵢⱼ | Rᵢₖ(Rₖₖ)*Rₖⱼ
```

Rᵢⱼ 表示当前从状态 i 到状态 j 的边上的表达式。状态 k 是正在被移除的那个状态。新的选择依次连接：一条进入的路线、在 k 处零次或多次的循环，以及一条离开的路线。

旧的直达路线仍留在并里面。同一步消除中用到的所有边的表达式，都指这一步之前的那张图；这个公式适用于幸存的状态 i 和 j。

### 04 / 先看一个完整例子

假设一个广义自动机有起点 s、中间状态 k 和终点 f。它的标签是 s→k:a、k→k:b、k→f:c 和 s→f:d。移除 k 之后，s→f 的标签变成 d|ab*c。字符串 abbbc 是这样走的：用 a 进入，绕三次 b 的环，用 c 离开。

字符串 ac 用的是零次循环，而 d 用的是原来的直达边。字符串 abcabc 被排除在外，因为到达 f 之后没有办法重新开始。如果原来没有那条直达边，它的标签就是 ∅，得到的表达式会化简为 ab*c。

### 先认识这些词

- **广义边:** 用正则表达式标记的边。

- **消除:** 移除一个状态，同时保留所有幸存端点之间可能的路线。

- **自环:** 从一个状态回到它自己的路线。

### 一步步想清楚

**为什么要保留旧的边？**

因为有些被接受的路线从不经过被移除的状态。

**缺失的自环贡献了什么？**

它的星贡献 ε，表示绕这个环零次。

**表达式更长，就意味着是不同的语言吗？**

不是。消除的顺序会影响表示的长度，但不会改变被接受的字符串。

### 消除一个带环的中间状态

状态 s、k、f 的标签为 s→f:u、s→k:v、k→k:w|x、k→f:y，没有其他的边。移除 k，并检验 vwxwy。

**先选择方法**

把避开 k 的路线，与进入 k、循环、再离开 k 的路线分开处理。

1. 避开 k 的路线已经贡献了 u，必须保留。

2. 经过 k 的路线贡献 v(w|x)*y，因为每绕一次环都可以独立地选择 w 或 x。

3. 对于 vwxwy，取入口 v、循环 w、x、w，再取出口 y。各部分都符合要求的顺序。

**解释最终答案**

最终的表达式是 u|v(w|x)*y，并且 vwxwy 被接受。

**检验推理**

零次循环的路线 vy 也匹配；而 u 不进入 k 也仍然被接受。

### 区分“没有边”与“免费的边”

没有 s→f 的边。标签是 s→k:ε 和 k→f:ab，k 没有自环。移除 k。然后再和 s→k 这条边不存在的变体作比较。

**先选择方法**

缺失的边用 ∅ 代入，而存在的免费边用 ε 代入。

1. 在第一张图中，代入得到 ∅ | ε(∅)*ab。原来的直达选项是空的。

2. 因为 ∅*={ε}，把 ε、ε 和 ab 连接起来，得到 ab。

3. 在变体中，入口是 ∅，所以 ∅ | ∅(∅)*ab = ∅。没有任何路线能进入 k。

**解释最终答案**

免费的入口恰好允许 ab；缺失的入口则不允许任何字符串。

**检验推理**

第一张图以及它的表达式都不接受 ε，因为出口仍然需要 a 和 b 两个符号。

### Leon 的进一步思考

**每次更新只用一张旧图**

要根据消除之前的标签，来计算每一条经过 k 的路线。如果在同一步里混入刚刚更新过的标签，可能会意外地把带有不该有的重复结构的路线也算了进去。

**空语言会把连接“湮灭”**

**注意这个边界:** 消除 k 时丢掉了原来的 i→j 表达式。那些从不经过 k 的路线仍然必须被表示出来。

## 匹配策略与重复工作

### 01 / 从一个故事开始

一位图书管理员想把一长排相同的卡片分成每包一张或两张的小包。如果最后的某个要求无法满足，管理员可能会撤销最近的一个选择，换一种分法再试，然后再换一种，一次又一次地探索面对同一个剩余任务的不同排法。一位更有条理的管理员会记录下已经到达过的每一种不同情形，并把等价的尝试合并起来。

这个区别说明了：为什么一个很简短的正则表达式，在回溯引擎里也可能运行得很慢，尽管有限状态的匹配方法是可行的。模式在数学上所表示的语言，与引擎所用的搜索策略，是两个不同的层次，在评判性能时两者都很重要。

### 02 / 理解原理

成员问题问的是：整个输入字符串是否属于某个正则表达式的语言。朴素的递归或回溯匹配器，可能对同一个前缀探索许多种分解，重复处理等价的子问题。Thompson 风格的 NFA 模拟则换了一种办法：它维护一个活跃状态集合，每读入一个输入符号就更新一次这个集合，其中包括 ε 闭包。

对于由大小为 m 的表达式构造出的、状态数和边数为 O(m) 的 NFA，直接的活跃状态模拟在长度为 n 的输入上需要 O(mn) 的时间和 O(m) 的工作空间。先做确定化，则对于一个固定的、转移耗时为常数的 DFA，匹配只需要 O(n) 的时间，但是构造这个 DFA 可能需要指数多个状态。这些界针对的是基本的正则表达式；反向引用之类的扩展不在这个有限状态模型之内。

### 03 / 逐项读懂公式

```text
NFA 模拟：O(mn) 时间，O(m) 活跃状态空间
固定 DFA 模拟：预处理之后 O(n) 时间
```

m 衡量 Thompson 风格 NFA 的大小，包括它的转移，n 是输入的长度。在读入每个字符时，ε 可达性和普通转移都会被处理，并且不会无休止地重复访问已经加入的状态。

DFA 的界把自动机视为已经构造好，并且把查找转移看作常数时间。这两个界都不意味着每一个库引擎都采用了这种策略；当表达式本身也是输入的一部分时，必须把预处理的成本计算在内。

### 04 / 先看一个完整例子

考虑表达式 (a|aa)*b 和字符串 aaaaac。五个 a 可以用好几种方式分成每块一个或两个：a,a,a,a,a，或者 aa,a,aa，等等。每一种选择最后都会失败，因为必须出现的最后那个 b 并不存在。回溯策略可能要通过许多种分解，一次又一次地重新发现这个失败。

NFA 模拟会把读完同一个前缀之后到达同一个状态的分支合并起来，然后在 c 没有有效的后续时拒绝。如果把结尾换成 b，得到 aaaaab，它就匹配。这个例子说明了重复的搜索工作，而没有改变所规定的那个正则语言。

### 先认识这些词

- **回溯:** 撤销一个选择，并尝试另一条路径。

- **活跃集合:** 当前输入前缀之后所有可达的状态。

- **预处理:** 在匹配某个具体输入之前所做的工作。

### 一步步想清楚

**为什么一个很短的模式也可能很慢？**

它的执行可能重复探索许多种分解，而它们最终都导向同样的失败。

**什么信息使得两次尝试可以合并？**

相同的自动机状态与相同的输入位置，意味着相同的剩余任务。

**构造 DFA 总是很便宜吗？**

不是。子集构造可能产生指数多个状态，即使之后的匹配是线性的。

### 统计重复的分解

对于模式 (a|aa)*b 和输入 aaaaac，统计把五个 a 分成长度为一或长度为二的块的分解方式的数目。不要声称这就是引擎全部指令的数目。

**先选择方法**

设 F(n) 为分解方式的数目。按第一块的长度是一还是二来分情况。

1. F(0)=1，对应空的分解；F(1)=1，对应只有一个单块。

2. 当 n≥2 时，F(n)=F(n−1)+F(n−2)，因为去掉第一块之后，剩下的长度就是这两种之一。于是 F(2)=2，F(3)=3。

3. 继续算：F(4)=3+2=5，F(5)=5+3=8。每一种分解最后遇到的仍然是 c，而不是所需要的 b。

**解释最终答案**

共有八种分解，全部不成功。这衡量的是重复出现的备选方案，而不是一个普遍适用的运行时间。

**检验推理**

把 c 换成 b，成员判断就变成了“是”，但 a 块可能的八种分解并不改变。

### 把准备工作与匹配分开

假设一个已经构造好的 DFA 对每个符号做一次转移。三个输入的长度分别是 4、7、9。它的构造花了 30 个抽象的工作单位；每次转移花一个单位。求匹配成本和总成本。

**先选择方法**

先把每个输入的扫描成本加起来，再把一次性的准备成本只加一次。

1. 第一个输入需要四次转移；第二个需要七次。它们的小计是 11。

2. 再加上第三个输入的九次转移，得到 20 个匹配单位。

3. 把构造成本 30 只加一次，三个输入总共是 50 个单位。

**解释最终答案**

匹配成本是 20 个单位；整批的总成本是 50。线性的扫描并不会抹掉准备工作的成本。

**检验推理**

如果每个输入都要使用一个构造成本相同的新 DFA，那么准备成本就是 90，总成本是 110。

### Leon 的进一步思考

**数状态，而不是数想象出来的人**

为了判断成员资格，活跃集合里从不需要同一个状态的多个副本。路径的数目可能增长，而集合仍然很小；统计解析的个数是另一个不同的问题。

**只有在合理时才摊销准备成本**

一个固定的 DFA 被多个字符串重复使用时，可以把构造成本分摊到这些字符串上。如果每个请求都换一个新模式，把准备工作排除在外，就会导致误导性的比较。

**注意这个边界:** 因为某一个回溯实现在某个模式上花了指数时间，就断定正则表达式匹配本质上是指数级的。

## 正则语言的封闭性与判定过程

### 01 / 从一个故事开始

一个面板可以同时记录两个传感器的模式。如果第一个传感器有三种模式，第二个有四种，那么组合起来的面板最多需要十二个模式对。策略可以规定：当两个传感器都认可时通过，或者当其中任何一个认可时通过，或者当它们意见不一致时通过。

这就是两个自动机的积。选择哪些状态对作为接受对，表达的是策略，而转移的结构保持不变。检查哪些状态对是可达的，就能回答“分歧到底有没有可能发生”，这为比较两份看上去不同的规格提供了一个有限的判定过程。

### 02 / 理解原理

正则语言对并、交、补是封闭的。对于同一个字母表上的完整 DFA，积构造会跟踪一个状态对，并在每读入一个输入符号时同时更新两个分量。根据想要的布尔运算来选择接受对。求补则更简单：把完整 DFA 的接受状态和非接受状态交换。成员资格通过模拟来判定。

非空性通过图的可达性来判定：看能否从起始状态到达某个接受状态。等价性可以归约为对称差是否为空：如果没有任何可达的积状态恰好有一个分量是接受的，那么这两台机器对每一个字符串的答案都一致。因此，把正则表达式转换成 DFA，就为表达式的等价判定给出了判定过程，尽管这种转换可能导致指数级的增长。

### 03 / 逐项读懂公式

```text
δ×((p,q),a) = (δ₁(p,a),δ₂(q,a))
L₁ = L₂ ⇔ (L₁ ∖ L₂) ∪ (L₂ ∖ L₁) = ∅
```

p 和 q 分别是第一个和第二个 DFA 的状态，δ₁ 和 δ₂ 是它们各自的转移函数。δ× 是积的转移。L₁ 和 L₂ 表示这两个语言。

差集保留属于一个语言、但不属于另一个语言的字符串；这里它们的并就是对称差。这些公式假定两者使用相同的输入字母表。如果需要，在取补或取积之前，先用一个拒绝汇点把其中任何一个自动机补全。

### 04 / 先看一个完整例子

设机器 A 接受以 1 结尾的二进制字符串，机器 B 接受含有奇数个 1 的二进制字符串。要比较它们，让它们的积从（不以 1 结尾，偶数）出发。对于输入 10，A 先进入它的接受状态，然后又回到拒绝；B 在读到 1 时切换为奇数，读到 0 时保持奇数。

最后的状态对恰好有一个分量是接受的。因此 10 见证了这两个语言不同。可达性搜索可以发现这样的一个状态对，并利用前驱链接把它对应的输入还原出来。只需要一个反例就够了；检查很多个一致的字符串则不够。

### 先认识这些词

- **积状态:** 记录两台机器各自一个状态的有序对。

- **对称差:** 恰好属于两个语言之一的字符串。

- **可达性:** 是否存在一条有限的路径，从起点通向某个状态。

### 一步步想清楚

**为什么一次分歧就足够了？**

等价要求在每一个输入上都一致，所以任何一个反例都能推翻它。

**三个状态和五个状态的机器，其积的大小上界是多少？**

最多 3×5=15 个状态对，不过其中有些可能是不可达的。

**在完整的 DFA 上，交换终态可行吗？**

可行。每个输入恰好有一次完整的运行，所以把它最终的接受性翻转，就翻转了答案。

**为什么测试很多个示例单词，比搜索积图要弱？**

有限的样本可能漏掉更长的见证。积图虽然只有有限个节点，却涵盖了任何单词可能到达的每一个状态对。

### 把两条简单规则求交

在 {0,1} 上，A 接受偶数长度，B 接受以 1 结尾的字符串。构造积的接受规则，并测试 101 和 01。

**先选择方法**

分别独立地跟踪长度的奇偶和最后一个符号的状态；交需要两者都满足。

1. 使用积状态 (E,N)、(E,Y)、(O,N)、(O,Y)，起始于 (E,N)。每个符号都会切换奇偶；符号的取值决定第二个分量：1 令它为 Y，0 令它为 N。

2. 101 的长度是三，并且以 1 结尾，所以它的状态是 (O,Y)，不满足偶数长度的条件。

3. 01 的长度是二，并且以 1 结尾，所以它结束在 (E,Y)，这是唯一的接受对。

**解释最终答案**

这个交接受 01，拒绝 101；只有 (E,Y) 是终态。

**检验推理**

ε 的长度是偶数，但没有最后的 1，所以所选的起始对正确地拒绝了它。

### 寻找语言的反例

A 接受含偶数个 1 的字符串。B 接受以 0 结尾的字符串，并且拒绝 ε。在 {0,1} 上，找出一个最短的分歧，并把 ε 也考虑在内。

**先选择方法**

在探索任何边之前，先检查起始对；空单词的长度是零。

1. 在 ε 上，A 见到的 1 的个数是零。零是偶数，所以 A 接受。

2. B 明确地拒绝 ε，因为它没有最后一个符号。所以起始对就已经出现了分歧。

3. 没有任何字符串的长度小于零，所以不可能有更短的分歧。

**解释最终答案**

ε 是一个最短的反例，这两个语言在它们的起始状态就已经不同。

**检验推理**

字符串 0 被两者都接受，这说明如果只从非空的例子开始，可能会漏掉最容易的见证。

### 在两台机器中跟踪单词 aba

比较“包含 ab”与“以 ab 结尾”。两台机器都从 0 开始，并且只接受状态 2。使用程序里的转移表。

**先选择方法**

读入每个字母之后都记录状态对，只有在读完整个单词之后才比较接受性。

1. 从 (0,0) 开始。读入 a 之后，两者都到达状态 1，得到 (1,1)。

2. 读入 b 之后，状态对是 (2,2)。前缀 ab 被两者都接受。

3. 读入最后的 a 之后，状态对是 (2,1)。只有“包含 ab”接受。

**解释最终答案**

aba 属于对称差，所以这两个语言不相等。

**检验推理**

长度小于 3 且包含 ab 的单词，只有 ab 本身；它也以 ab 结尾。因此不存在更短的见证。

### 找出区分两个 DFA 的最短单词

两位同学各自做了一个文本过滤器。一个接受在任何位置包含 ab 的单词，另一个接受以 ab 结尾的单词。他们用 ab 和 aab 测试，结果都通过，于是以为两个过滤器是一致的。米娜（Mina）不再去猜测试单词了。她把两台机器放在一起运行，搜索一个恰好只有一个机器接受的状态对。搜索返回了 aba，这就是对二者分歧的一个具体解释。

```python
from collections import deque
from itertools import product

def witness(a, accepting_a, b, accepting_b):
    alphabet = ("a", "b")
    start = (0, 0)
    parents = {start: None}
    queue = deque([start])
    while queue:
        pair = queue.popleft()
        x, y = pair
        if (x in accepting_a) != (y in accepting_b):
            letters = []
            while parents[pair] is not None:
                previous, letter = parents[pair]
                letters.append(letter)
                pair = previous
            return "".join(reversed(letters))
        for letter in alphabet:
            nxt = (a[x][letter], b[y][letter])
            if nxt not in parents:
                parents[nxt] = (pair, letter)
                queue.append(nxt)
    return None

def accepts(table, word):
    state = 0
    for letter in word:
        state = table[state][letter]
    return state == 2

contains = [{"a": 1, "b": 0}, {"a": 1, "b": 2}, {"a": 2, "b": 2}]
ends = [{"a": 1, "b": 0}, {"a": 1, "b": 2}, {"a": 1, "b": 0}]
word = witness(contains, {2}, ends, {2})
assert word == "aba" and witness(contains, {2}, contains, {2}) is None
for size in range(len(word)):
    for letters in product("ab", repeat=size):
        test = "".join(letters)
        assert accepts(contains, test) == accepts(ends, test)
print("shortest witness:", repr(word))
print("contains ab:", accepts(contains, word))
print("ends in ab:", accepts(ends, word))
```

```sh
python regular-decision-problems-shortest-dfa-counterexample.py
```

**预期输出**

```text
shortest witness: 'aba'
contains ab: True
ends in ab: False
```

**按执行顺序理解**

1. 积状态 (x,y) 记录了两台机器在读完同一个输入前缀之后各自所处的位置。

2. 在一个状态对入队时就把它标记为已访问。这个图最多有 |Q_A|*|Q_B| 个状态对。

3. 当恰好有一个分量接受时，就把这个积状态当作目标。这是对称差，而不是交集。

4. 用父指针来还原单词。BFS 使得最先找到的见证在符号个数上是最短的。

**逐步读懂代码**

两个语言不同，恰好当它们的对称差非空：L(A) != L(B) 当且仅当存在某个 w，使得 accept_A(w) XOR accept_B(w) 成立。对于给定的有限机器，完整的积搜索可以判定这个条件。如果没有任何不一致的状态对是可达的，那么每一个单词都会通向一个一致的状态对。

设两台机器分别有 q_A 和 q_B 个状态，字母表大小为 s，则时间为 O(s*q_A*q_B)，存储的状态用 O(q_A*q_B) 的空间。完整性很重要：每个状态对每个字母表符号都要有转移。缺失的转移应当先送到一个明确的拒绝汇点。

如果两个起始状态就出现了分歧，那么返回空字符串也是一个合法的见证。返回 None 则表示不存在见证。这里的小规模暴力检查验证了：对这个测试样例，没有更短的单词能区分它们；而关于“已访问的积状态”的论证，则解释了为什么一般的搜索会终止。这个方法比较的是 DFA；它并不是一个对任意程序都适用的等价性测试。

### Leon 的进一步思考

**共同的字母表很重要**

补是相对于 Σ* 而言的。改变字母表，就会改变那些没见过的符号该被拒绝还是该被接受，所以要在同一个字母表上把两台机器都补全。

**用广度优先找最短的证据**

当每条边恰好消耗一个符号时，对积图做广度优先搜索，可以找到一个最短的分歧单词。除了父状态，还要存下进入的符号，才能把它还原出来。

**注意这个边界:** 在不完整的 DFA 上不加汇点就交换终态。一个字符串如果因为缺少转移而“卡死”，原机器会拒绝它，所以补机器必须接受它；这需要一个明确的汇点状态。

一次有限的搜索，怎么能确认无穷多个字符串上的一致性？

每一个字符串都会在有限的积图中对应一条路径。如果没有任何可达的状态表示分歧，那么就不可能有字符串成为反例。

## 证明有限记忆不够

### 01 / 从一个故事开始

衣帽间的管理员只有一组固定数量的卡片，用来记住进来了多少位客人。如果管理员之后必须恰好放行同样数量的人离开，那么迟早会有两个不同的到达总数共用同一张卡片。从那一刻起，相同的离开序列会产生相同的行为，尽管其中一个总数应该通过，而另一个应该失败。

这不只是“没能发明出更好的卡片”这样一次失败的尝试：它是针对每一种固定有限卡片系统的论证。关键在于一个没有上限的精确要求。如果客人数量有一个上限，或者只是按某个固定的数取模来计数，那么问题就变了。

### 02 / 理解原理

要证明一个语言是非正则的，就要说明任何有限状态的摘要，都无法保留未来的后缀所需要的全部区别。对于 L={aⁿbⁿ:n≥0}，假设存在一个有 m 个状态的 DFA。在 m+1 个前缀 ε,a,…,aᵐ 之中，必定有两个不同的前缀 aⁱ 和 aʲ 通向同一个状态。接着在两者后面追加同样的后缀 bⁱ，这台机器对这两个字符串的行为就完全一样。

但是 aⁱbⁱ 属于 L，而 aʲbⁱ 不属于 L。这个矛盾证明了语言是非正则的。另一种技巧利用封闭性：如果一个假设是正则的语言，与已知的正则语言组合之后，会产生一个已知的非正则语言，那么这个假设就不成立。这两种论证都不是说该语言不可判定；它们只是排除了有限自动机。

### 03 / 逐项读懂公式

```text
δ*(q₀,aⁱ) = δ*(q₀,aʲ), i < j
⇒ δ*(q₀,aⁱbⁱ) = δ*(q₀,aʲbⁱ)
```

m 是状态的个数，所以被检查的 m+1 个前缀，根据抽屉原理必然迫使某个状态重复出现。i 和 j 是两个不同的前缀长度，bⁱ 是共同的区分后缀。δ* 是 DFA 的扩展转移函数。

这个蕴含之所以成立，是因为一台确定性的机器如果处于同一个状态，就会以相同的方式处理相同的剩余输入。矛盾涉及的是这两个完整字符串的成员资格，而不仅仅是它们长度的不同。

### 04 / 先看一个完整例子

考虑 {a,b} 上的语言 E，它由 a 和 b 的个数相等的字符串组成，顺序任意。假设 E 是正则的。语言 a*b* 是正则的，而正则语言对交运算是封闭的。它们的交恰好包含的是：一段 a，后面跟着一段同样长的 b，也就是 {aⁿbⁿ:n≥0}。

重复状态的论证证明了这个语言是非正则的，这就产生了矛盾。因此 E 也不是正则的。注意，abba 属于 E 但不属于 a*b*；取交集就是有意地去掉了顺序混杂的字符串，从而露出那个已知的困难模式。

### 先认识这些词

- **抽屉原理:** 对象的个数多于类别的个数时，必定有两个对象落入同一个类别。

- **区分后缀:** 追加同一个字符串之后，所要求的成员资格答案却不同。

- **非正则:** 没有任何有限自动机能识别该语言。

### 一步步想清楚

**为什么要用 m+1 个前缀？**

只有 m 个状态，所以必定有两个前缀共用同一个状态。

**为什么恰好追加 bⁱ？**

它能配平较短的那个 a 前缀，但配不平较长的那个。

**非正则就意味着没有算法能判定它吗？**

不是。拥有无界工作记忆的机器，可以对这些有限的输入进行计数和比较。

### 走一遍被迫碰撞的论证

假设识别 {aⁿbⁿ:n≥0} 的某个假想 DFA 在读完 a² 和 a⁵ 之后到达同一个状态。解释为什么这个碰撞与正确性相矛盾。

**先选择方法**

找出一个共同的后缀，使得其中一个前缀需要它，而另一个必须拒绝。

1. 选择后缀 b²，因为它恰好为较短的前缀提供了两个 b。

2. 补全后的 a²b² 两种符号个数相等，必须被接受；a⁵b² 有五个 a 和两个 b，必须被拒绝。

3. 两次运行都是在同一个状态下开始读这个后缀的。确定性迫使之后的状态和最终的判定都相同，这与上面那些要求相矛盾。

**解释最终答案**

在任何一个正确识别该语言的 DFA 中，这两个前缀都不能共用一个状态。需要区分的情形有任意多个，所以排除了有限 DFA 的可能。

**检验推理**

改用后缀 b⁵，会反过来使另一个补全后的字符串变成配平的，同样得出矛盾。

### 有上限的版本是正则的

令 L₃={aⁿbⁿ:0≤n≤3}。给出一个正则表达式，并解释为什么无限语言的那个证明不能原封不动地套用。

**先选择方法**

把有限个允许的 n 值逐个列出，而不是去寻找一个无界计数器的重复。

1. n=0 得到 ε，n=1 得到 ab。

2. n=2 得到 aabb，n=3 得到 aaabbb；没有其他允许的 n 值。

3. 取并 ε|ab|aabb|aaabbb。一个有限的表达式就是对这四个字符串的正则描述。

**解释最终答案**

L₃ 是正则的。先前的证明需要任意多个互相不同、又必须区分的前缀，而在这个固定的上限下就没有了。

**检验推理**

a⁴b⁴ 虽然两种符号个数相等，但仍被拒绝，因为 n=4 超过了规定的上限。

### Leon 的进一步思考

**量词承载着证明**

状态个数 m 是任意的。只说明某一台三状态的机器行不通，比从任意的有限 m 出发推出矛盾要弱。

**加上上限就改变了语言**

把 n 限制在 n≤3，就只剩下 ε、ab、aabb、aaabbb。一个有限的列表总是可以被识别的，尽管那个没有上限的模式无法用有限的记忆来实现。

**注意这个边界:** 声称画不出 DFA 就证明了非正则。证明必须排除每一个可能的有限 DFA，而不仅仅是到目前为止试过的那些设计。

不是。它是有限的，所以可以用一个 DFA，或者用若干个显式表达式的有限并来识别。推动不可能性证明的，是那个没有上限的要求。

## 文法与递归结构

### 01 / 从一个故事开始

一位工匠可以这样做一个嵌套的收纳盒：要么放一个空的隔间，要么在一个较大的盒子里面再放进一个小盒子。这份说明可以引用它自己，所以一份有限的配方就能做出任意深度的嵌套。上下文无关文法的工作方式与此类似：一个有名字的、尚未完成的组件，可以被替换成一个由终结符和更多未完成组件组成的模式。

只有当不再剩下任何未完成的组件时，最终的对象才算完成。这个类比解释了递归，但文法并不规定一个实际的物理执行顺序。不同的替换顺序可以描述同一个结构，并且产生同一个最终的字符串。

### 02 / 理解原理

上下文无关文法（CFG）由非终结变量、终结符、产生式规则和一个起始变量组成。每条规则把一个非终结符替换成一个有限的序列，这个序列也可以是 ε。“上下文无关”的意思是：无论相邻的符号是什么，这条规则都可以使用。推导从起始变量开始；只有全部由终结符组成的结果才属于这个语言。

文法能够表达超出有限状态记忆能力的嵌套结构。正确性有两个方向：每个被生成的字符串都必须满足预期的性质，并且每个预期的字符串都必须能被生成。

上下文无关语言对并、连接和星是封闭的：先把各个组成部分的变量改名以避免冲突，然后再添加一条新的起始规则，用来选择、连接或重复它们的起始变量。与正则语言不同，它们对任意的交和补并不封闭。每一个正则语言都是上下文无关的，但反过来则不成立。

### 03 / 逐项读懂公式

```text
G = (V, Σ, P, S)
L(G) = {w ∈ Σ* : S ⇒* w}
```

V 是非终结符的集合，Σ 是与之不相交的终结符字母表，P 是产生式的集合，S 是起始非终结符。一个 ⇒ 表示一步重写；⇒* 表示零步或多步这样的重写。

一个推导可以经过含有非终结符的混合字符串，但这些中间形式并不是语言的成员。条件 w∈Σ* 保证最终的结果只含终结符，也包括可能出现的空串 ε。

### 04 / 先看一个完整例子

用文法 S→[S]S | ε 来生成平衡的方括号。要生成 [][]，先选择 S⇒[S]S，把里面的 S 替换成 ε 得到 []S，再把剩下的 S 展开成 [S]S，最后把剩下的两个变量都替换成 ε。要生成 [[]]，则改为展开第一个里面的 S。

为什么这个文法能涵盖每一个平衡的括号串？任何一个非空的平衡串，都有一个起首的 [，它所匹配的 ] 把串分成两部分：一个内部的平衡串，和后面跟着的一个平衡后缀。这两个更小的部分恰好对应两个 S 的位置。这种分解支持对字符串长度作归纳的证明。

### 先认识这些词

- **非终结符:** 仍然需要被重写的有名字的组件。

- **终结符:** 允许出现在最终字符串中的符号。

- **推导:** 从起始变量开始的一系列规则应用。

### 一步步想清楚

**为什么有限的文法能生成无穷多个字符串？**

一条递归的规则可以被应用任意有限多次。

**aSb 已经是语言的成员了吗？**

只要 S 还是非终结符，它就不是；剩下的工作必须完成。

**生成几个例子，就能证明完备性吗？**

不能。必须解释每一个预期的字符串是如何被生成的。

### 生成一个镜像的单词

字母表 {a,b} 上的文法 S→aSa|bSb|ε。给出 abba 的完整推导，并描述每个被生成的单词所具有的一个性质。

**先选择方法**

匹配最外层相同的符号，对中间部分递归，最后用 ε 结束。

1. abba 最外层的符号是 a，所以应用 S⇒aSa。

2. 它里面的目标是 bb，所以用 bSb 替换那个 S：aSa⇒abSba。

3. 把剩下的 S 替换成 ε，得到 abba，不再有变量。每一次包裹，都会在两端各加上一个相同的符号。

**解释最终答案**

S⇒aSa⇒abSba⇒abba。每一个被生成的单词都是偶数长度的回文。

**检验推理**

单词 aba 是回文，但长度是奇数，所以这个文法生成不了它。长度这个不变量解释了原因。

### 用新的名字构造连接

G₁ 有规则 A→aA|ε，G₂ 有规则 B→bB|b。构造一个文法，生成“一个 G₁ 的字符串后面接一个 G₂ 的字符串”，然后推导 aab。

**先选择方法**

保持变量 A 和 B 不相交，并用一个新的起始变量把它们连接起来。

1. 添加 S→AB。A 生成零个或多个 a，B 生成一个或多个 b。

2. 推导 S⇒AB⇒aAB⇒aaAB⇒aaB，即先做两步递归的 A，然后用 A→ε。

3. 用 B→b 得到 aab。没有任何规则能把 a 放到 b 的后面，因为这两个组成部分始终保持先后的顺序。

**解释最终答案**

这个文法生成 a*b⁺，也就是任意一段 a 后面接一段非空的 b。它能推导出 aab。

**检验推理**

当 A 立刻消失时，允许得到 b；而 ε 被排除在外，因为 B 不可能消失。

### Leon 的进一步思考

**可靠性与完备性是不同的**

一个只生成 ε 的文法，对于平衡括号而言是可靠的，但不是完备的。它从不生成错误的括号串，却漏掉了每一个非空的正确串。

**合并之前先改名**

两个文法可能都把某个变量叫作 S，却表示不同的东西。在把它们合并之前，要先给变量改名；否则规则之间可能会发生意想不到的相互作用。

**注意这个边界:** 把像 [S] 这样的句型，误当成已经生成的终结符字符串。推导必须把所有的非终结符都处理完。

S→aS | b 生成的是什么语言？

恰好是 {aⁿb:n≥0}。每一步递归会在前面加一个 a；最后一条规则贡献一个 b，并结束推导。

## 解析树与歧义

### 01 / 从一个故事开始

一个书面的表达式，就像一份缺少了分组标记的装配说明。如果一位技术员先把前两块拼起来再加第三块，而另一位技术员先把后两块拼起来，那么他们可能从同一行符号搭出不同的结构。解析树把结构明确地表示了出来。

它的叶子记录了看得见的字符串，而它的内部节点则显示了文法是如何把这个字符串组装起来的。把相互独立的工作按不同的先后顺序去做，并不一定会产生不同的结构。歧义说的是树的不同，所以不能仅仅因为列出了两种任意的规则应用顺序，就断定存在歧义。

### 02 / 理解原理

解析树记录的是一次推导的层级结构。它的根是起始变量，每个内部节点按照某条产生式展开，叶子构成的结果串则按从左到右的顺序读出。如果某个字符串有两棵不同的解析树，那么这个文法就是有歧义的；等价地说，就是该字符串有两条不同的最左推导。

像 E→E+E | E×E | n 这样的算术文法是有歧义的，因为运算符的优先级和结合性都没有被固定下来。一个分层的文法可以强制规定优先级：表达式用加法把项组合起来，项用乘法把因子组合起来，而因子提供原子或者括号。

歧义是属于某一个特定文法的；证明了某一个文法有歧义，并不能证明它的语言就没有无歧义的文法。解析的作用是选定结构，这是在求值或翻译能够可靠进行之前所必需的。

### 03 / 逐项读懂公式

```text
G 有歧义 ⇔ 存在 w ∈ L(G)，使得 w 至少有两棵不同的解析树
```

G 是一个文法，w 是一个终结符字符串。存在量词表示只要有一个见证的字符串就够了。不同的解析树指的是它们的产生式结构不同，而不是书写方式不同，也不是遍历顺序不同。

最左推导总是展开最左边剩下的那个非终结符，这样就去掉了与结果无关的展开顺序的选择。这个陈述是对歧义的定义，而不是一个能对每一个可能的文法都判定其是否有歧义的算法。

### 04 / 先看一个完整例子

对于 E→E+E | E×E | n，字符串 n+n×n 有一棵根运算是加法的树，也有另一棵根运算是乘法的树。让三个 n 叶子的值分别取 2、3 和 4，在第一棵树下得到 2+(3×4)=14，在第二棵树下则得到 (2+3)×4=20。

要强制让乘法优先，可以使用 E→E+T | T、T→T×F | F 和 F→n | (E)。这样，没有括号的乘法是在一个项的内部构造出来的，所以加法必须位于它的上方。括号仍然可以明确地要求另一种解释。

### 先认识这些词

- **解析树:** 一个层级结构，显示是哪些文法规则构造出了这个字符串。

- **优先级:** 决定哪个运算符结合得更紧的规则。

- **结合性:** 同一层级上重复出现的运算符如何分组。

### 一步步想清楚

**为什么两条任意的推导还不够？**

它们可能只是按不同的顺序展开了相互独立的分支，描述的仍是同一棵树。

**同一个表达式怎么会有 17 和 27 两个值？**

对于 5+4×3，5+(4×3)=17，但 (5+4)×3=27。

**加法的优先级规则，也能确定减法的结合性吗？**

不能。重复的减法需要另一条单独的分组规则。

**为什么在同一种切分内部用乘法，而在不同的切分之间用加法？**

在同一种切分内部，每一棵左树都可以与每一棵右树配对。在不同的切分之间，一棵树恰好只有一种根的划分，所以这些集合互不相交。

### 两棵树，不同的结果

使用 E→E+E|E×E|n，其中 n 表示一个数字记号。三个数字记号依次显示的值是 5、4 和 3。给出 5+4×3 的两种解析并求值。

**先选择方法**

保持叶子的顺序不变，选择不同的根运算。

1. 选择根为 +，左叶子是 5，右子树是 4×3。先做乘法：4×3=12。

2. 在根处相加：5+12=17。这棵树表示 5+(4×3)。

3. 改为选择根为 ×，左子树是 5+4=9，右叶子是 3。它的根的值是 9×3=27。

**解释最终答案**

两棵树对应的是同样的无括号文本，但值分别是 17 和 27，这证明了这个文法是有歧义的。

**检验推理**

加上明确的括号，就能区分这两种所要求的结构，并消除这一处歧义。

### 展开顺序并不等于树的歧义

文法 S→AB、A→a、B→b 没有其他的产生式。比较先展开 A 与先展开 B 这两种做法。

**先选择方法**

把两条推导都写出来，然后比较它们的父子结构。

1. 先展开 A，得到 S⇒AB⇒aB⇒ab。

2. 先展开 B，得到 S⇒AB⇒Ab⇒ab。

3. 两棵树的根都是 S，孩子都是 A 和 B，叶子都是 A 下面的 a 和 B 下面的 b。没有任何产生式的选择不同。

**解释最终答案**

这两种顺序描述的是同一棵解析树。它们并不能说明有歧义；这个文法是无歧义的。

**检验推理**

只有第一种顺序自始至终都是最左推导，这就去掉了无关紧要的顺序选择。

### 由较小的情形算出五棵树

对于 E -> E+E | n，不列出所有推导顺序，计算 T(4)。

**先选择方法**

按根处的切分来数树的结构。展开节点的不同顺序可能产生同一棵树，不能重复计数。

1. T(1)=1，T(2)=T(1)T(1)=1。

2. T(3)=T(1)T(2)+T(2)T(1)=2。

3. T(4)=T(1)T(3)+T(2)T(2)+T(3)T(1)=2+1+2。

**解释最终答案**

共有五棵解析树。程序会打印出这五种互不相同的加括号方式。

**检验推理**

对于三个操作数，两棵树是 ((n+n)+n) 和 (n+(n+n))。这核对了第一个不平凡的情形。

<a id="lab-parse-trees-ambiguity-count-expression-trees"></a>

### 数一数解析树，而不是默认只有一棵

一个计算器接受 n+n+n+n。米娜（Mina）通过把前两个操作数合并来画一棵树，但她的朋友却先合并最后两个。两种做法都遵循 E -> E+E | n。这个文本是合法的，但它的结构并不唯一。米娜把根处所有的切分都数了一遍，然后把可能的左树和右树组合起来。她发现一共有五棵树，也明白了为什么解析器需要一条结合性规则。

```python
from functools import lru_cache

def count_trees(operands):
    if operands < 1:
        raise ValueError("at least one operand required")
    ways = [0] * (operands + 1)
    ways[1] = 1
    for size in range(2, operands + 1):
        ways[size] = sum(ways[left] * ways[size - left]
                         for left in range(1, size))
    return ways[operands]

@lru_cache(None)
def trees(operands):
    if operands == 1:
        return ("n",)
    return tuple(f"({left}+{right})"
                 for cut in range(1, operands)
                 for left in trees(cut)
                 for right in trees(operands - cut))

assert [count_trees(n) for n in range(1, 6)] == [1, 1, 2, 5, 14]
assert len(set(trees(4))) == count_trees(4)
print("four operands:", count_trees(4), "parse trees")
for tree in trees(4):
    print(tree)
```

**在本地运行**

```sh
python parse-trees-ambiguity-count-expression-trees.py
```

**预期输出**

```text
four operands: 5 parse trees
(n+(n+(n+n)))
(n+((n+n)+n))
((n+n)+(n+n))
((n+(n+n))+n)
(((n+n)+n)+n)
```

**按执行顺序理解**

1. 只有一个操作数时，只有一棵叶子树。这是基础情形，计数是一，而不是零。

2. 对于根处在左边若干个操作数之后的切分，把左树和右树的数目相乘。每一对左右树构成一棵树。

3. 把不同的根切分的结果求和。它们不可能描述同一棵有序树，因为它们在根处的划分不同。

4. 只枚举四个操作数用于显示。计数和把每一棵树都具体地构造出来，输出的成本差别非常大。

**逐步读懂代码**

设 T(m) 表示由加号隔开的 m 个相同操作数记号的解析树数目。T(1)=1，并且 T(m) 等于 k 从 1 到 m-1 对 T(k)*T(m-k) 求和。k 是左边的叶子数。对于 m=4，三种根的选择分别贡献 1*2、1*1 和 2*1，总共是 5。

这个计数器需要 O(m²) 次算术运算，并存储 O(m) 个整数。较大的计数需要大整数，所以这个运算次数的模型并没有声称，对于任意大的 m，算术运算的成本是常数。枚举每一棵树至少要花费与所打印的字符数相当的成本，并且增长得快得多。

算术结果相等，并不会使文法变成无歧义的。歧义指的是同一个记号字符串对应多棵解析树。文法 E -> E+n | n 为这个简单的语言固定了左结合。这个例子假定表达式已经分好了词，并且只含加号；它没有实现词法分析器，也没有实现其他运算符的优先级，更不是一个通用的文法解析器。

### Leon 的进一步思考

**相同的值可能掩盖歧义**

1+2+3 的两棵树求值结果都是六，但它们仍然是不同的树。数值结果相等，并不能证明文法没有歧义。

**修改文法，而不是猜测结构**

把表达式、项和因子分开，就把优先级变成了语法的一部分。这样求值器可以沿着树来计算，而不必事后添加一条前后不一致的规则。

**注意这个边界:** 把仅仅是按不同顺序展开相互独立的分支的两条推导，称作有歧义。应当比较的是树，或者使用最左推导。

## 不改变语言的 Chomsky 范式

### 01 / 从一个故事开始

一家家具公司希望每一条装配说明都只有两种形状之一：把两个尚未完成的组件连接起来，或者装上一个已经完成的零件。复杂的说明被拆分成更小的、有名字的阶段。可选的组件和别名需要小心处理，这样修订后的说明书才仍然恰好能做出同样的那些产品。

Chomsky 范式为文法规则提供的就是这样一种规整的形状。目的并不是让说明变得更短或更优雅，而是让解析更容易推理。空产品这个特殊的例外会被单独保留下来，因为一棵带有可见叶子的装配树，无法表示一个不含任何零件的产品。

### 02 / 理解原理

在 CNF 中，普通的产生式具有 A→BC 或 A→a 的形式。如果语言包含 ε，则可以额外让一个全新的起始符号产生 ε，并且这个起始符号不得出现在任何产生式的右侧。转换过程要保持语言不变，做法是：为较长规则中的终结符引入辅助变量；把较长的右侧拆分成二元规则；带上所有需要的替代形式来消除可空变量的出现；通过别名之间的可达性来去掉单位产生式。

顺序和记录很重要：一个可空变量可能出现不止一次，如果删除 ε 规则而不添加替代形式，就会丢失一些字符串。对于长度为 n 的非空单词，一棵 CNF 解析树有 n 个产生终结符的节点和 n−1 个二元产生式节点。这种有界的形状使成员资格问题可判定，并且支持动态规划。

### 03 / 逐项读懂公式

```text
A→BC 或 A→a；可选 S₀→ε
含 n 个终结符的非空解析使用 2n−1 次产生式应用
```

A、B 和 C 是非终结符，a 是终结符，S₀ 是受保护的起始符号。那条可选的空产生式是唯一的 ε 例外。n 是所推导出的非空字符串的长度。

它的二叉解析骨架有 n 个叶子和 n−1 个内部分支节点；终结符产生式又增加了 n 次叶子的应用。这个计数假定文法是 CNF，不适用于含有单位链或可空环的任意文法。

### 04 / 先看一个完整例子

从 S→aS | b 开始。引入 A→a，使得这条混合的规则变成 S→AS。因为 S 出现在某条规则的右侧，所以引入一个新的起始符号 S₀，并先加上 S₀→S。去掉这条单位规则时，把 S 的非单位产生式复制过来，得到 S₀→AS | b、S→AS | b 和 A→a。

结果是 CNF，并且仍然对 n≥0 生成 aⁿb。对于 aab，推导是 S₀⇒AS⇒aS⇒aAS⇒aaS⇒aab。一共有五次产生式应用，与 2×3−1 相符。不同的展开顺序给出同样的次数，因为二叉的解析结构固定了所需节点的数目。

### 先认识这些词

- **Chomsky 范式:** 规则被限制为两个变量或一个终结符，另有一个受保护的起始符号例外。

- **可空:** 一个变量能推导出 ε。

- **单位产生式:** 右侧只有一个变量的规则 A→B。

### 一步步想清楚

**为什么要引入终结符的辅助变量？**

二元的 CNF 规则必须含两个变量，而不能是 aB 这样的混合形式。

**生成四个终结符需要多少个 CNF 步骤？**

四条终结符规则加上三条二元规则，一共是 2×4−1=7。

**ε 可以用同样的正长度计数来处理吗？**

不能。它没有终结符的叶子，使用的是那个单独的起始符号例外。

### 转换一条长度为三的规则

文法 S→aBC、B→b、C→c 只有一个单词 abc。把它转换成 CNF，同时不改变这个语言。

**先选择方法**

先把长规则中的终结符隔离出来，再把三个变量拆成两个变量的步骤。

1. 引入 A→a，并把 S→aBC 替换成 S→ABC。所生成的符号不变。

2. 引入 X→BC，并把这条长规则换成 S→AX。现在 S 的每一步都产生两个变量。

3. 保留 B→b 和 C→c。规则 S→AX、X→BC、A→a、B→b、C→c 都是允许的形式。

**解释最终答案**

这个 CNF 文法仍然恰好生成 abc。每次解析使用两条二元产生式和三条终结符产生式。

**检验推理**

当 n=3 时，2n−1=5，与这五次应用相符。没有任何别的规则能生成另一个单词。

### 消除一个重复出现的可空变量

文法 S→AA 和 A→a|ε。使用 CNF 并保持它的语言不变，允许 S 作为受保护的起始符号。S 从不出现在任何右侧。

**先选择方法**

在去掉 ε 规则和单位规则之前，先对两处 A 的出现，枚举各自独立地保留或省略的选择。

1. 两个 A 都保留，得到 S→AA。省略其中一个，得到 S→A；无论省略哪一个，得到的规则都相同。

2. 两个都省略，得到 S→ε。因为 S 是受保护的，所以这条空规则是允许的。

3. 去掉 A→ε，剩下 A→a。把单位规则 S→A 替换成 S→a。最终的规则是 S→AA|a|ε 和 A→a。

**解释最终答案**

两个文法生成的恰好都是 {ε,a,aa}；最终的这个是带有所述起始符号例外的 CNF。

**检验推理**

如果删掉 A→ε，却不添加 S→a 和 S→ε，就会丢掉三个单词中的两个。

### Leon 的进一步思考

**先保留各种选择，再做删除**

如果一个变量可以消失，那么每一处相关的出现都既可以保留，也可以省略。先删掉它的 ε 规则，可能会悄悄地丢掉较短的单词。

**范式是一种工具**

CNF 可能会增加许多辅助变量。它的好处是得到可预测的二叉解析结构，而不一定是更紧凑的文法，或更简短的文字。

**注意这个边界:** 把每条长度至多为二的规则都叫作 CNF。A→B 是单位规则，A→aB 把终结符和非终结符混在一起；两者都需要转换。

## CYK：从短片段构造长解析

### 01 / 从一个故事开始

一位校对员检查一个句子时，先给每一个单独的词贴上标签，然后是每一对词，再然后是更长的片段。一个较长的片段，只有当它能被切成两个已经理解了的、并且符合某条文法规则的部分时，才能得到一个标签。表格把有用的答案存了下来，这样校对员就不用一遍又一遍地重新发现同一个片段。

CYK 对 CNF 文法就是遵循这样的计划。它并不假定某个看上去有希望的切分点就是唯一的切分点；每一个边界都必须考虑到。表格直接回答了成员资格的问题，而且把成功的选择也存下来，还可以还原出一棵真正的解析树。

### 02 / 理解原理

使用左闭右开区间：T[i,j] 是推导出子串 w[i:j] 的非终结符集合，位置从 0 到 n。先用终结符规则来初始化长度为一的区间。然后按长度 2 到 n 依次处理。对于严格位于 i 和 j 之间的每一个切分点 k，以及每一条规则 A→BC，只要 B 属于 T[i,k]，并且 C 属于 T[k,j]，就把 A 加进去。

所有的依赖关系都指向更短的片段，所以这个顺序是有效的。当且仅当起始变量在 T[0,n] 中时，才接受这个非空单词。ε 要利用文法的起始符号例外来单独处理。直接扫描二元产生式时，时间是 O(|P|n³)，表格中成员关系的存储量是 O(|V|n²)。对于固定的文法，这就变成了三次方的时间和二次方的空间。

### 03 / 逐项读懂公式

```text
T[i,i+1] = {A : A→w[i]}
T[i,j] = {A : ∃k, i<k<j, A→BC, B∈T[i,k], C∈T[k,j]}
```

i 是包含在内的起始位置，j 是不包含在内的结束位置，k 是两个非空子串之间的边界。所以 w[i:j] 的长度是 j−i。P 是文法的产生式集合，V 是它的非终结符集合。

T 存储的是集合，而不是单一的获胜变量，因为同一个子串可能扮演多个语法角色。这个递推在 CNF 转换之后适用，并且只适用于非空的片段；空输入的成员资格要单独检查。

### 04 / 先看一个完整例子

使用 S→AB、A→AA | a 和 B→b，解析 w=aab。初始化 T[0,1]={A}，T[1,2]={A}，T[2,3]={B}。对于长度为二的片段，T[0,2] 包含 A，因为 A→AA 把前两个格子合并了起来。T[1,3] 包含 S，因为 S→AB 把最后的 a 和 b 合并了起来。

对于 T[0,3]，在 k=2 处切分：A∈T[0,2] 并且 B∈T[2,3]，所以加入 S，并接受。较短的格子里含有 S 并不足够；接受要求的是 S 出现在对应整个字符串的那个格子里。记录下成功的切分，就能还原出这棵树：S(A(A(a),A(a)),B(b))。

### 先认识这些词

- **片段:** 两个边界之间的连续子串。

- **动态规划:** 存储较短子问题的答案，并在更大的问题中重复使用它们。

- **左闭右开区间:** 包含起始位置，不包含结束位置。

### 一步步想清楚

**为什么每个格子里要存一个集合？**

几个变量可能推导出同一个子串，并且在不同的父规则中都有用。

**在 abc 中，T[1,3] 覆盖的是什么？**

位置 1 和 2，也就是 bc；位置 3 只是结束的边界。

**短格子里有 S，就能证明整个单词被接受吗？**

不能。起始变量必须出现在跨越整个单词的那个格子里。

### 填写一个小的 CYK 表

CNF 文法 S→AC、C→BB、A→a、B→b。使用边界 0,1,2,3 来解析 abb。

**先选择方法**

先初始化各个字母，再逐步扩大片段，使得每个孩子都先于它的父亲可用。

1. 长度为一的格子是 T[0,1]={A}、T[1,2]={B}、T[2,3]={B}。

2. 对于长度为二的片段，ab 没有适用的二元规则，所以 T[0,2]=∅。两个 b 的格子通过 C→BB 合并，所以 T[1,3]={C}。

3. 对于整个片段，在 k=1 处切分：T[0,1] 中的 A 和 T[1,3] 中的 C 满足 S→AC，所以加入 S。

**解释最终答案**

S∈T[0,3]，所以 abb 被接受，树是 S(A(a),C(B(b),B(b)))。

**检验推理**

这个文法没有任何其他的产生式，所以它唯一可能的终结符单词确实就是 abb。

### 字母都合法，却仍被拒绝

使用同一个文法 S→AC、C→BB、A→a、B→b，测试 bab。解释为什么整个片段会失败。

**先选择方法**

检查所有可能的二元切分，而不是只看每个字母是否有终结符规则。

1. b、a、b 对应的对角线格子是 {B}、{A}、{B}。每一个单独的字母都是已知的。

2. ba 和 ab 都不匹配唯一的长度为二的规则 C→BB，所以两个长度为二的格子都是空的。

3. 在 k=1 时，右边的片段是空的；在 k=2 时，左边的片段是空的。两种切分都无法提供一个 A 后面接着一个 C。

**解释最终答案**

T[0,3]=∅，bab 被拒绝。符号合法并不保证结构合法。

**检验推理**

对比被接受的 abb：只有它把一个 a 放在了所要求的两个 b 的区域之前。

### Leon 的进一步思考

**保留所有成功的切分**

判断成员资格，只需要知道某个变量是否存在。若要恢复所有的解析，就要保留每一条成功的规则和切分，而不是只保留一个指针。

**三次方来自循环结构**

区间的个数是二次方量级，而每个区间可以有线性多个切分点。扫描文法还会再多出一个因子；固定文法下的三次方时间，并不意味着成本是常数。

**注意这个边界:** 混淆含端点和不含端点。如果 T[i,j] 表示 w[i:j]，那么它的子格子必须是 T[i,k] 和 T[k,j]，不能缺少或重复任何一个字符。

为什么不能按任意顺序填写各个片段？

一个格子依赖更短的片段。按长度递增的顺序，能保证每一个需要的子问题在被使用之前都已经完成。

## 图灵机与配置

### 01 / 从一个故事开始

想象一位一丝不苟的书记员，面前有一条很长的方格纸带、一支铅笔和一张小小的指令卡。卡片上写着：根据书记员当前所处的模式，以及铅笔下面那一格里的符号，应该做什么。一步操作可以把那个符号换掉，把铅笔移动一格，并且改变模式。

与有限自动机不同，这位书记员可以回头去看之前的格子，并且留下提醒用的记号。纸带提供了可以扩展的记忆，而指令卡始终是有限的。无限长的纸带是对“可用的存储没有上限”的一种理想化，并不是要求在一步之内完成无限多的操作。

### 02 / 理解原理

图灵机把有限的控制部分、一条可读写的纸带和一个可移动的读写头结合在一起。它的带字母表包括输入字母表，再加上空白符号，也可能还有一些标记符号。配置记录的是当前的状态、读写头的位置和纸带的内容；转移函数决定下一个配置。在任何有限的计算之后，纸带上的绝大多数格子仍然是空白的。

一台机器可以停机并接受，也可以停机并拒绝，还可以永远运行下去。当把它用作计算函数的机器时，需要规定输出是如何编码在纸带上的，以及读写头最后应该停在哪里。不同的标准约定，比如单向的纸带还是双向的纸带，或者是否允许原地不动的移动，会改变描述的方式，但不会改变哪些函数是可计算的。不过，时间和模拟所带来的额外开销仍然可能不同。

### 03 / 逐项读懂公式

```text
δ(q,a) = (q′,b,d),  d ∈ {L,R,S}
C₀ ⊢ C₁ ⊢ C₂ ⊢ ⋯
```

q 是当前的控制状态，a 是读写头下面的符号，q′ 是下一个状态，b 是被写入的符号，d 是移动的方向。S 表示停留在同一个格子上。

Cᵢ 是 i 步之后的完整配置，⊢ 表示一次有效的转移。停机状态之后不再有后续的计算工作。一次转移只读当前的那一个格子；并不会一次性检查整条纸带。

### 04 / 先看一个完整例子

设计一台机器，扫描一个二进制字符串，把每个 0 换成 1，并让原有的 1 保持不变。在状态 scan 下，读到 0 或 1 都写入 1，向右移动，并停留在 scan。读到空白时，不改变纸带，进入一个停机状态。

从 010 开始，读写头位于它的第一个符号上，纸带上的非空白部分依次变成 110、110，然后是 111。再有一次转移看到空白并停机。对于空输入，它立即停机。这台机器有限的状态并不存储整个单词；是纸带记录着不断变化的输出。

### 先认识这些词

- **配置:** 当前状态、读写头位置和纸带内容合在一起。

- **带字母表:** 所有可以被写入的符号，包括空白和标记。

- **转移:** 一条读取、写入、移动并改变状态的规则。

### 一步步想清楚

**为什么只有状态还不是一个配置？**

同一个状态可能读到不同的格子或不同的符号，因此下一步也会不同。

**从位置 2 向右移动，会发生什么？**

在写完当前格子之后，下一个读写头的位置是 3。

**没有上限的纸带，意味着每一步要做无限多的工作吗？**

不是。每一步只访问一个格子，并做一次有限的移动。

### 跟踪一台翻转位的机器

在 scan 状态：读到 0→写 1，R，scan；读到 1→写 0，R，scan；读到空白→写空白，S，halt。输入 101 占据位置 0–2，读写头从 0 开始。跟踪到停机为止。

**先选择方法**

每次转移之后，都要同时记录纸带和读写头；控制状态没有变，并不意味着什么都没有发生。

1. 在位置 0 读到 1，写入 0，并移到位置 1。纸带是 001。

2. 在位置 1 读到 0，写入 1，并移到位置 2。纸带是 011。

3. 在位置 2 读到 1，写入 0，并移到空白的位置 3。纸带是 010。第四次转移看到空白，并在那里停机。

**解释最终答案**

输出是 010，经过四次转移之后，读写头在 3。

**检验推理**

把输出的每一位再翻转一次，就得到原来的 101，这独立地检验了这个变换。

### 一个配置，一个合法的下一步

纸带位置 0、1、2 里的内容是 a、b、空白。读写头在 1，状态是 q。规则 δ(q,b)=(r,X,L)。计算下一个配置。

**先选择方法**

先读出所指示的那个格子，然后把写入、移动和控制状态的更新分开处理。

1. 读写头位置 1 里是 b，所以这条规则适用；位置 0 的 a 现在并没有被读取。

2. 把位置 1 替换成 X。纸带变成 a、X、空白，所有其他的格子保持不变。

3. 从 1 向左移到 0，并把 q 改成 r。新的读写头只有在下一次转移时才会读到 a。

**解释最终答案**

下一个配置的状态是 r，读写头在 0，纸带是 aX 后面跟着空白。

**检验推理**

纸带的改变是局部的：向左移动和改变状态，都不会把 a 擦掉。

### Leon 的进一步思考

**要说明输出的约定**

如果一次计算在临时标记之间留下了有用的数字，那么只说“输出在纸带上”是不完整的。要指明哪些格子构成输出，以及标记是否必须擦除。

**要把停机的那次转移也算进去**

一个扫描器通常还需要多一步，才能看到数据之后的第一个空白。只数被改变的格子，可能会少算它的执行步数，即使某些写入并没有改变符号。

**注意这个边界:** 把缺少转移、拒绝和无限循环当作可以互换的东西。要说明所用的约定，并把停机的结果与不终止区分开来。

## 用标记与不变量设计机器

### 01 / 从一个故事开始

一位职员检查成对的包裹：先在左边一组的某个包裹上贴一张贴纸，走到右边一组，在那里贴上一张与之匹配的贴纸，然后走回来重复这个过程。这些贴纸就是记忆，它们在职员来回走动的过程中一直保存着。

如果右边一组过早地用完了，或者到最后还剩下多余的、没有配对的包裹，这批货物就算失败。当比较的任务需要没有上限的记忆，而机器只有有限个模式时，这种做法就很有用。一个好的设计要说明每一趟来回保证了什么，以及为什么对于一批有限的货物，不可能有无穷多趟来回。

### 02 / 理解原理

实现层面的图灵机描述，可以先用若干阶段来描述，而不必立即把每一个转移都列出来。要为每个阶段规定它的不变量、它所期望的纸带标记，以及成功或失败时的出口条件。对于 aⁿbⁿ，首先要确保输入是一个 a 块后面接着一个 b 块。然后反复地：标记最左边未标记的 a，找到并标记一个未标记的 b，再回到左边界。

如果找不到配对的伙伴就拒绝；只有当所有的 a 和 b 都被标记之后才接受。每一次成功的一轮，未标记的 a 的个数都严格减少，这就证明了机器会终止。每一轮可能要扫描 O(n) 个格子，而一共有 O(n) 轮，所以这个简单的单带实现有 O(n²) 的上界，这并不是一个普遍适用的下界。

### 03 / 逐项读懂公式

```text
完成 r 轮之后的不变量：有 r 个 a 和 r 个 b 被标记
每成功一轮，剩余的 a 的个数减少一个
```

r 是已完成的配对轮数。这个不变量针对的是已经通过了 a*b* 形状检查的纸带，所以被标记的符号仍然对应两个有序的块。

剩余的 a 的个数是一个非负整数，用作终止的度量。运行时间界中的 n 是输入的总长度。一个阶段性的描述，在被展开成完整规定的转移表之前，还必须解释边界的检测以及格式不对的输入。

### 04 / 先看一个完整例子

在 aaabbb 上运行这个配对的方法。形状检查之后，第一轮得到 XaaYbb。接下来的几轮分别得到 XXaYYb 和 XXXYYY。最后的一次扫描看不到任何未标记的字母，于是接受。在 aabbb 上，两轮之后得到 XXYYb；剩下的那个 b 导致拒绝。

在 abab 上，形状检查就在配对之前拒绝了，因为在 b 块开始之后又出现了一个 a。这三条轨迹分别测试了个数相等、个数不等和顺序不正确这三种情形。仅仅匹配个数，会不小心接受一些顺序混杂、不在目标语言中的字符串。

### 先认识这些词

- **标记:** 记录某个位置已经被处理过的纸带符号。

- **阶段:** 为了一个清楚陈述的目的而服务的一组步骤。

- **终止度量:** 在重复推进的过程中严格递减的一个非负量。

### 一步步想清楚

**为什么要在配对之前检查顺序？**

仅仅个数相等，也会接受像 abab 这样顺序混杂的字符串。

**完成一轮保证了什么？**

恰好有一个新的 a 和一个新的 b 被标记了。

**二次方的界是一个普遍的下界吗？**

不是。它只是对这种简单的重复扫描设计所给出的界，而不是对每一种模型或算法的界。

### 伙伴不足时拒绝

用 X 标记 a，用 Y 标记 b。在 aaaabb 上运行这个有序块配对的算法。每一轮都标记最左边未标记的 a 和 b。

**先选择方法**

先跟踪完整的成功轮次，然后找出第一个缺少的伙伴。

1. 形状 a*b* 是合法的。第一轮把一个 a 和一个 b 配成一对，得到 XaaaYb。

2. 第二轮得到 XXaaYY。还剩下两个 a，但所有的 b 都已被标记。

3. 第三轮选中一个 a，得到 XXXaYY，但向右扫描时在遇到空白之前找不到未标记的 b。在这个明确的失败处拒绝。

**解释最终答案**

aaaabb 被拒绝，因为四个 a 无法与两个 b 配成对。

**检验推理**

直接计数 4≠2 确认了这个结果；机器并不需要把数字四存在它有限的控制部分里。

### 证明配对循环会停机

输入是一个有限的 a 块后面接一个 b 块，总长度为 n。每一次扫描都在纸带的边界处或者明确的失败处结束。证明这个算法不可能完成无穷多轮配对。

**先选择方法**

把未标记的 a 的个数当作一个递减的非负整数。

1. 一开始，设未标记的 a 的个数为 u，其中 0≤u≤n。

2. 每成功一轮，恰好标记一个原先未标记的 a，所以这个度量从 u 变为 u−1。没有任何规则会把它恢复。

3. 至多经过最初的 u 轮成功之后，这个计数就变成零。缺少 b 时可能更早就拒绝；最后检查是否剩下 b，是一次有限的扫描。

**解释最终答案**

所有被允许的输入都会终止。把至多 n 轮与每轮 O(n) 的工作量结合起来，这个实现有 O(n²) 的上界。

**检验推理**

当 u=0 时，没有配对轮次；最后的一次扫描仍然可以区分 ε 与一个非空的 b 块。

### Leon 的进一步思考

**区分不同类型的失败**

顺序错误时立即拒绝；所选的 a 没有伙伴时拒绝；最后还剩下 b 时也拒绝。每一项检查所堵住的正确性漏洞各不相同。

**递减的计数器还需要各个阶段是有限的**

未标记的 a 变少，只有在每一次扫描自身都能到达边界或者明确失败的前提下，才能证明成功的轮数是有限的。要把这一条扫描会终止的事实也写进去。

**注意这个边界:** 证明了被接受的输入都是正确的，却忘记证明终止，或者没有拒绝未配对的符号。一个判定器需要两个方向的正确性，以及一个停机的论证。

## 规则表、三种描述层次与多带机器

### 01 / 从一个故事开始

Leon 在一家小面包店里培训新助手。同一份工作，他用三种方式讲。对店主，他说：“每个做好的蛋糕都盖一颗星。”对助手，他说：“沿着货架从左往右走。看每个蛋糕上的标签。写着已完成的，就在蛋糕上盖一颗星，然后往前走。货架走到头就停。”对安全检查员，他递上一本规则册，每种情况一行：“在状态‘行走’，看到‘已完成’标签：盖星，向右一步，保持‘行走’状态。”这三种说法讲的是同一份工作，区别只在于细节的多少。

后来面包店又买了第二个货架，助手可以把蛋糕放在一个货架上，把标签放在另一个货架上。助手并没有变得更有本事，只是更方便了。助手用两个货架能做的事，一个有耐心、只用一个货架的助手来回走动也都能做。这就是机器的“等价”：同样的活都能完成，只是用时不一定相同。

### 02 / 理解原理

图灵机是一本有限的规则册加上一条纸带。形式上它是一个七元组 (Q, Σ, Γ, δ, q₀, q_accept, q_reject)：状态集、输入符号、带符号（包含输入符号和空白）、转移函数、起始状态和两个停机状态。每条规则的意思是：处于状态 q，读到符号 a，就写下 b，磁头移动一格或不动，并转到状态 q′。转移规则表为每一对（状态，读到的符号）列一行。状态图为每个状态画一个圆，为每条规则画一条箭头，标签写成 a/b,D，读作：读到 a，写 b，移动 D。表和图包含的信息完全一样。一定要说明没有适用规则时会发生什么。常见的约定是：缺少规则就算拒绝。

描述一台机器可以有三个层次。高层描述是用普通语言写的算法，不提纸带：“把二进制数加一。”实现层描述说明磁头做什么、纸带上写什么，但不给状态起名：“走到最右端，再向左移动，把每个 1 改成 0，直到遇到 0 或空白，然后写 1。”形式层描述给出整个七元组和完整的表。要选择题目要求的层次，并且要能向下展开一层：高层描述中的每一句话，都应该对应一组有名字的状态和规则。

多轨机器只有一个磁头和一条带，但每个格子里叠放着多个符号，每条轨道一个。在字母表 Γ 上有两条轨道时，一个格子里放的是 Γ × Γ 中的一对符号。把每一对重新命名为一个符号，就得到普通的单带机器，所以多轨没有增加能力。多带机器有 k 条带和 k 个磁头。一条规则同时读取 k 个磁头下的符号，同时在 k 个磁头下写入，各个磁头分别移动，并且只改变那个共享的状态。

两台机器，或者两种机器模型，如果识别同样的语言，计算同样的函数，就是等价的。证明等价要在两个方向上都做模拟。单带机器就是 k = 1 的 k 带机器。另一个方向则要把 k 条带并排存在一条带上，用 # 隔开，并在每个磁头所在的符号上做标记。模拟一步需要扫一遍，读出被标记的符号，再扫一遍，写入并移动标记。如果某条带需要新的格子，它右边的内容整体后移一格。能力等价并不意味着速度相同：k 条带上的 t 步，在一条带上可能需要大约 t² 步。

一个小程序可以对应到这些形状。像 x = x + 1 这样的赋值，对应一小段改变格子的状态路径。语句的顺序对应一条链：前一段的结束状态就是后一段的起始状态。循环对应一个带测试的状态环，测试有一条箭头回到环中重来，另一条箭头离开。变量对应一条带、一条轨道，或者带上用 # 隔出来的一块区域。要说清每个磁头从哪里开始、在哪里结束，因为循环开始时磁头位置不对，就会读错格子。

### 03 / 逐项读懂公式

```text
M = (Q, Σ, Γ, δ, q₀, q_accept, q_reject)        δ(q, a) = (q′, b, D),   D ∈ {L, R, S}
k 条带：   δ : Q × Γᵏ → Q × Γᵏ × {L, R, S}ᵏ
k 条轨道： 一个磁头，每个格子存放 Γᵏ 中的一个符号

二进制加一。   Q = {start, carry, halt},   Γ = {0, 1, _}

   状态     读     新状态       写      移动
   start    0      start        0       R
   start    1      start        1       R
   start    _      carry        _       L
   carry    1      carry        0       L
   carry    0      halt         1       S
   carry    _      halt         1       S

   0/0,R 1/1,R              1/0,L
      +---+                  +---+
      |   v                  |   v
 --> (start) --- _/_,L ---> (carry) --- 0/1,S ---> ((halt))
                               |                       ^
                               +-------- _/1,S --------+
```

Q 是有限的状态集。Σ 是输入字母表，Γ ⊇ Σ 是带字母表。空白符 _ 属于 Γ，但不属于 Σ。δ(q, a) = (q′, b, D) 给出下一个状态、写入的符号和移动方向：L 向左，R 向右，S 不动。在 1/0,L 这样的标签里，斜线前面是读到的符号，斜线后面先是写入的符号，再是移动方向。双圆圈（这里画成 (( ))）表示停机状态。像加一机器这样计算函数的机器，可以只用一个停机状态来代替 q_accept 和 q_reject。

k 是带的条数。轨道是格子中的一层。带是一条独立的纸带，有自己的磁头。# 是分隔符，不出现在输入里。后面的代价估计中，t 表示被模拟的步数，L 表示编码后那条带的格子数。

### 04 / 先看一个完整例子

在 1011 上跟踪加一机器，1011 是二进制的十一。磁头从最左边的一位开始。在状态 start 下，它向右走过 1、0、1、1（四步），到达空白。随后在状态 carry 下退回最后一位（第 5 步）。这一位是 1，所以写 0 并向左（第 6 步）。再下一位也是 1：写 0，向左（第 7 步）。再下一位是 0：写 1 并停机（第 8 步）。纸带上是 1100，也就是十二。对 111，进位会越过最左端，空白对应的规则写下一个新的最高位 1，输出是 1000。

下面是这台机器的三种层次。高层：“把二进制数加一。”实现层：“向右扫到第一个空白，再退回最后一位。磁头读到 1 就写 0 并向左。读到 0 或空白时，写 1 并停止。”形式层：公式框里的那张表。

再看一个带循环的程序：x = 101（五），然后“重复 3 次：x = x + 1”。用两条带。第 1 条带用二进制存 x，第 2 条带用一进制存计数器 111。状态 start 检查计数器：磁头看到 1，说明还要再做一遍；看到空白，机器停机。状态 scan、carry、back 在第 1 条带上做加一，并让磁头回到最左端，最后一条规则把计数器的磁头向右移一格，用掉一个 1。start、scan、carry、back、start 这个环就是循环。scan 和 carry 是加一，依次经过各个状态就是顺序执行。每次检查时，第 1 条带上依次是 101、110、111、1000。机器在 29 步后停机，x = 1000，也就是八。

要在一条带上运行同一个程序，把两条带存成 #101#111#，并标记每个磁头下的格子。模拟一步要把这个串扫两三遍。如果编码后的串从不超过 12 格，模拟一步最多花大约 3 × 12 = 36 步，29 个被模拟的步骤最多花大约一千步。答案相同，只是更慢。

### 先认识这些词

- **转移规则表:** 一张规则列表，为每对（状态，读到的符号）列一行，给出新状态、要写的符号和移动方向。

- **状态图:** 一幅图，每个状态一个圆，每条规则一条箭头，标签写成 读/写,移动。

- **多轨带:** 一条带、一个磁头，每个格子为每条轨道存放一个符号。

- **多带机器:** 有几条带的机器，每条带有自己的磁头，由同一个状态控制。

- **等价模型:** 识别同样的语言、计算同样的函数的两种模型，即使其中一个更慢。

### 一步步想清楚

**标签 1/0,L 的三部分各是什么意思？**

读到 1，写下 0，磁头向左移动一格。

**实现层和形式层有什么不同？**

实现层说明磁头做什么、纸带上写什么。形式层要给每个状态命名，列出每条规则，并说明规则缺失时怎么办。

**循环在状态图里是什么样子？**

是一个环：某个状态有箭头回到前面的状态，途中的一个测试还有第二条离开这个环的箭头。

**为什么单带模拟要在各条带之间放 #？**

它标出一条带到哪里结束、下一条带从哪里开始。没有它，模拟器分不清哪些格子属于哪条带。

### 把规则表变成状态图并跟踪运行

3. 机器每遇到一个 1 就在 even 与 odd 之间切换，遇到 0 则不变。一共见到三个 1，所以最后停在 odd。状态 odd 读到空白就拒绝。

4. 高层描述：恰好接受含偶数个 1 的串。

### 把一个小程序对应到两带机器上

程序：total = 0；对输入中的每个 1：total = total + 1；total = total + 1。第 1 条带上是输入 111，第 2 条带开始时为空白。规则 (状态, 带1, 带2) → (状态, 写1, 写2, 移动1, 移动2) 为 (first,1,_)→(second,1,1,S,R)，(second,1,_)→(first,1,1,R,R)，(first,_,_)→(halt,_,_,S,S)。请跟踪运行，并指出其中的加一、顺序执行和循环。

**先选择方法**

跟着状态名走。注意第 2 条带上的磁头只向右移动，所以第 2 条带像一个不断增长的计数器。

1. 第 1 步：状态 first 在第 1 条带上读到 1，在第 2 条带上读到空白。它在第 2 条带上写 1，让那个磁头右移，并转到 second。第 2 条带上是 1。

2. 第 2 步：状态 second 读到 1 和空白。它在第 2 条带上再写一个 1，两个磁头都右移，转到 first。第 2 条带上是 11，输入磁头前进了一格。

3. 第 3 到第 6 步对第二个和第三个 1 重复同样的一对动作。第 4 步后第 2 条带上是 1111，第 6 步后是 111111。

4. 第 7 步：状态 first 在第 1 条带上读到空白，停机。机器共用了 2 × 3 + 1 = 7 步。

5. 加一就是在第 2 条带上“写 1 并右移”，在 first 和 second 中各出现一次。顺序执行就是先 first 后 second。循环就是从 second 回到 first 的那条箭头，由第 1 条带上的测试决定是继续循环还是停机。

**解释最终答案**

输出是 111111，三个输入符号对应六个 1：循环每一遍把总数加 2。

**检验推理**

输入为空时，机器立刻停机，第 2 条带为空，对应循环执行零遍。

### 在一条带和两条带上运行规则表

Mia 把机器的规则当作数据来保存。规则表是一个 Python 字典，从（状态，读到的符号）映射到（新状态，写入的符号，移动方向）。一个小模拟器可以运行任意条带的表。第一张表在一条带上给二进制数加一。第二张表在两条带上运行程序“重复 3 次：x = x + 1”。

```python
def run_tm(rules, tapes, start="start", halt="halt", limit=500):
    """Run a deterministic k-tape machine. Every tape starts with its head on cell 0.

    rules maps (state, symbols read) to (new state, symbols written, moves)."""
    cells = [dict(enumerate(t)) for t in tapes]
    heads = [0] * len(tapes)
    state, steps, history = start, 0, []

    def snapshot():
        shown = []
        for tape, head in zip(cells, heads):
            used = [i for i, c in tape.items() if c != "_"] + [head]
            lo, hi = min(used), max(used)
            shown.append("".join(f"[{tape.get(i, '_')}]" if i == head else tape.get(i, "_")
                                 for i in range(lo, hi + 1)))
        return state, shown

    history.append(snapshot())
    while state != halt:
        read = tuple(t.get(h, "_") for t, h in zip(cells, heads))
        if (state, read) not in rules:
            raise RuntimeError(f"no rule for {state} reading {read}")
        state, write, moves = rules[(state, read)]
        for i, (w, m) in enumerate(zip(write, moves)):
            cells[i][heads[i]] = w
            heads[i] += {"L": -1, "R": 1, "S": 0}[m]
        steps += 1
        history.append(snapshot())
        if steps > limit:
            raise RuntimeError("step limit reached")
    return steps, history


def contents(history):
    return [t.replace("[", "").replace("]", "").strip("_") for t in history[-1][1]]


# One tape: add 1 to a binary number. Rules: (state, (read,)) -> (state, (write,), (move,))
increment = {}
for bit in "01":
    increment[("start", (bit,))] = ("start", (bit,), "R")      # walk to the right end
increment[("start", ("_",))] = ("carry", ("_",), "L")           # step back onto the last bit
increment[("carry", ("1",))] = ("carry", ("0",), "L")           # 1 plus carry: write 0, carry on
increment[("carry", ("0",))] = ("halt", ("1",), "S")            # 0 plus carry: write 1, done
increment[("carry", ("_",))] = ("halt", ("1",), "S")            # ran off the left end: new leading 1

for text in ("1011", "111"):
    steps, history = run_tm(increment, [text])
    print(f"one tape : {text} + 1 = {contents(history)[0]} in {steps} steps")

# Two tapes: tape 1 holds x in binary, tape 2 holds a unary counter.
# Program:  repeat 3 times: x = x + 1
loop = {}
for bit in "01":
    loop[("start", (bit, "1"))] = ("scan", (bit, "1"), "SS")    # counter left? do one more pass
    loop[("start", (bit, "_"))] = ("halt", (bit, "_"), "SS")    # counter empty: finished
    loop[("scan", (bit, "1"))] = ("scan", (bit, "1"), "RS")     # find the end of x
    loop[("back", (bit, "1"))] = ("back", (bit, "1"), "LS")     # return to the start of x
loop[("scan", ("_", "1"))] = ("carry", ("_", "1"), "LS")
loop[("carry", ("1", "1"))] = ("carry", ("0", "1"), "LS")       # the increment, as before
loop[("carry", ("0", "1"))] = ("back", ("1", "1"), "LS")
loop[("carry", ("_", "1"))] = ("back", ("1", "1"), "LS")
loop[("back", ("_", "1"))] = ("start", ("_", "1"), "RR")        # count one pass, loop again

steps, history = run_tm(loop, ["101", "111"])
print(f"two tapes: x = 101, counter 111 -> x = {contents(history)[0]} in {steps} steps")
for state, (tape1, tape2) in history:
    if state == "start":
        print(f"  at the loop test: x = {tape1:<8} counter = {tape2}")
```

**按执行顺序理解**

1. run_tm 为每条带保存一个格子字典和一个磁头位置。不在字典里的格子都是空白。

2. 每一步从每条带读一个符号，查规则，在每个磁头下写入，移动每个磁头，并改变状态。缺少规则就抛出错误，这是本程序对“崩溃”的约定。

3. 加一的表有六条规则：两条用于向右走过各个比特，一条用于在空白处折返，三条用于进位。起始状态是 start，停机状态是 halt。

4. 循环的表增加了第二条带。计数器磁头下的 1 表示还要再做一遍。状态 start 检查它，状态 scan、carry 和 back 完成加一并回到最左端，最后一条规则把计数器磁头向右移一格。

5. snapshot 生成被打印和被跟踪的字符串：每个磁头下的格子用方括号标出。

**跟踪状态的变化**

| 步数 | 状态 | 纸带（磁头在方括号内） |
| --- | --- | --- |
| 0 | start | [1]011 |
| 1 | start | 1[0]11 |
| 2 | start | 10[1]1 |
| 3 | start | 101[1] |
| 4 | start | 1011[_] |
| 5 | carry | 101[1] |
| 6 | carry | 10[1]0 |
| 7 | carry | 1[0]00 |
| 8 | halt | 1[1]00 |

**逐步读懂代码**

输出的前两行显示，加一机器在 1011 和 111 上都用 8 步，尽管后一个输入的进位一直传到最左边。对 1011，向右走用 5 步（四个比特，再加空白），进位用 3 步。对 111，向右走用 4 步，进位用 4 步，因为最后的进位落在空白上，写下一个新的最高位 1。

循环机器每次重新进入状态 start，也就是每次检查计数器时，都会打印 x 的值：101、110、111 和 1000。方括号显示磁头的位置。第三遍之后，计数器磁头落在空白上，于是下一次检查就结束了循环。机器 29 步后停机。

找一找这三种形状。加一是 scan 和 carry 这一对状态。顺序执行是依次经过 scan、carry 和 back。循环是从 back 回到 start 的那条规则。因为计数器有自己的带，它不会干扰那个数。如果只有一条带，就需要在带上隔出一块区域放计数器，而且每一遍都要跑过去一趟。

### Leon 的进一步思考

**选择与论断相配的层次**

要证明一个语言可判定，通常用实现层描述就够了，前提是每个阶段都明确会停机并且正确。高层的“加一”把进位藏起来了。实现层把进位的循环摆出来，终止性论证就在这里：每一步都向左移动，所以循环到 0 或最左端就结束。当具体细节很重要时，比如要数步数或给出一台很小的机器，就用形式层的表。

**用边界输入检验小表**

在空输入、单个比特和全是 1 的输入上跑一遍。加一的表在空输入上，于状态 start 读到空白，转到 carry，再读到空白并写 1，输出是 1。要判断这样是否可以接受。这张表还依赖数字左边有一个空白格。如果纸带在左端是封闭的，向左进位的情形就需要额外的移位阶段，表也要随之改变。

**等价说的是能力，不是速度**

在两条带上，把长度为 n 的串复制到第二条带只需要大约 n 步。在一条带上，机器必须在两份拷贝之间来回奔走，代价按 n² 增长。有一个经典结果：单带机器判定一个串是否为回文，需要 n² 数量级的步数，而两带机器只需要大约 n 步。所以多加几条带虽然不改变任何语言，却会改变运行时间。

**注意这个边界:** 只在一个方向上证明等价，或者把“等价”理解为“一样快”。k 带机器显然至少和单带机器一样强，因为可以取 k = 1。真正的工作在另一个方向，而且即使做到了，k 条带上的 t 步在一条带上也可能要花大约 t² 步。

## 模拟、通用性与 Church–Turing 论题

### 01 / 从一个故事开始

一台通用的音乐播放器可以演奏许多不同的曲子，因为它读取的是作为数据提供给它的乐谱。它的硬件不需要为每一首旋律重新制造一遍。通用图灵机也是类似的：它读取一份经过编码的机器描述，连同那台机器的输入，然后一步一步地解释这份描述。

这个类比也暴露出一个局限：能够照着乐谱演奏，并不意味着事先就能知道，一份古怪的乐谱会不会要求播放器永远重复下去。通用性是模拟任意被编码的程序的能力，而不是不去执行就能预测每一个程序最终行为的能力。

### 02 / 理解原理

通用图灵机 U 根据有限的编码 ⟨M,w⟩，模拟机器 M 在输入 w 上的运行。它保留了被模拟机器的结果，也就是接受、拒绝或者不终止这三种结果中的哪一种，U 就给出哪一种。机器描述之所以能成为数据，是因为有限的字母表、状态和转移表，都允许用有限的字符串来编码。两个形式化的计算模型之间的等价，要通过两个方向上的模拟来建立；只有一个方向的模拟，只能证明能力的包含关系。

Church–Turing 论题把有效的算法计算，与图灵可计算性等同起来。它是关于“算法”这一非形式概念的论题，并不是仅仅通过定义图灵机就能证明的定理。具体的模拟定理，包括通用性，以及标准纸带变体之间的等价，则是用数学证明出来的结果。计算上的等价，本身并不意味着速度相同、内存成本相同，或者实际用起来同样方便。

### 03 / 逐项读懂公式

```text
U(⟨M,w⟩) 模拟 M(w)
M(w) 接受／拒绝／发散 ⇒ U(⟨M,w⟩) 有相同的结果
```

⟨M,w⟩ 是对一份有限的机器描述和一个有限的输入字符串的可计算编码，它带有足够的结构，能把这两部分分开。U 是一台固定的机器，而 M 则遍历所有被编码的机器。“发散”表示这次计算永远不会停机。

上面所示的关系说的是行为是否一致，而不是模拟一共用了多少步。一个有效的编码还需要规定如何处理格式不对的描述，通常的做法是立即拒绝。

### 04 / 先看一个完整例子

假设 M 是这样一台机器：在一元的输入后面再多写一个 1，然后停机。把 M 的编码连同 111 一起交给 U。U 存储一个被模拟的状态和读写头位置，查找适用的、被编码的规则，更新被模拟纸带的一个表示，并不断重复，直到 M 的停机状态出现。

被模拟的输出是 1111。现在再给 U 一台不同的机器，它唯一的行为就是永远向右移动。U 也会永远运行下去。这两种情形由同一个解释器来处理：这说明了通用性的威力，同时也说明了为什么通用性并不能提供一个判断程序是否停机的测试。

### 先认识这些词

- **编码:** 表示一台机器或一个输入的有限字符串。

- **通用机器:** 一个能够模拟被编码机器的解释器。

- **模拟开销:** 重现另一个模型的各个步骤所需要的额外工作。

### 一步步想清楚

**为什么一份机器描述可以作为输入数据？**

它有限的规则可以被一一列出，并用有限的符号来编码。

**模拟一个循环，会让它停机吗？**

不会。忠实的模拟会保留不终止这一性质。

**为什么需要两个方向的模拟？**

一个方向只能证明，模拟器的表达能力至少不低于被模拟的模型。

### 模拟一个简单的加一器

机器 M 向右扫过一元的 1，在第一个空白处多写一个 1，然后停机。输入是 11，读写头在它的第一个符号上。描述被模拟的输出和各个步骤。

**先选择方法**

保持被模拟的纸带、读写头和状态；一次只应用一条被编码的规则。

1. 第一个扫描步骤读到位置 0 的 1，保持不变，并移到位置 1。

2. 第二个扫描步骤读到位置 1 的 1，并移到空白的位置 2。

3. 下一条规则在位置 2 写入 1，并进入停机状态。被模拟的纸带现在包含 111。

**解释最终答案**

被模拟的输出是 111，表示一元的三。按照所述的约定，M 使用了三次转移。

**检验推理**

通用的解释器，可能要用多于三次的自身转移，才能实现这三个被模拟的步骤。

### 跟踪明确给出的模拟开销

一个玩具解释器，每模拟一步需要它自己的 6 步，另外还需要 10 步的准备。被模拟的程序在 7 步之后停机。求解释器的总工作量；然后讨论被模拟的程序不停机的情形。

**先选择方法**

把固定的准备工作与每一步重复的成本分开，然后区分有限的成本与被保留下来的发散。

1. 七个被模拟的步骤花费 7×6=42 个解释器步骤。

2. 再加上一次准备：42+10=52。这是题目给出的成本模型，而不是一个普遍适用的界。

3. 如果被模拟的程序要执行无穷多步，那么重现每一步也需要无穷多个解释器步骤。

**解释最终答案**

停机的那个例子花费 52 步。对不停机的那个例子做忠实的模拟，同样永远不会停机。

**检验推理**

当被模拟的步数为零时，只剩下准备工作，是 10 步，与公式 10+6t 一致。

### Leon 的进一步思考

**行为与资源是两回事**

两个模型可以计算相同的函数，却花费差别很大的步数。在讨论一个模拟时，要同时说明被保留的结果，以及资源上的关系。

**格式不对的编码同样是普通的输入**

一个通用的解释器必须能识别机器描述在哪里结束，并按照事先规定好的约定去拒绝无效的格式。否则，它对形式输入的行为就是不完整的。

**注意这个边界:** 说 Church–Turing 论题证明了所有可以想象的物理设备都与图灵机等价，或者说模拟保证了同样的效率。

## 识别器与判定器

### 01 / 从一个故事开始

失物招领处在有人找到一张匹配的标签时，就能确认你的包已经到了。如果包还没有到，职员可能会一直无休止地找下去。另一个办公室则承诺：会把一份完整而有限的登记册查完，然后回答“是”或者“否”。

第一种行为类似于识别，第二种行为类似于判定。在第一个办公室里等得再久，也不能把沉默变成一个可靠的“否”。两者的差别，是对所有输入的一种保证，而不是职员在迄今为止所观察到的那些请求上，看上去是否友好或者是否快速。

### 02 / 理解原理

一个语言的识别器，必须接受每一个成员，并且绝不接受任何非成员。对于非成员，它可以拒绝，也可以永远运行下去。判定器还要求在每一个输入上都停机，所以每一个成员资格的问题，都能得到一个正确的“是”或“否”。

每一个可判定的语言都是可识别的，但不是每一个可识别的语言都是可判定的。对于被编码的机器的接受问题，通用模拟可以识别出答案为“是”的实例：如果被模拟的机器接受，这个事件迟早会被观察到。如果它拒绝，识别器可以拒绝；如果它循环，识别器可能也会循环。

有限次的测试，不能证明一个程序是判定器，因为一个没有测试过的输入可能会发散。证明既需要论证所有被允许的计算都会终止，也需要论证它们的答案是正确的。

### 03 / 逐项读懂公式

```text
L(M) = {w : M 接受 w}
判定器：对每个 w ∈ Σ*，M 都停机
可判定语言 ⊊ 可识别语言
```

L(M) 只记录被接受的字符串；被拒绝的计算和发散的计算，都不属于这个语言。Σ* 是在所选的编码下，所有有限输入字符串组成的全集。

严格包含的符号表示：每一个可判定的语言都是可识别的，并且至少有一个可识别的语言是不可判定的。这种分类描述的是：是否存在某台合适的机器；而不是某一个设计得很差的具体实现，是否碰巧会终止。

### 04 / 先看一个完整例子

考虑这样一个程序：它依次检查候选的 0、1、2、…，如果找到一个满足输入谓词 P(x) 的整数 x，就接受。假设每一次单独的谓词检查都会停机。如果存在一个见证，这个程序迟早会到达它并接受。如果不存在，这个搜索就会永远继续下去。

因此它识别了“存在见证”这一性质，但并不会自动地判定它。当 P(x) 表示 x²=49 时，它在 x=7 处接受。当 P(x) 表示非负整数上的 x²=50 时，它会一直搜下去，尽管对于这一类特殊的谓词，人们可以设计出一个更好的、有界的过程。一个循环的实现，并不能证明一个语言是不可判定的。

### 先认识这些词

- **识别器:** 接受每一个成员，并且从不接受非成员；它可以在非成员上循环。

- **判定器:** 对每一个输入都给出正确的成员资格答案，并且停机。

- **见证:** 能够确立“是”这个答案的一个有限对象。

### 一步步想清楚

**识别器的沉默可能意味着什么？**

它可能只是还没有找到将来才会出现的见证，也可能会永远搜下去；仅凭沉默，无法区分这两种情形。

**为什么每一个判定器也都是识别器？**

它正确的接受行为满足了识别的要求，而且还额外保证了在答案为“否”的实例上也会停止。

**一个可判定的语言，可以有一个很差的识别器吗？**

可以。可判定性说的是，是否存在某一个判定器，而不是每一个实现的质量如何。

### 在一个简单的“否”的情形上循环的识别器

对于输入 n≥0，依次测试 x=0,1,2,…，当 x²=n 时接受。每一次平方的检验都会停机。比较输入 16 和 18。

**先选择方法**

把见证是否存在，与没有见证时是否终止区分开来。

1. 对于 n=16，测试过的平方数是 0、1、4、9、16，所以 x=4 提供了见证，程序接受。

2. 对于 n=18，4²=16，5²=25。之后的非负平方数只会越来越大，所以没有任何 x 满足这个等式。

3. 所规定的这个程序，没有在越过 n 之后停下来的规则。尽管存在数学上可以拒绝的论证，它在 18 上仍然会永远试下去。

**解释最终答案**

这个程序识别完全平方数，但并不判定它们。它接受 16，而在 18 上发散。

**检验推理**

另一个不同的程序，可以在 x²>n 时立刻拒绝。所以这个循环的例子并不能证明平方数语言是不可判定的。

### 把这个特殊的搜索变成判定器

修改平方数搜索：对于整数 n≥0，测试 x 从 0 到 n（含两端）；当 x²=n 成立时接受，否则在循环结束之后拒绝。证明它的正确性和终止性。

**先选择方法**

证明这个有限的范围包含了每一个可能的非负平方根。

1. 对于 n=0，只需要 x=0，并且它成功了。对于 n≥1，任何 x>n 都有 x²≥x>n，所以不可能是解。

2. 循环检查 n+1 个候选，并且每一次检验都会停机，所以整个执行是有限的。

3. 出现相等就给出了一个真正的平方数见证。如果在这个足够的范围内一个也没有出现，就不存在非负整数解，所以拒绝是正确的。

**解释最终答案**

这个有界的过程判定了完全平方数的成员资格。一个更紧的界可以提高速度，而不会改变答案。

**检验推理**

对于 n=1，x=1 被包含在内。如果省略上端点，就会错误地拒绝这个边界情形。

### Leon 的进一步思考

**证明需要对所有输入都终止**

展示十条轨迹会停止，只证明了这十种情形。要有一个涵盖所有被允许输入的界，或者一个递减的度量，才补上了所缺少的一般性论证。

**一些限制可能使搜索变成有限的**

如果能证明某个可计算的有限的界已经足够，那么一个没有上界的见证搜索就可以变成判定器。这个界必须来自问题本身，而不是一个随意设定的超时。

**注意这个边界:** 由超时推断出不是成员，或者仅仅因为尝试的某一个算法会循环，就推断出不可判定。

可以。在语言之外，这两种行为都是允许的。在那里唯一被禁止的行为是接受。

## 为什么通用停机测试不可能

### 01 / 从一个故事开始

想象有一份目录，声称能对每一个可能的“目录检查程序”进行分类，其中也包括那些会读取自己在目录中的条目的程序。一个爱捣乱的程序，可以查看目录里关于它自己的预测，然后故意做出相反的事情。如果目录总是正确的，并且总是给出回答，这种自我引用就会产生矛盾。

这个论证并不依赖于机器太慢，或者内存不够。它针对的是一个完整的过程是否可能存在。现实中的分析工具仍然是有用的，因为它们可以限制所考虑的程序，可以允许不确定，或者满足于那些并不回答关于每一个程序的每一个问题的保证。

### 02 / 理解原理

假设有一个全停机的算法 H，它能判定任意一台被编码的机器在任意输入上是否停机。构造一台机器 D：对于输入的机器描述 x，D 去询问 H：x 在输入 x 上是否停机。如果 H 回答“是”，D 就永远循环；如果 H 回答“否”，D 就停机。然后在 D 自己的描述上求 D 的行为。

H 无论给出哪一个答案，都与 D 所定义的行为相矛盾，所以不存在这样一个全停机且正确的 H。然而，停机语言仍然是可识别的：通过模拟，直到出现任何一种停机的结果。接受问题同样是可识别的，但是不可判定。

一个相关的对角语言，由那些“其机器不接受自己的描述”的机器描述所组成，它是不可识别的：任何被提出的识别器，在它自己的描述上都会与这个语言不一致。在形式化的证明中，编码和格式不对的输入必须得到一致的处理。

### 03 / 逐项读懂公式

```text
HALT = {⟨M,w⟩ : M 在 w 上停机}
D(x)：如果 H(x,x)=是 则循环；否则停机
```

H 是一个假设的判定器，所以假定它的答案会对每一个格式正确的对都给出。x 编码了一台机器，同时它也是这台机器的一个合法的输入字符串。

D 是一个把 H 当作子程序来使用的有限程序。代入 x=⟨D⟩ 就迫使矛盾出现。HALT 既包括接受而停机，也包括拒绝而停机；它与只由接受的计算所组成的语言是不同的。

### 04 / 先看一个完整例子

假设那个假想的 H 预测 D 在 ⟨D⟩ 上会停机。按照 D 的规则，D 看到“是”，就故意循环，使得这个预测是错的。反过来，假设 H 预测 D 不会停机。D 看到“否”，就立刻停机，这又使得这个预测是错的。这两种情形穷尽了一个判定器的布尔答案。

再加上第三种“未知”的结果，可以避免这个矛盾，但这样就没有判定原来的那个问题了。把注意力限制在有固定步数上限的程序上，也可以避免这个矛盾，因为这样的程序只需要模拟到上限就行；但那是另一类不同的输入。

### 先认识这些词

- **不可判定:** 没有任何算法能对每一个允许的输入都停机，并给出正确的答案。

- **对角化:** 利用所构造对象自身的描述，迫使它与某个东西产生分歧。

- **全停机算法:** 保证在其定义域内的每一个输入上都会停机的算法。

### 一步步想清楚

**关于 H 假设了什么？**

它对每一个格式正确的机器与输入对都给出正确的回答，并且总是停机。

**在预测为“是”之后，D 会做什么？**

它故意循环，这与“它会停机”的预测相矛盾。

**“未知”能避开这个矛盾吗？**

可以，但那样 H 就不是对每一个输入都适用的判定器了。

### 补全自我引用的各种情形

假设 H 是一个全停机且正确的停机判定器。定义 D(x)：如果 H(x,x)=是，就循环；如果 H(x,x)=否，就停机。求 H 在 (⟨D⟩,⟨D⟩) 上的结果。

**先选择方法**

穷尽两个可能的布尔答案，而不是去猜实际发生的是哪一个。

1. 如果 H 返回“是”，它就预测 D 在它自己的描述上会停机。但是 D 的“是”分支会永远循环。

2. 如果 H 返回“否”，它就预测 D 在那里不会停机。但是 D 的“否”分支会立刻停机。

3. 因为 H 是全停机的，它必须返回这两个答案之一。两者都与正确性相矛盾，所以最初的假设不成立。

**解释最终答案**

对于任意被编码的程序与输入，不存在全停机且正确的停机判定器 H。

**检验推理**

如果 H 可以不返回，第三步就不成立了。这个证明针对的是完整的判定器，而不是部分的工具。

### 一个有界的问题是可判定的

给定一份有限的机器描述 M、输入 w 和一个非负整数 B，判定 M 是否至多在 B 次转移之内停机。解释一个正确的过程，并包括 B=0 的情形。

**先选择方法**

给定的有限的界允许我们一直完整地模拟到这个界为止；只回答这个有界的问题。

1. 检查初始配置。如果它已经是一个指定的停机配置，那么即使 B=0 也回答“是”。

2. 否则，最多执行 B 次合法的转移，每一次之后都检查是否到达了停机状态。如果到达了，就回答“是”。

3. 如果这些被检查过的配置都没有停机，就对“在 B 之内”这个问题回答“否”。计数器限制了模拟，所以这个过程本身会终止。

**解释最终答案**

有界的停机问题是可判定的。回答“否”表示在这个界之内没有停机，而不是永远不会停机。

**检验推理**

一台在第 B+1 步停机的机器，会被这个有界的问题正确地拒绝，但它却属于不受限制的 HALT。

### Leon 的进一步思考

**不要把停机和接受混为一谈**

一个停机并拒绝的程序，也属于 HALT。因此，HALT 的识别器在模拟看到任何一种停机之后都要接受，而不是只在模拟看到接受之后才接受。

**有用的工具仍然是可能的**

对于一种受限的、带有递减整数计数器的循环语言，检查器可以证明它会终止。这与定理并不冲突，因为定理的范围包括任意的程序。

**注意这个边界:** 断定没有任何程序能够证明另一个程序会终止。这个定理排除的，是一个针对所有程序和输入、完整且总是正确的判定器。

D 必须先收到 H 的答案，才能选择与之相反的行为。如果 H 可以循环，或者可以回答“未知”，这个矛盾就不再能说明不存在一个完整的判定过程。

## 交错模拟与补语言

### 01 / 从一个故事开始

两位调查员针对同一个论断，各自寻找相反的证明材料。一位寻找这个论断为真的证据，另一位寻找它为假的证据。如果让第一位调查员一直独占房间，直到他完成，那么第二位可能永远也轮不到。正确的做法是给他们交替的时间段。

当其中有一位一定会最终找到相应的证明材料时，交替地投入精力就保证能得出结论。这种调度的思想叫作交错模拟（dovetailing），也就是让几个搜索轮流前进。它并不会神奇地凭空变出一个不可能的证明材料：它的力量来自于这样一个事实：每一种情况都恰好属于两个可搜索的方面之一。

### 02 / 理解原理

可判定语言对补、并、交都是封闭的，因为它们的判定器在每个输入上总会结束，所以可以放心地组合。把接受和拒绝交换一下，就得到了一个判定器的补。可识别语言对并和交是封闭的，但不保证对补封闭。对于并，要公平地模拟两个识别器，任何一个接受时就接受；如果按顺序先等第一个，那么即使第二个会接受，也可能卡住。

对于交，在两个都接受之后才接受，使用公平模拟可以作为一种统一的构造。一个语言是可判定的，当且仅当它本身和它的补都是可识别的。要证明反方向，就把这两个识别器交错地运行；其中必有一个最终会接受，从而确定了答案。这个定理解释了，为什么一个可识别但不可判定的语言，它的补不可能也是可识别的：否则就能用上面的方法把它判定出来。

### 03 / 逐项读懂公式

```text
L 是可判定的 ⇔ L 与 Σ*∖L 都是可识别的
并的识别器：当 R₁ 或 R₂ 接受时就接受
交的识别器：在两者都接受之后才接受
```

Σ* 固定了输入字符串的整个全集，所以补包含了所有不在 L 中的字符串。R₁ 和 R₂ 是识别器，每一个都有它自己被模拟的配置。

公平模拟给每一个尚未结束的过程无穷多步的机会，例如各自轮流走一步。一个过程停机之后，它的接受标志可以被记住。在非成员上，组合起来的识别器仍然可能永远运行下去，因为识别只要求不接受非成员，并不要求停机，所以这与识别的要求是一致的。

### 04 / 先看一个完整例子

设 Ryes 识别语言 L，Rno 识别它的补。在某个输入 z 上，假设 Ryes 会永远循环，而 Rno 在 37 步之后接受。先等 Ryes 的顺序策略永远给不出答案。交替地让两个模拟器各走一步，至多经过 74 个模拟步，就会到达 Rno 的接受事件，所以这个组合的过程会拒绝 z。

如果 z 属于 L，那么 Ryes 就是那个保证最终会接受的过程。无论哪种情形，组合的过程都会停机。这个保证需要两个语言互为补，也就是每个输入都恰好落在其中一边；两个互不相关的搜索，可能在同一个输入上都永远运行下去。

### 先认识这些词

- **交错模拟:** 在各个模拟之间公平地分配步数，使得没有哪一个会永远等待另一个。

- **补语言:** 所有不属于该语言的允许输入字符串。

- **接受标志:** 记住的一个事实：某个模拟已经接受了。

### 一步步想清楚

**为什么不先把一个识别器运行到结束？**

它在这个输入上可能永远不结束，这样另一个识别器就没有机会去找到见证。

**交的识别器必须记住什么？**

每个组成部分是否已经接受；只有当两个标志都为真时才接受。

**为什么互补的识别器能给出一个判定器？**

每个输入恰好属于一边，而那一边的识别器保证最终会接受。

### 数一数公平模拟的步数

Ryes 识别 L，Rno 识别它的补。在输入 w 上，Ryes 循环，而 Rno 在它自己的第五步接受。先走 Ryes 再走 Rno，各走一步地交替。求组合起来的判定器什么时候给出答案。

**先选择方法**

给全局的模拟步编号，并跟踪每一步由哪台机器得到。

1. 全局的第 1、3、5、7、9 步给了 Ryes；它们并没有结束它的搜索。

2. 全局的第 2、4、6、8、10 步是 Rno 的第一步到第五步。在全局第 10 步，它接受。

3. 补语言的识别器接受，证明了 w∉L，所以组合起来的机器立刻拒绝。

**解释最终答案**

判定器在 10 个组成部分的模拟步之后拒绝，不计调度器的额外记录工作。

**检验推理**

如果按顺序先等 Ryes，尽管只需要五步的证明材料，也永远不会走到 Rno 的任何一步。

### 为什么补不可能也是可识别的

假设 L 是可识别的并且是不可判定的。用反证法，假设它的补有一个识别器 C。在不假设任何一个识别器对所有输入都停机的情况下，推出矛盾。

**先选择方法**

借助公平调度和成员资格的互斥性，把两个部分成功的过程组合起来。

1. 在同一个输入上，交替地运行给定的 L 的识别器 R 和它的补的识别器 C。

2. 如果输入属于 L，R 最终会接受；否则 C 最终会接受。两者都不可能在错误的一边接受。

3. R 接受时就接受，C 接受时就拒绝。这样每一个输入都得到了一个正确的、会终止的答案。

**解释最终答案**

这就构造出了 L 的一个判定器，与前提相矛盾。因此它的补是不可识别的。

**检验推理**

对于一个可判定的语言，不存在矛盾：它和它的补都有判定器，因此都有识别器。

### Leon 的进一步思考

**公平是一项算法上的承诺**

对每个仍在运行的过程，轮流各走一步就足够了。仅仅说“两个都试一试”是不完整的，因为某个实现可能不再给其中一个过程后续的机会。

**拒绝并不是补语言的识别的证明材料**

一个识别器可能拒绝某些外部的输入，却在其他的输入上循环。仅仅重用它的那些拒绝，无法覆盖补语言的每一个成员。

**注意这个边界:** 通过交换停机的标签，来求一个识别器的补。它的无限计算仍然是无限的，所以先前没有被接受的输入，并不会全部变成被接受的。

## 证明新语言不可判定或不可识别

### 01 / 从一个故事开始

Noah 宣布他做出了一个检查器。他说，只要把任意一台机器的说明书交给它，它就能立刻告诉你这台机器是否至少接受一个输入。Iris 并不相信。她没有拿成千上万份说明书去试这个检查器，而是换了一个问题：如果这个检查器真的有效，我还能用它做什么？

Iris 已经知道一件谁也做不到的事：给定机器 M 和输入 w，判断 M 是否接受 w。她想到一个办法。根据 M 和 w，她写出一份新的说明书 M_w。新机器对除 w 以外的所有输入都不理会，遇到 w 时就照着 M 的步骤去做。这样，M_w 恰好在 M 接受 w 时才会接受某个输入。Iris 把 M_w 交给 Noah 的检查器，读出答案。如果检查器有效，Iris 就解决了那件谁也做不到的事。所以它不可能有效。

请注意，Iris 只是写出了新说明书，并没有照着去执行。写说明书只要几分钟，照着执行却可能永远没有结果。

### 02 / 理解原理

要证明一个新语言 L 不可判定，先选一个已知不可判定的语言 A，通常是 A_TM，也就是所有满足“机器 M 接受输入 w”的二元组 ⟨M,w⟩。然后用反证法，假设 L 有判定器 R。把 R 当作子程序，造一台判定 A 的机器 S。这样的 S 不可能存在，所以 R 也不可能存在。

一个完整的证明有五个部分：假设、S 的构造、答案为“是”时 S 正确的证明、答案为“否”时 S 正确的证明，以及 S 对每个输入都会停机的证明。最后一部分最容易被忘记。它通常依赖两个事实：构造这一步只是写出一个有限长的串，而 R 是判定器，总会给出答案。

同样的想法还有一种简洁的写法。从 A 到 B 的映射归约是一个可计算的函数 f，它对每个串都有定义，并且 w 属于 A 当且仅当 f(w) 属于 B。记作 A ≤m B。如果 B 可判定，那么 A 也可判定：先算出 f(w)，再请 B 的判定器回答。如果 B 可识别，A 也可识别。反过来读，这些结论正是我们要用的工具：A 不可判定，则 B 不可判定；A 不可识别，则 B 不可识别。方向很重要：已知很难的语言放在左边，新语言放在右边。

封闭性给出第二条往往更短的路。可判定语言对补、并、交、差都封闭，因为判定器总会停机，它们的答案可以组合起来。可识别语言对并和交封闭，但对补不封闭。两类语言之间有一个关键联系：一个语言可判定，当且仅当它和它的补都可识别。因此，要证明 L 不可判定，可以假设它可判定，再用一条封闭规则把它与一个可判定语言组合，重新得到一个已知不可判定的语言。要证明 L 不可识别，则证明它的补可识别但不可判定。

### 03 / 逐项读懂公式

```text
A ≤m B：存在可计算的 f，对每个串都有定义，并且  w ∈ A  ⇔  f(w) ∈ B

A ≤m B 且 B 可判定          ⇒  A 可判定
A ≤m B 且 B 可识别          ⇒  A 可识别
A ≤m B 且 A 不可判定        ⇒  B 不可判定
A ≤m B 且 A 不可识别        ⇒  B 不可识别

L 可判定  ⇔  L 与它的补都可识别

证明“L 不可判定”的模板：
  1. 假设 R 判定 L。
  2. S 在输入 ⟨M,w⟩ 上：写出 ⟨M′⟩；在 ⟨M′⟩ 上运行 R；给出答案（有时要取反）。
  3. 证明  M 接受 w  ⇔  S 接受（两个方向都要证）。
  4. 证明 S 对每个输入都会停机。
  5. 于是 S 判定了 A_TM，矛盾。
```

A_TM = {⟨M,w⟩ : M 接受 w} 和 HALT_TM = {⟨M,w⟩ : M 在 w 上停机} 是两个标准的不可判定语言。A_TM 可识别，因为可以模拟 M 在 w 上的运行，但它的补不可识别。记号 ⟨M⟩ 是描述机器 M 的一个串，这样别的机器就能把它当作输入。L(M) 是 M 接受的全部串。E_TM = {⟨M⟩ : L(M) = ∅} 是那些什么也不接受的机器所组成的语言。按照约定，不是合法编码的串，被看作一台什么也不接受的机器的编码。

M′ 和 M_w 是 S 写出来的机器，它们依赖于 M 和 w。映射归约中的函数 f 起的是第 2 步的作用：它是一个总会结束并输出一份描述的程序。Σ* 是所有串的集合，L 的补是 Σ* ∖ L。

### 04 / 先看一个完整例子

命题：E_TM 不可判定。证明：假设 R 判定 E_TM，来构造 S。输入 ⟨M,w⟩ 时，S 先写出机器 M_w 的代码，M_w 的行为如下：输入 x 时，若 x 不是 w，就拒绝；若 x 是 w，就在 w 上运行 M，M 接受则接受。然后 S 在 ⟨M_w⟩ 上运行 R。R 接受，则 S 拒绝；R 拒绝，则 S 接受。

两个方向都要检查。若 M 接受 w，则 M_w 接受 w 而且只接受 w，于是 L(M_w) = {w} 非空，R 拒绝 ⟨M_w⟩，S 接受。若 M 不接受 w（因为拒绝或者死循环），则 M_w 什么也不接受，L(M_w) = ∅，R 接受，S 拒绝。S 总会停机：写出 ⟨M_w⟩ 只是把 ⟨M⟩ 和 w 抄进一个固定模板，而 R 总会给出答案。所以 S 判定了 A_TM，这是不可能的。因此 R 不存在。

取一台具体的 M：当且仅当串里 1 的个数是偶数时接受。对 w = 1001，串里有两个 1，M 接受，L(M_w) = {1001}，S 回答“是”。对 w = 1011，有三个 1，M 拒绝，L(M_w) = ∅，S 回答“否”。若 M 在 w 上死循环，则 M_w 在 w 上也死循环，L(M_w) 仍然为空，S 仍回答“否”。

再看不可识别的那一半。E_TM 的补，是至少接受一个串的机器的编码所成的语言。这个语言可识别：对串 0、1、00、01、…… 公平地交错运行 M，只要有一次运行接受就接受。如果 E_TM 也可识别，那么 E_TM 就可判定，而这一点刚刚被排除。所以 E_TM 不可识别。

### 先认识这些词

- **归约:** 一种可计算的改写，把关于一个语言的问题变成关于另一个语言的问题。

- **假想的判定器:** 我们只是为了推出矛盾而假设存在的判定器。

- **编码 ⟨M⟩:** 描述机器 M 的一个串，使别的机器可以把它当作输入。

- **封闭性:** 如果对一类语言中的成员施行某种运算，结果总还在这一类里，就说这类语言对该运算封闭。

- **构造件:** 构造过程中包在 M 和 w 外面的那一小段固定的机器行为。

### 一步步想清楚

**我们假设哪个语言有判定器？**

假设新语言 L 有判定器，也就是我们想证明不可判定的那个语言。对已知很难的语言，我们只用它不可判定这一点。

**证明的最后，机器 S 判定的是什么？**

一个已知不可判定的语言，例如 A_TM。矛盾就出在这里。

**为什么要证明“M 接受 w 当且仅当 S 接受”的两个方向？**

只证一个方向的话，S 仍可能在某些输入上出错，比如拒绝了 M 确实接受的二元组。那样 S 就没有判定 A_TM。

**对补封闭怎样帮上忙？**

如果 L 可判定，把答案“是”和“否”互换，就能判定它的补。所以不可判定语言的补也不可判定。

### 证明停机语言不可判定

设 HALT_TM = {⟨M,w⟩ : M 在 w 上停机}。已知 A_TM 不可判定。请写出完整证明：从 HALT_TM 的假想判定器 H 出发，构造 A_TM 的判定器，从而证明 HALT_TM 不可判定。

**先选择方法**

要判定的是已知很难的 A_TM。用 H 排除循环的情形，因为只有在 H 保证 M 停机之后，模拟 M 才是安全的。

1. 假设 H 判定 HALT_TM。定义 S：输入 ⟨M,w⟩ 时，先在 ⟨M,w⟩ 上运行 H。

2. 若 H 拒绝，则 M 在 w 上循环，M 不接受 w，S 拒绝。若 H 接受，则 M 在 w 上停机，所以模拟 M 在 w 上的运行一定会结束。S 进行模拟，并给出相同的答案：M 接受就接受，M 拒绝就拒绝。

3. 正确性：若 M 接受 w，则 H 接受，模拟接受，S 接受。若 M 拒绝 w，则 H 接受，模拟拒绝，S 拒绝。若 M 循环，则 H 拒绝，S 拒绝。每种情形下，S 接受当且仅当 M 接受 w。

4. 终止性：H 总会停机。模拟只在 H 说 M 在 w 上停机之后才开始，所以它也会停机。因此 S 对每个输入都停机，并判定了 A_TM，这是不可能的，所以 H 不存在。例如，M 接受含偶数个 1 的串，w = 1011：H 接受（M 在 4 步后停机），模拟结果为拒绝，S 拒绝。

**解释最终答案**

HALT_TM 不可判定。证明成立，是因为唯一可能循环的那一步，也就是对 M 的模拟，只在 H 证明它会停机之后才开始。

**检验推理**

如果允许 H 在某些输入上循环，最后一步就不成立：S 也可能循环，S 就不是判定器，也就没有矛盾。

### 用封闭性证明一个“填充过”的语言不可判定

设 V 是所有形如 ⟨M,w⟩ 的合法编码的集合，X = A_TM ∪ (Σ* ∖ V)，即 M 接受 w 的二元组，再加上所有不是合法二元组编码的串。只使用 A_TM 不可判定、V 可判定这两条事实，证明 X 不可判定。

**先选择方法**

假设 X 可判定，再与可判定集合 V 取交，还原出 A_TM。

1. V 可判定：机器可以在有限步内检查一个串的格式，然后接受或拒绝。可判定语言对交封闭。

2. 计算 X ∩ V。A_TM 的每个成员都是合法的二元组编码，所以 A_TM ∩ V = A_TM。填充部分 Σ* ∖ V 与 V 没有公共元素，所以 (Σ* ∖ V) ∩ V = ∅。因此 X ∩ V = A_TM。

3. 假设 X 有判定器 D_X。那么下面这台机器总会停机：输入 z 时，先做 V 的格式检查；z 不合法就拒绝；否则在 z 上运行 D_X 并照抄它的答案。这台机器判定了 A_TM。比如 z = “hello”，格式检查不通过，机器拒绝，这是对的，因为“hello”不在 A_TM 里。

4. 这与 A_TM 不可判定矛盾，所以 D_X 不存在。

**解释最终答案**

X 不可判定。给不可判定语言添上容易识别的杂项，并不会让它变得可判定。

**检验推理**

这个论证要求 V 可判定。如果检查格式本身就不可判定，第 1 步就不成立，第 3 步中的机器也可能不停机。

### 用带步数上限的构造件证明语言不可识别

设 ALL_TM = {⟨M⟩ : L(M) = Σ*}。证明 ALL_TM 不可识别。可以使用 A_TM 的补不可识别这一事实。

**先选择方法**

把 A_TM 的补归约到 ALL_TM。构造件必须恰好在 M 不接受 w 时接受所有串，而加上步数上限就能做到这一点。

1. 定义 f。对合法的二元组 ⟨M,w⟩，f 输出机器 N 的代码，N 对输入 x 的行为是：模拟 M 在 w 上最多 |x| 步；若这时 M 已经接受，就拒绝；否则接受。对不合法的串，f 输出一台接受所有串的机器的代码。写出这些代码总会结束，所以 f 可计算，并且对每个串都有定义。

2. 若 M 不接受 w（拒绝或循环），则任何模拟都看不到 M 接受，N 接受每个 x，L(N) = Σ*。所以 f(⟨M,w⟩) 属于 ALL_TM，而 ⟨M,w⟩ 属于 A_TM 的补。

3. 若 M 恰好在 5 步后接受 w，则 N 拒绝所有满足 |x| ≥ 5 的 x，只接受更短的串，所以 L(N) ≠ Σ*。于是 f(⟨M,w⟩) 不属于 ALL_TM，而 ⟨M,w⟩ 不属于 A_TM 的补。不合法的串被映射进 ALL_TM，同时也在补里。所以两边总是一致的。

4. 假设 Q 识别 ALL_TM。那么“先算 f，再运行 Q”就能识别 A_TM 的补，这是不可能的。所以 Q 不存在。

**解释最终答案**

ALL_TM 不可识别。步数上限的作用，是把“M 在某个时刻接受 w”变成“N 没有接受所有串”。

**检验推理**

若 M 在 t 步后接受 w，N 恰好拒绝长度至少为 t 的串。t = 5 时，长度不小于 5 的串都被拒绝，N 漏掉无穷多个串，正符合要求。

### 只构造，不运行：构造件演示

Emma 想把这个证明的结构写成程序看一看。这里的玩具机器是 Python 生成器：每次 yield 算一步，返回 "accept" 或 "reject" 表示停机。函数 build_Mw 就是主例子里的归约，它只写出一台新机器，不运行任何东西。判定器 R 的替身在有限步数内寻找被接受的串。真正的 R 并不存在，所以这个替身只是猜测，表格会显示它在哪里出错。

```python
# A toy machine is a generator function. Each yield is one step.
# Returning "accept" or "reject" halts it. Never returning means looping.

def run(machine, text, budget):
    """Run for at most `budget` steps. Return the answer, or None if unfinished."""
    steps = machine(text)
    for _ in range(budget):
        try:
            next(steps)
        except StopIteration as done:
            return done.value
    return None


def even_ones(text):                 # accepts when the number of 1s is even
    ones = 0
    for ch in text:
        yield
        ones += ch == "1"
    return "accept" if ones % 2 == 0 else "reject"


def spin(text):                      # loops forever
    while True:
        yield


def slow_accept(text):               # accepts, but only after 5000 steps
    for _ in range(5000):
        yield
    return "accept"


def build_Mw(M, w):
    """The reduction. It writes down a new machine and runs nothing."""
    def Mw(x):
        yield
        if x != w:
            return "reject"
        answer = yield from M(w)     # simulate M on w, one step at a time
        return "accept" if answer == "accept" else "reject"
    return Mw


def stand_in_for_R(machine, probes, budget):
    """A budgeted guess at 'is the language empty?'. A real decider cannot exist."""
    return all(run(machine, p, budget) != "accept" for p in probes)


def S(M, w, budget):
    Mw = build_Mw(M, w)                              # step 1: always finishes
    empty = stand_in_for_R(Mw, [w, "", "0"], budget)  # step 2: ask R
    return not empty                                 # step 3: flip the answer


cases = [("even_ones", even_ones, "1001"), ("even_ones", even_ones, "1011"),
         ("spin", spin, "1001"), ("slow_accept", slow_accept, "1001")]
print("machine      w     M accepts w  R says empty  S accepts  S correct")
for name, M, w in cases:
    truth = run(M, w, 20000) == "accept"
    says = S(M, w, 100)
    print(f"{name:<12} {w}  {str(truth):<11}  {str(not says):<12}  {str(says):<9}  {says == truth}")

print("building M_w for a looping M returns at once:", callable(build_Mw(spin, "1001")))
print("running that M_w on w for 100 steps gives:", run(build_Mw(spin, "1001"), "1001", 100))
```

**预期输出**


**按执行顺序理解**

1. run 最多运行玩具机器 budget 步，返回它的答案；若机器还没结束，就返回 None。程序不能无限等待，这个函数模拟的正是这种限制。

2. even_ones、spin 和 slow_accept 在每个输入上行为各不相同：一台带着答案停机，一台永远循环，一台要到 5000 步以后才接受。

3. build_Mw 就是归约。它返回一台新机器：对 w 以外的 x 一律拒绝，遇到 w 时用 yield from 运行 M。调用 build_Mw 时什么也不会运行。

4. S 遵循证明的三个步骤：构造 M_w，问 R 的替身 M_w 是不是什么也不接受，然后给出相反的答案。

5. 最后的循环把 S 和真相作比较。“真相”一列用的是很大的步数上限，这只因为我们事先知道这些玩具机器的行为。对真实的机器，它是算不出来的。

**跟踪状态的变化**

| 情形 | M 在 w 上 | L(M_w) | R 说“空” | S 的答案 |
| --- | --- | --- | --- | --- |
| even_ones, w = 1001 | 接受 | {1001} | False | 接受（正确） |
| even_ones, w = 1011 | 拒绝 | 空 | True | 拒绝（正确） |
| spin, w = 1001 | 循环 | 空 | True | 拒绝（正确） |
| slow_accept, w = 1001 | 5000 步后接受 | {1001} | True（步数上限太小） | 拒绝（错误） |

**逐步读懂代码**

表格展示了 S 的逻辑。若 100 步内没有任何探测串被接受，R 的替身就说“空”，S 返回相反的答案。前三行与 M 和 w 的真实情况一致。对 slow_accept，M 确实接受 w，但要等 5000 步。100 步以内 M_w 还没有接受，替身说“空”，S 就答错了。

把步数上限调大，可以修好这台机器，却会在下一台更慢的机器上出错。这正是定理的缩影：不管等多久，都无法把一台永远不接受的机器和一台很晚才接受的机器区分开。真正的判定器 R 必须对每台机器都答对，而这恰恰是不可能存在的。

最后两行说明构造这一步为什么是安全的。对一台循环的机器构造 M_w，会立刻返回，因为构造只是新建一个函数。真正运行这个 M_w 却永远不会结束，程序在 100 步后把它截停。证明从不运行 M_w，只把描述交给 R。

### Leon 的进一步思考

**先问目标语言在检验什么，再选构造件**

E_TM 检验的是“有没有被接受的串”，所以 M_w 要做成恰好在 M 接受 w 时才接受某个串。如果目标是“机器的语言是正则的”，就要让 M_w 的语言恰好在 M 接受 w 时是正则的：让 M_w 接受所有形如 0ⁿ1ⁿ 的串，对其他串则在 w 上运行 M，M 接受就接受。若 M 接受 w，L(M_w) 是 Σ*，是正则的；否则 L(M_w) 是 {0ⁿ1ⁿ}，不是正则的。套路不变，只换构造件。

**只和代码本身有关的性质很容易判定**

“M 的状态数是否超过五个”这个问题，读一遍 ⟨M⟩ 就能回答，所以它可判定，任何构造件都无法把它和接受行为挂上钩。归约证明只适用于那些取决于机器做什么，而不是取决于机器怎么写的性质。动手证明之前，可以先用它快速检查一下。

**封闭性论证需要一个可判定的搭档**

如果 X 和 D 都可判定，那么 X ∩ D、X ∪ D 和 X ∖ D 都可判定。使用时，要找一个可判定的 D，把未知语言 X 削成一个已知不可判定的语言。常见的搭档是语法：合法的二元组编码 ⟨M,w⟩ 所成的集合是可判定的，因为机器能在有限步内检查格式。第二道例题就用了这一点。

**注意这个边界:** 把归约的方向弄反。如果证明了“用新语言可以解决已知很难的语言”，这才有意义。如果只证明了“用已知很难的语言可以解决新语言”，那只说明新语言不比它更难，并不能说明它是否可判定。

## 命题语法与真值

### 01 / 从一个故事开始

实验室里的一块警报面板，把几个简单的信号组合在一起：门是开着的，风扇正在运转，温度超过了限度。面板的接线说明了这些信号是如何组合的；而它们当前的开关设置，则决定了最终得到的警报值。逻辑把这两个层面区分开来，称为语法和语义。

括号就像接线的连接方式：改变它们，可能就会改变面板所计算的结果。这个模型假定每个信号都有一个确定的真值。它并不会自动地表达测量的不确定性或因果的影响，所以不应该把逻辑上的蕴含，误当成连接两个传感器的物理机制。

### 02 / 理解原理

命题公式是由原子命题，以及否定、合取、析取等联结词构造出来的。一个真值赋值给每一个原子命题指定一个布尔值，而公式的值则根据它的解析树递归地计算出来。除非明确说明是异或，否则析取是包含式的。实质蕴含 P→Q 只有在 P 为真而 Q 为假时才为假；当 P 为假时，这个蕴含是真的。

如果至少有一个赋值使公式为真，这个公式就是可满足的；如果每一个赋值都使它为真，它就是有效的；如果没有任何赋值使它为真，它就是不可满足的。有 k 个原子命题时，完整的真值表有 2ᵏ 行。这给出了一个有限的判定过程，不过，即使对每一个单独的赋值求值很容易，指数多个赋值的代价也可能很高。

### 03 / 逐项读懂公式

```text
P→Q ≡ ¬P∨Q
F 可满足：∃α，α(F)=1
F 有效：∀α，α(F)=1
```

P 和 Q 是公式，F 是正在考察的公式，α 是给原子命题指定真值的一个赋值。α(F) 把这个赋值递归地扩展到整个公式上。

符号 ∃ 和 ∀ 分别表示“存在”和“对每一个”。这里 1 表示真。关于蕴含的这个等价式，定义的是它在真值上的行为；它并不是说 P 导致了 Q，也不是说 Q 与 P 相关。

### 04 / 先看一个完整例子

设 p 表示样本已被冷藏，q 表示它的封口是完好的。考虑 F=p→q。赋值 (p,q)=(假,假)、(假,真) 和 (真,真) 使 F 成立；只有 (真,假) 使它不成立。因此 F 是可满足的，但不是有效的。现在再加上 p 这个要求，得到 p∧(p→q)。

唯一满足它的赋值是 p=真并且 q=真。如果我们再进一步要求 ¬q，就没有任何赋值留下来了，得到的这个合取是不可满足的。这种一步一步的推理表明，一组要求可以如何排除一些配置，而并不是在声称冷藏本身在物理上保证了封口是完好的。

### 先认识这些词

- **真值赋值:** 为每个原子命题选定真或者假。

- **可满足:** 至少对一个赋值为真。

- **有效公式:** 对每一个赋值都为真。

### 一步步想清楚

**为什么三个原子命题有八行？**

每一个有两种选择，所以有 2×2×2=8 个赋值。

**p→q 什么时候为假？**

恰好在 p 为真而 q 为假时。

**一个可满足的公式，也可能在某处为假吗？**

可能。可满足只需要有一行为真；有效才要求所有行都为真。

### 给一个受限制的蕴含分类

对于原子命题 p、q，利用全部四个赋值，判断 F=(p→q)∧¬q 是可满足的、有效的，还是不可满足的。

**先选择方法**

这个合取首先强制要求 ¬q；然后在剩下的那些行上检查蕴含。

1. 当 q=真 时，¬q=假，所以 p 取任何一个值，都使 F 为假。

2. 当 q=假 并且 p=真 时，p→q 为假，所以 F 为假。

3. 当 q=假 并且 p=假 时，p→q 为真，并且 ¬q 为真，所以 F 为真。

**解释最终答案**

只有 (p,q)=(假,假) 满足 F。它是可满足的，但不是有效的。

**检验推理**

把蕴含改写，得到 (¬p∨q)∧¬q，在 ¬q 成立时它化简为 ¬p∧¬q。

### 数一数包含式“或”的模型个数

设 F=(p∨q)∧r，有三个相互独立的布尔原子命题。数一数满足它的真值赋值有多少个；“或”是包含式的。

**先选择方法**

把被强制的原子 r，与被允许的 p、q 的组合分开。

1. 合取要求 r=真。r=假 的全部四个赋值都不成立。

2. 当 r=真 时，p∨q 接受 (真,假)、(假,真) 和 (真,真)，但不接受 (假,假)。

3. 把唯一的 r 的选择与这三个组合配在一起，在 2³=8 个赋值中得到 1×3=3 个模型。

**解释最终答案**

F 有三个满足它的赋值，它是可满足的，但不是有效的。

**检验推理**

如果“或”是异或，那么两者都为真的那一对就会被去掉，个数会降到二。

### Leon 的进一步思考

**由内向外求值**

先计算带括号的子公式，再计算它们的父联结词。这样可以避免把一个很长的公式，当作带有偶然分组的非正式句子来读。

**经典的蕴含不是因果**

一个为真的蕴含，只是排除了“前提为真而结论为假”这一种组合。它并不解释事件为什么发生，也不给它们分配概率。

**注意这个边界:** 把“p only if q”读成 q→p。“Only if”给出的是一个必要条件，所以正确的翻译是 p→q。

在经典的二值语义下它是有效的：要么 p 为真，要么 p 为假而它的否定为真。

## 逻辑等价与安全改写

### 01 / 从一个故事开始

两个警报电路可能含有不同的门，却在完全相同的传感器设置下点亮同一盏警示灯。测试一种设置，只能确立一次一致；电路的等价要求在每一种可能的设置下都一致。代数改写可以在不查看电路外观的情况下，证明这种一致性。

一条替换规则必须作用在一个完整的子电路上，就像一条逻辑等价式必须作用在一个完整的子公式上一样。这个类比对于理解布尔行为是有用的，但是，当它们被翻译成带有状态的表达式的编程语言时，等价的公式不一定具有相同的求值成本或副作用。

### 02 / 理解原理

当每一个真值赋值都使公式 F 和 G 取相同的值时，F 和 G 就是逻辑等价的。等价支持在更大的公式内部做替换：可以把一个子公式换成与它等价的子公式，而不改变整体的真值。常用的规则包括双重否定、德摩根律、分配律、吸收律和蕴含消除。

真值表通过检查所有的赋值来证明等价；只要有一行不同，就推翻了等价。要区分公式 F↔G 和元层面的断言 F≡G：前者在某一个赋值下有一个真值，后者则对所有赋值进行量化。双条件式 F↔G 是永真式，当且仅当它的两边等价。这些都是语义上的论断；仅仅重新排列符号，或者只给出几个例子，是不够的。

### 03 / 逐项读懂公式

```text
F ≡ G ⇔ ∀α，α(F)=α(G)
¬(F∧G) ≡ ¬F∨¬G
F→G ≡ ¬G→¬F
```

α 遍历所涉及的原子命题的所有赋值。符号 ≡ 陈述的是公式之间的一种关系，而 ∧、∨、¬ 和 → 则是用来构造公式的。最后一条规则是逆否：它反转一个蕴含，同时对两边取否定。

它并不允许只把箭头反过来。使用一条改写规则时，要仔细地找出与这条规则相匹配的整个子公式，并且保持它周围联结词的分组不变。

### 04 / 先看一个完整例子

化简 F=¬(p∨¬q)。应用 德摩根律得到 ¬p∧¬¬q，再用双重否定得到 ¬p∧q。在 p=假 且 q=真 时，两个公式都是真的，但仅仅这一行并不是证明；是这些规则确立了四个赋值下的一致。

再看一个不等价的例子，比较 p→q 与 q→p。在 p=假 且 q=真 时，第一个是真的，而第二个是假的。只凭这一行，就立刻推翻了等价。p→q 的正确的、等价的反转是 ¬q→¬p，它保留了那个被禁止的组合：p=真 且 q=假。

### 先认识这些词

- **等价:** 在每一个赋值下，真值都一致。

- **逆命题:** P→Q 被反转之后的蕴含 Q→P。

- **逆否命题:** 蕴含 ¬Q→¬P，它与 P→Q 等价。

### 一步步想清楚

**为什么只有一行不同，就足以确定不等价？**

等价是对每一行都要成立的，所以只要有一次失败，就推翻了它。

**¬(p∧q) 是怎样分配的？**

对两边取否定，并把合取换成析取：¬p∨¬q。

**反转一个蕴含，能保持它不变吗？**

只有在对两边都取否定的逆否中才可以；单单是逆命题，通常是不同的。

### 化简一个嵌套的否定

利用等价律化简 F=¬(p∧¬q)，并在 p=真、q=假 时求出两种形式的值。

**先选择方法**

先把外层的否定推过合取，再去掉双重否定。

1. 德摩根律给出 ¬p∨¬¬q，因为否定把 ∧ 换成了 ∨。

2. 双重否定把 ¬¬q 化简为 q，得到 ¬p∨q。

3. 在 p=真、q=假 时，原来的内部 p∧¬q 是真的，所以 F=假。改写后的 ¬p∨q 是 假∨假=假。

**解释最终答案**

F≡¬p∨q≡p→q。取样的这一行是一致的，而这些规则则证明了所有行上的等价。

**检验推理**

在 p=假 时，改写后的公式无论 q 取什么都是真的，这与原来“对一个为假的合取取否定”相符。

### 推翻一个诱人的反转

比较 F=p→q 和 G=q→p。给出一个反例赋值，然后写出 F 的正确的、等价的反转。

**先选择方法**

找这样一行：其中一个蕴含的前件为假，而另一个蕴含的前件为真且结论为假。

1. 选择 p=假、q=真。F 是真的，因为它的前件 p 是假的。

2. G 是假的，因为 q 为真而 p 为假。所以 F 和 G 在这个赋值上不同。

3. 在反转的同时对两边取否定，得到 ¬q→¬p。它和 F 有同样的假的情形：p=真、q=假。

**解释最终答案**

逆命题不等价；逆否命题 ¬q→¬p 是等价的。

**检验推理**

当 p=q=真 时，F 和 G 碰巧都是真的；这个共同的一行并不能修复那个反例。

### Leon 的进一步思考

**子公式的边界很重要**

在 ¬(p∨q)∧r 中，否定只覆盖 p∨q。应用 德摩根律时，必须保持外层与 r 的合取不变。

**编程中的副作用需要另外小心**

纯粹的布尔等价，并不保证函数调用的执行顺序或次数是相同的。逻辑假定原子命题已经有了固定的真值。

**注意这个边界:** 把一个命题与它的逆命题混为一谈。p→q 与 q→p 通常是不同的；逆否在反转的同时，还要对两边取否定。

不能。等价要求 F↔G 在每一个赋值下都为真。一行只能确立局部的一致。

## 命题逻辑的范式

### 01 / 从一个故事开始

一座仓库只有在每一份检查清单都通过时，才会接收一批货物。每一份清单都允许几个可供选择的合格条件。这种“所有清单都要满足，每份清单中至少满足一个选项”的布局，就类似于合取范式。把一个逻辑要求重新组织成这种布局，可以帮助求解器系统地检查它，即使原来的那个句子看上去很不一样。

这种重新组织可能会使文档大幅膨胀，因为把几个备选项分配到各种组合上，会重复很多内容。一个很短的原始陈述，并不保证它等价的清单也很短。另外，“范式”这个词描述的是一种被允许的结构形式，而不是这个要求唯一的最佳版本。

### 02 / 理解原理

在否定范式中，公式只使用合取、析取，以及对原子命题的否定。先消去蕴含和双条件，然后利用 De Morgan 律和双重否定，把否定向内推。在合取范式中，公式是若干子句的合取，每个子句是若干文字的析取。文字是一个原子命题或者它的否定。把析取分配到合取上，可以把否定范式转换成等价的合取范式，但是可能造成指数级的增长。

单个文字可以充当只含一个文字的子句。命题逻辑中的 CNF 与文法的 Chomsky 范式毫无关系，尽管它们有相同的缩写。高效的 SAT 编码常常会引入新的变量，以便在保持可满足性的同时，使大小可以控制；这样的编码不应该与“在恰好原来那组变量上的等价”混为一谈。

### 03 / 逐项读懂公式

```text
F∨(G∧H) ≡ (F∨G)∧(F∨H)
CNF = C₁∧⋯∧Cₘ，其中每个 Cᵢ 是若干文字的析取
```

F、G 和 H 是任意的命题公式。Cᵢ 是第 i 个子句，m 是子句的个数。文字是某个原子命题 p 的 p 或者 ¬p；一个被取了否定的复合公式不是文字。

上面所示的分配律，是用来构造 CNF 的那个方向。如果出现空合取和空子句，就必须说明约定；这里普通的例题使用的都是非空的子句。

### 04 / 先看一个完整例子

把 p→(q∧r) 转换成 CNF。首先去掉蕴含：¬p∨(q∧r)。这个公式已经是否定范式了，因为它唯一的否定是直接作用在 p 上的。把 ∨ 分配到 ∧ 上，得到 (¬p∨q)∧(¬p∨r)。当 p=假 时，两个子句都自动成立。

当 p=真 时，第一个子句要求 q，第二个子句要求 r，这与原来的蕴含是吻合的。相比之下，(p∧q)∨r 并不是写成 CNF 的形式，尽管它可以被变换成 (p∨r)∧(q∨r)。分类所关心的，是所写出来的语法结构，而不仅仅是是否存在一个等价的 CNF。

### 先认识这些词

- **文字:** 一个原子命题，或者一个原子命题的否定。

- **子句:** 若干文字的析取，例如 p∨¬q。

- **合取范式:** 若干子句的合取；每一个子句都必须成立。

### 一步步想清楚

**p 是一个子句吗？**

是的。一个单独的文字就是只含一个文字的子句。

**¬(p∨q) 是否是否定范式？**

不是。把它改写成 ¬p∧¬q，使否定移到原子命题上。

**转换总是会缩短公式吗？**

不会。分配可能重复子公式，并且大幅增加公式的大小。

### 转换一条带有多个备选项的规则

在不引入新变量的情况下，把 (p∧q)→r 转换成 CNF。使用普通的二值逻辑。

**先选择方法**

先消去蕴含，然后把否定向内推。

1. A→B 等于 ¬A∨B，所以公式变成 ¬(p∧q)∨r。

2. De Morgan 律把 ¬(p∧q) 变成 ¬p∨¬q。

3. 结合律给出一个子句 ¬p∨¬q∨r，它已经是 CNF。

**解释最终答案**

CNF 是 ¬p∨¬q∨r。它只禁止 p=q=真 且 r=假 的情形。

**检验推理**

这恰好就是原来的规则中，前提为真而结论为假的那一种情形。

### 分配两对

把 (p∧q)∨(r∧s) 转换成 CNF。数一数子句的个数，并在 p=真、q=假、r=真、s=真 时求值。

**先选择方法**

一次分配一个合取；保留每一个配对。

1. 首先得到 [p∨(r∧s)]∧[q∨(r∧s)]。

2. 在每个方括号里面再分配：(p∨r)∧(p∨s)∧(q∨r)∧(q∨s)。

3. 共有四个子句。在给定的赋值下，每一个都是真的，因为 r 和 s 都是真的。

**解释最终答案**

这个有四个子句的 CNF 是真的，与原公式中为真的右边的合取一致。

**检验推理**

当 p=r=假 时，这四个子句不可能全部成立：子句 p∨r 是假的，而原公式中的两个合取也都是假的。

### Leon 的进一步思考

**把 CNF 当作一份清单来读**

一个为真的文字，满足的是它自己所在的那个子句，而不是每一个子句。在 (p∨q)∧r 中，即使让 p 为真，仍然留下了 r 这个要求。

**新变量改变了比较的方式**

如果一个变换为 p∧q 引入了 z，那么子句必须强制 z 与 p∧q 之间的关系。保持可满足性问的是：是否存在一个合适的 z，而不是 z 的每一种选择是否都与原公式一致。

**注意这个边界:** 把 CNF 与 DNF 混为一谈，或者以为每个 CNF 子句恰好有三个文字。一般的 CNF 允许任意长度的子句。

不是，因为否定作用在一个复合的表达式上。它等价的否定范式是 ¬p∨¬q，这同时也是一个单独的 CNF 子句。

## 逻辑后承与反模型

### 01 / 从一个故事开始

一位审查员要问的是：只要一组前提被满足，结论是否就一定无法避免。这个任务不同于问这个结论听上去是否合理，或者今天碰巧是否为真。要想推翻这个推理，审查员只需要一种可能的情形：其中所有的前提都成立，而结论却不成立。

这样的一种情形就是反模型。要想证明这个推理成立，就必须排除每一种这样的情形。这种方法把有效的推理与背景信念区分开来，并且使错误变得具体。它也解释了为什么相互矛盾的前提是危险的：当没有任何情形能满足它们时，在经典逻辑中，每一个结论都会空泛地变成无法避免的。

### 02 / 理解原理

如果每一个满足前提集合 Γ 中所有前提的赋值，也都满足公式 F，那么就说 Γ 蕴涵 F。对于有限多个前提，可以通过检查它们的合取与 ¬F 放在一起是否不可满足，来检验蕴涵。如果这个公式有一个满足它的赋值，那么这个赋值就是这个论证的一个反模型。

一个有效的论证，并不需要它的前提在现实世界里为真；有效性关心的是前提与结论之间的关系。同样，一个为真的结论，也不会使一个无效的推理变成有效的。常见的有效模式包括肯定前件（modus ponens）和否定后件（modus tollens）。肯定后件和否定前件，在没有额外前提的情况下是无效的。蕴涵是有方向的，而等价则相当于两个方向上都有蕴涵。

### 03 / 逐项读懂公式

```text
Γ ⊨ F ⇔ 不存在同时满足 Γ 的全部公式和 ¬F 的赋值
{P→Q, P} ⊨ Q
```

Γ 是一组公式的集合，⊨ 表示语义上的蕴涵。当一个赋值使 Γ 中的每一个成员都为真时，它就满足 Γ。F 是所提出的结论。第二行是肯定前件：这个蕴含与它的前件，迫使后件成立。

这个记号陈述的是元层面的关系；Γ 本身并不是一个额外的原子命题。对于一个有限的前提列表，在使用真值表或 SAT 检验之前，先用 ∧ 把这些前提合并起来。

### 04 / 先看一个完整例子

设 p 表示一个文件通过了验证，q 表示它被接受了。前提 p→q 和 q，并不蕴涵 p。取 p=假 且 q=真：这个蕴含是真的，第二个前提是真的，但结论 p 是假的。这是一个反模型，它也许对应着另一条单独的被接受的途径。

把第二个前提改成 ¬q。现在 p→q 和 ¬q 蕴涵 ¬p，因为假设 p 成立，就会迫使 q 成立，而这与 ¬q 矛盾。区别在于逻辑结构；这两个结论都不应当根据“被接受的文件通常都通过了验证”这种日常的可能性来判断。

### 先认识这些词

- **前提:** 在检验一个论证时，暂时假定为真的陈述。

- **反模型:** 使每个前提都为真而结论为假的赋值。

- **蕴涵:** 在前提的每一个模型中都为真的结论。

### 一步步想清楚

**一个为假的前提，会使一个论证的形式无效吗？**

不会。有效性关心的是，如果所有前提都成立，真值是否被保持。

**怎样用 SAT 来检验蕴涵？**

寻找一个同时满足这些前提和被否定的结论的赋值。

**为什么一个反模型就足够了？**

蕴涵要求在前提的每一个模型上都成功。

### 连接两个蕴含

前提 p→q、q→r 和 p，是否蕴涵 r？使用经典的命题逻辑。

**先选择方法**

假设所有前提都为真，并传播它们所要求的结果。

1. 第三个前提使 p 为真。

2. 因为 p→q 为真且 p 为真，所以 q 必须为真；否则这个蕴含就不成立了。

3. 现在 q→r 为真且 q 为真，所以 r 必须为真。不可能有反模型。

**解释最终答案**

是的，通过两次使用肯定前件，这些前提蕴涵 r。

**检验推理**

p=q=r=真 满足这些前提，所以这个结果并不是由不一致的前提造成的。

### 检验否定前件

p→q 和 ¬p 是否蕴涵 ¬q？如果可能，构造一个反模型。

**先选择方法**

先使所提出的结论为假，然后看前提是否还能保持成立。

1. 要使 ¬q 为假，选择 q=真。

2. 要满足 ¬p，选择 p=假。

3. 由于前件 p 为假，p→q 为真。两个前提都成立，但 ¬q 不成立。

**解释最终答案**

不蕴涵。p=假、q=真 是一个反模型；这条规则从来没有说过 p 是通向 q 的唯一途径。

**检验推理**

同一个赋值确实满足 p→q，因为不存在那个被禁止的“从真到假”的情形。

<a id="lab-logical-consequence-entailment-countermodels"></a>

### 找出每一个反模型

通过穷举两个布尔原子命题，来检验 p→q 是否蕴涵 p∨q。

```python
from itertools import product

rows = []
for p, q in product([False, True], repeat=2):
    premise = (not p) or q
    conclusion = q or p
    if premise and not conclusion:
        rows.append((p, q))
print("Countermodels:", rows)
assert rows == [(False, False)]
```

**在本地运行**

```sh
python logical-consequence-entailment-countermodels.py
```

**预期输出**

```text
Countermodels: [(False, False)]
```

**按执行顺序理解**

1. 枚举 (False,False)、(False,True)、(True,False)、(True,True)。

2. 在 (False,False) 处，蕴含是真的，而 p∨q 是假的。

3. 其他三行都不是反模型；被保存下来的那一对就推翻了蕴涵。

**逐步读懂代码**

product 生成 p 和 q 的全部四种选择。for 循环把每一对解包到这两个名字里。在 Python 中，not 对一个真值取否定，or 表示包含式的析取。因此 (not p) or q 表示蕴含。

if 条件只保留前提为真而结论为假的那些行。append 把这一对加入列表。print 显示完成后的列表，assert 检查预期的结果。这种有限的穷举只检验了这一个论证；原子命题更多的公式，需要更多的行。

### Leon 的进一步思考

**用结论来引导搜索**

要反驳 Γ⊨p∨q，从 p=q=假 开始，因为这是使结论不成立的唯一方式。然后检验前提是否仍然可以保持为真。

**把一致性与有效性区分开**

在把由 p 和 ¬p 得出的蕴涵，解释成有用的知识之前，先检验这些前提是否有任何模型。仅有逻辑上的有效性，并不能回答这个不同的问题。

**注意这个边界:** 只检查结论为真的那些赋值。反模型必须使每一个前提都为真，并且使结论为假。

## 谓词、量词与作用域

### 01 / 从一个故事开始

一位工作坊的协调员说：“每一位学徒都有一位导师。”这允许不同的学徒有不同的导师。而说“对每一位学徒来说，都有一位导师”，根据措辞的不同，却可能表示有一个人指导所有的学徒。谓词逻辑把这个区别，强制地表现为明确的量词顺序。

它还要问论域里包含什么：是所有的人，是工作坊的成员，还是别的什么。一个精确的公式，就像一张认真填写好的行政表格，有命名的角色和清楚的作用域。公式本身并不提供这些事实；必须由一个解释来说明有哪些对象，以及它们之间实际上成立哪些关系。

### 02 / 理解原理

谓词逻辑增加了在论域上取值的变量、表示性质和关系的谓词，以及全称量词和存在量词。在通常的论域非空的约定下，∀xF 要求 F 对论域中的每一个对象都成立，而 ∃xF 则需要一个见证。“所有 A 都是 B”用 ∀x(A(x)→B(x)) 来翻译；“有些 A 是 B”用 ∃x(A(x)∧B(x)) 来翻译。混合的量词顺序很重要，因为一个存在的见证，可能依赖于它前面的全称变量。

否定会交换量词的类型，并对它的作用域取否定。一个变量的出现，只有在对应量词的作用域之内才是被约束的；自由变量需要一个赋值。把量词移过公式，需要满足一些附加条件，尤其是被移动的变量不能在另一个公式中自由出现。必要时要给被约束的变量改名，以避免意外的捕获。

### 03 / 逐项读懂公式

```text
∀x∃y M(x,y) 与 ∃y∀x M(x,y) 的对比
¬∀x F ≡ ∃x ¬F;  ¬∃x F ≡ ∀x ¬F
```

M(x,y) 是一个二元关系，这里读作“y 指导 x”。x 和 y 在所说明的论域中取值。在第一个公式里，y 可以依赖于 x；在第二个公式里，必须有同一个 y 对每个 x 都有效。

F 是被量词所作用的范围，其中可能含有 x。否定的规律会保持其他自由变量及其赋值不变。每当所想要的分组可能产生歧义时，就用括号来标明作用域。

### 04 / 先看一个完整例子

取论域 {Ada, Ben}。设指导关系包含 M(Ada,Ben) 和 M(Ben,Ada)，没有自己指导自己的对。那么 ∀x∃y M(x,y) 是真的：Ben 为 Ada 提供了这个要求的见证，Ada 为 Ben 提供了见证。但是 ∃y∀x M(x,y) 是假的：没有任何一个人同时指导两个人。

第一个公式的否定是 ∃x∀y ¬M(x,y)，意思是在这个论域里，有某个人没有任何导师。另外，“并非每一位学徒都得到认证”变成 ∃x(Apprentice(x)∧¬Certified(x))；如果仅仅断言 ∃x¬Certified(x)，选中的可能是一个非学徒，那样说出来的东西就更弱了。

### 先认识这些词

- **论域:** 变量可以指称的对象所组成的非空集合。

- **见证:** 使一个存在陈述为真的对象。

- **作用域:** 公式中受某个量词或联结词支配的那一部分。

### 一步步想清楚

**在 ∀x∃y 中，见证可以不同吗？**

可以。每选定一个 x 之后，合适的 y 可以依赖于它。

**我们怎样否定 ∃xP(x)？**

写成 ∀x¬P(x)：每一个候选对象都不满足这个性质。

**为什么对“所有 A 都是 B”使用蕴含？**

只有 A 类的对象必须通过 B 的检验；不属于 A 的对象不受任何要求。

**可以交换这两个量词而不改变命题吗？**

一般不可以。所给的这个关系，使“全称—存在”为真，而“存在—全称”为假，所以它是对这个所谓的等价的一个反模型。

### 一个会变化的见证

设论域是 {1,2,3}，R(x,y) 表示 x≠y。求 ∀x∃yR(x,y) 与 ∃y∀xR(x,y) 的真假。

**先选择方法**

对第一个公式，为每个 x 找一个见证；对第二个公式，把每一个固定的 y 拿去对所有的 x 做检验。

1. 对于 x=1 选 y=2；对于 x=2 选 y=1；对于 x=3 选 y=1。每个 x 都有一个与它不同的伙伴。

2. 对于论域中任何一个固定的 y，全称的 x 都包括 x=y 这一种情形。

3. 在 x=y 时，R(x,y) 是假的，所以没有哪一个 y 能通过这三个 x 的全部检验。

**解释最终答案**

第一个公式是真的，第二个是假的；交换不同种类的量词，会改变意义。

**检验推理**

不相等的有序对有六个，但三个对角线上的对不存在；每一行都有一个见证，而每一列都有一个失败。

### 否定一条全称的类别规则

设学生是 {A,B,C}，并且 Pass(A)=真，Pass(B)=假，Pass(C)=真。翻译并求值“并非每位学生都及格”。假设这个论域只包含学生。

**先选择方法**

对全称量词取否定，然后找一个具体的不及格的学生。

1. “每位学生都及格”是 ∀xPass(x)，因为论域已经把 x 限制为学生。

2. 取否定得到 ¬∀xPass(x)≡∃x¬Pass(x)。

3. 选 x=B。Pass(B) 是假的，所以 ¬Pass(B) 是真的，B 就是所需要的见证。

**解释最终答案**

这个陈述是真的。它断言的是至少有一个人不及格，而不是每个人都不及格。

**检验推理**

A 和 C 及格了，所以更强的陈述 ∀x¬Pass(x) 是假的。

### 否定一个带量词的陈述并检验它

使用代码里的三名学生和两位导师。把“每个学生都有一位导师”取否定，并判断在删除 (Bo,Noah) 之后，这个否定是否变成真的。

**先选择方法**

把否定依次推过每一个量词，然后寻找一个明确的见证。

1. ¬∀x∃yR(x,y) 变成 ∃x¬∃yR(x,y)。

2. ¬∃y 变成 ∀y¬，得到 ∃x∀y¬R(x,y)。

3. 删除之后，R(Bo,Ivy) 和 R(Bo,Noah) 都是假的。选择 x=Bo。

**解释最终答案**

删除之后，这个否定是真的。Bo 就是见证。

**检验推理**

删除之前，每个学生的见证列表都是非空的，所以这个否定是假的。

### 在有限模型中寻找见证与反例

一个社团里的每一位学生都有一位导师。米娜（Mina）听到这个，就以为每个人共用同一位导师。一张小小的表就推翻了她的假设：Ana 和 Cy 跟着 Ivy，而 Bo 跟着 Noah。每个学生都有人指导，但没有任何一位导师涵盖这三个人。米娜用嵌套的循环，使这两个量词的顺序变得清晰可见。

```python
students = ["Ana", "Bo", "Cy"]
mentors = ["Ivy", "Noah"]
relation = {("Ana", "Ivy"), ("Bo", "Noah"), ("Cy", "Ivy")}

def inspect(students, mentors, relation):
    witnesses = {x: [y for y in mentors if (x, y) in relation] for x in students}
    every_has_someone = all(witnesses[x] for x in students)
    shared = [y for y in mentors if all((x, y) in relation for x in students)]
    uncovered = [x for x in students if all((x, y) not in relation for y in mentors)]
    assert bool(uncovered) == (not every_has_someone)
    return witnesses, every_has_someone, shared, uncovered

witnesses, every, shared, uncovered = inspect(students, mentors, relation)
print("witnesses:", witnesses)
print("every student has a mentor:", every)
print("one mentor for everybody:", bool(shared))
assert every and not shared
broken = relation - {("Bo", "Noah")}
print("counterexample after removal:", inspect(students, mentors, broken)[3])
assert inspect([], mentors, relation)[1] is True
assert inspect(students, [], relation)[1] is False
```

**预期输出**

```text
every student has a mentor: True
one mentor for everybody: False
counterexample after removal: ['Bo']
```

**按执行顺序理解**

1. 为每一个学生建立一份见证列表。内层的存在搜索，可以为外层的每个学生选择不同的导师。

2. 要找共同的导师，就把搜索反过来：先选一位导师，然后要求这位导师涵盖每一位学生。

3. 找出没有被覆盖的学生，方法是检查每一位可能的导师都失败。这构造了否定命题，而不仅仅是打印一个 False。

4. 检查空的论域。对于没有学生的情形，“全部”是真的；而一个非空的学生集合却没有导师，就使原来的论断失败。

**逐步读懂代码**

设 S 是学生的集合，M 是导师的集合，R(x,y) 表示 y 指导 x。第一个陈述是：对 S 中的每一个 x，都存在 M 中的某个 y，使得 R(x,y)。第二个是：存在 M 中的某个 y，对 S 中的每一个 x 都有 R(x,y)。一个共同的见证可以证明第二个，因此也证明了第一个；而各自分开的见证只能证明第一个。

对第一个陈述取否定，得到：存在 S 中的某个 x，对 M 中的每一个 y，都有 not R(x,y)。去掉 Bo–Noah 这一对之后，Bo 就成了这个反例。设有 |S| 名学生和 |M| 位导师，这些直接的检查需要 O(|S||M|) 次关系查询。这里假定集合的查找平均是 O(1)。

这检查的是一个指定的有限解释。在一张表上得到的结果，并不能证明一个公式在所有解释下都是有效的，也不能解决任意的一阶逻辑有效性问题。论域的假设应当写在问题的陈述里；对于空集的行为，不应当在看到一个不方便的结果之后再去临时修补。

### Leon 的进一步思考

**把有限论域展开，来检验含义**

在论域 {1,2} 上，∀xP(x) 变成 P(1)∧P(2)，而 ∃xP(x) 变成 P(1)∨P(2)。这就把量词与熟悉的命题运算联系了起来。

## 英语与量词公式的互译

### 01 / 从一个故事开始

Iris 在为学校的储物间写使用规则，Leon 负责校对。Iris 写道：“每个学生都有一个储物柜。”Leon 问：你是说每个学生都有自己的储物柜，还是说存在一个所有学生共用的储物柜？在英语里，同一句话两种读法都说得通，可管理员必须按其中一种去执行。谓词逻辑用量词的顺序把这个选择摆到明处。从左往右读，每个量词都是依次做出的一次选择，后面的选择可以依赖前面的选择。

反过来翻译是同一种本领。Leon 把公式当作一个按顺序讲的小故事来读：“任选一个学生。那么有一个储物柜是这个学生拥有的。”按这个顺序慢慢读，再拿一个只有两个学生、两个储物柜的小模型去检验这个故事，大多数错误都能查出来。

### 02 / 理解原理

把一句话翻译成逻辑，分四步。第一步，确定论域：x 可以是哪一类东西？第二步，给谓词起名，例如 Student(x) 和 Has(x, y)。第三步，按出现的顺序列出量词词语：每个、有些、没有、至少、恰好。第四步，确定每个量词的范围。像“每个学生”这样的限定，在 ∀ 后面变成蕴含；“有些学生”则在 ∃ 后面变成合取。公式框里的模式涵盖了常见的句子，包括“没有”“并非每个”“只有”“至多一个”和“恰好一个”。

把公式翻译回英语时，从左到右读出量词，并给每个变量安排角色：“对每个 x，存在 y，使得 ……”。然后把字母换成名词。再用一个小模型检验结果：造一个让这句话为真的模型，再造一个让它为假的模型。如果你的英语读法分不出这两个模型，读法就是错的。

同类量词可以交换：∀x∀y 与 ∀y∀x 含义相同，∃x∃y 与 ∃y∃x 含义相同。不同类的量词则不能交换。在 ∀x∃y φ 中，见证 y 可以依赖 x。在 ∃y∀x φ 中，必须有同一个 y 对所有 x 都成立。所以 ∃y∀x φ 总能推出 ∀x∃y φ，因为那个唯一的 y 对每个 x 都适用，但反过来可能不成立。

量词提取是把量词从公式的一部分里移到外面。只有当该变量在另一部分中不是自由出现时，才允许这样做。如果是自由出现的，就先给约束变量改名。公式框里的规则在论域至少有一个对象时成立，这是通常的假设。要留意蕴含的前件：∀ 一旦从那里移出，就变成 ∃，∃ 则变成 ∀。还要留意合并的陷阱：∀ 对 ∧ 可以分配，对 ∨ 却不行；∃ 对 ∨ 可以分配，对 ∧ 却不行。

### 03 / 逐项读懂公式

```text
每个 A 都是 B         ∀x (A(x) → B(x))
有些 A 是 B           ∃x (A(x) ∧ B(x))
没有 A 是 B           ∀x (A(x) → ¬B(x))      ≡   ¬∃x (A(x) ∧ B(x))
并非每个 A 都是 B     ∃x (A(x) ∧ ¬B(x))
只有 A 才是 B         ∀x (B(x) → A(x))
至多有一个 A          ∀x ∀y ((A(x) ∧ A(y)) → x = y)
恰好有一个 A          ∃x (A(x) ∧ ∀y (A(y) → y = x))

同类量词可交换：      ∀x∀y φ ≡ ∀y∀x φ            ∃x∃y φ ≡ ∃y∃x φ
不同类量词，单向成立： ∃y∀x φ ⊨ ∀x∃y φ           （反方向不成立）

量词提取（x 在 R 中不自由，且论域非空）：
  (∀x P) ∧ R ≡ ∀x (P ∧ R)       (∃x P) ∧ R ≡ ∃x (P ∧ R)
  (∀x P) ∨ R ≡ ∀x (P ∨ R)       (∃x P) ∨ R ≡ ∃x (P ∨ R)
  (∀x P) → R ≡ ∃x (P → R)       (∃x P) → R ≡ ∀x (P → R)
  R → (∀x P) ≡ ∀x (R → P)       R → (∃x P) ≡ ∃x (R → P)
不能合并：            (∀x P) ∨ (∀x Q) ≢ ∀x (P ∨ Q)       (∃x P) ∧ (∃x Q) ≢ ∃x (P ∧ Q)
```

A(x) 和 B(x) 是谓词，也就是一个对象要么具有、要么不具有的性质。P 和 Q 也是谓词，R 是 x 不自由出现的公式，例如 TripOn 这样的一个简单命题。φ 代表任意公式。符号 = 表示两个对象是同一个，≠ 表示不是同一个。符号 ≡ 表示“在每个模型中真值都相同”。符号 ⊨ 表示“凡是使左边为真的模型也使右边为真”。符号 ≢ 表示“不等价”。

论域是变量取值的对象集合。如果周围没有量词捕获某个变量，它就是自由的，否则是约束的。提取规则要求 R 里没有自由的 x，这样移出去的量词才不会把属于 R 的 x 捕获进来。

### 04 / 先看一个完整例子

取一个有四个人的模型：Leon、Mia、Emma 和 Jack。关系 Admires(x, y) 恰好对四对成立：(Leon, Mia)、(Mia, Emma)、(Emma, Mia) 和 (Jack, Mia)。翻译并判断五个句子。“每个人都敬佩某个人”是 ∀x∃y Admires(x, y)。它为真，而且见证在变：Leon 对应 Mia，Mia 对应 Emma，Emma 对应 Mia，Jack 对应 Mia。“有一个人被所有人敬佩”是 ∃y∀x Admires(x, y)。它为假：Mia 被 Leon、Emma 和 Jack 敬佩，却不被她自己敬佩。“有一个人被其他所有人敬佩”是 ∃y∀x (x ≠ y → Admires(x, y))。取 y = Mia 时为真。“没有人敬佩自己”是 ∀x ¬Admires(x, x)，为真。“恰好有一个人敬佩 Emma”是 ∃x (Admires(x, Emma) ∧ ∀z (Admires(z, Emma) → z = x))，取 x = Mia 时为真。

再把一个公式读回英语。∃x∀y ¬Admires(y, x) 的意思是：有一个人没有被任何人敬佩。它为真，因为没有人敬佩 Leon。它也是 ∀x∃y Admires(y, x)，即“每个人都被某个人敬佩”的否定。

接下来看一次提取。“如果每个人都付了款，旅行就成行”是 (∀x Paid(x)) → TripOn。TripOn 里没有 x，所以规则给出 ∃x (Paid(x) → TripOn)。读出来是：存在某个人，如果这个人付了款，旅行就成行。听起来奇怪，但它恰好在“有人没付款或者旅行成行”时为真，这正是原句的意思。前件里的 ∀ 变成了 ∃。

相反的句子是“如果有人付了款，旅行就成行”。它是 (∃x Paid(x)) → TripOn，等价于 ∀x (Paid(x) → TripOn)：每一个付款的人单独就够了。两种情况下量词都发生翻转，是因为蕴含的前件处于否定的位置。

### 先认识这些词

- **见证:** 使 ∃ 命题为真的那个对象。在 ∀x∃y 中，y 的见证可以随 x 变化。

- **量词提取:** 把量词从公式某个部分的内部移到最前面，而不改变含义。

- **自由变量:** 周围没有量词捕获的变量，它的取值必须从外部给定。

- **反模型:** 一个小模型，其中一个公式为真而另一个为假，说明二者不等价。

- **前束范式:** 所有量词都在最前面，其余部分不再含有量词的公式。

### 一步步想清楚

**为什么“每个 A 都是 B”用 → 而不用 ∧？**

这句话只涉及属于 A 的东西。对于不属于 A 的东西，蕴含为真，不会造成妨碍。如果用 ∧，公式就变成了“所有东西既是 A 又是 B”。

**“没有 A 是 B”有哪两种写法？**

写成 ∀x (A(x) → ¬B(x))，即每个 A 都不是 B；或者写成 ¬∃x (A(x) ∧ B(x))，即不存在既是 A 又是 B 的东西。二者等价。

**为什么从 (∀x P(x)) ∧ Q(x) 提取之前必须先改名？**

Q(x) 里的 x 是自由的。把 ∀x 移到 Q(x) 外面会捕获它，改变含义。先把约束变量改名为 z：∀z (P(z) ∧ Q(x))。

**为什么 ∃y∀x φ 总能推出 ∀x∃y φ？**

如果有同一个 y 对每个 x 都成立，那么每个 x 都可以用这个 y 作见证。反过来不行，因为不同的 x 可能需要不同的 y。

### 翻译三个句子并在模型上检验

论域包含学生 Mia、Jack、Iris 和储物柜 L1、L2。Student 和 Locker 是谓词，Has(x, y) 对 (Mia, L1)、(Jack, L2)、(Iris, L2) 成立。请翻译并判断：(a) 每个学生都有一个储物柜；(b) 有某个储物柜被两个不同的学生共用；(c) 没有哪个储物柜被所有学生使用。

**先选择方法**

按英语词语的顺序写量词，用对应的谓词限定每个量词，并寻找明确的见证或反例。

1. (a) ∀x (Student(x) → ∃y (Locker(y) ∧ Has(x, y)))。见证：Mia 用 L1，Jack 用 L2，Iris 用 L2。三个学生都满足，所以 (a) 为真。

2. (b) ∃y (Locker(y) ∧ ∃x ∃z (x ≠ z ∧ Student(x) ∧ Student(z) ∧ Has(x, y) ∧ Has(z, y)))。取 y = L2，x = Jack，z = Iris。他们是两个不同的学生，都拥有 L2，所以 (b) 为真。

3. (c) ∀y (Locker(y) → ¬∀x (Student(x) → Has(x, y)))。对 L1，Jack 没有它。对 L2，Mia 没有它。所以两个储物柜都不被所有学生拥有，(c) 为真。

4. “每个学生都有一个储物柜”的共用读法 ∃y (Locker(y) ∧ ∀x (Student(x) → Has(x, y))) 正好与 (c) 相反，所以在这个模型里为假。这个模型把两种读法区分开了。

**解释最终答案**

在这个模型里，翻译后的三个句子都为真，而“每个学生都有一个储物柜”的共用读法为假。

**检验推理**

如果 Jack 和 Iris 也都拥有 L1，那么 L1 就被三个学生全部拥有，(c) 就会变成假。

### 把公式读出声，并比较两种嵌套顺序

设 F = ∀x (Cat(x) → ∃y (Mouse(y) ∧ Chases(x, y)))，G = ∃y (Mouse(y) ∧ ∀x (Cat(x) → Chases(x, y)))。论域有猫 Tom、Kit 和老鼠 m1、m2，Chases 对 (Tom, m1) 和 (Kit, m2) 成立。请用英语读出二者，判断真假，并证明 G 蕴含 F。

**先选择方法**

按顺序读每个量词。对 G，逐只检验每只老鼠。要证明蕴含，就取 G 的任一模型，构造出 F 所要求的见证。

1. F 读作：每只猫都追某只老鼠。G 读作：有一只老鼠被每只猫追。

2. F 为真：Tom 追 m1，Kit 追 m2。

3. G 为假：m1 没有被 Kit 追，m2 没有被 Tom 追。没有哪只老鼠同时被两只猫追。

4. G 蕴含 F：在 G 为真的任何模型中，取那只被每只猫追的老鼠 y。于是每只猫都有一只自己追的老鼠，就是 y，所以 F 成立。反过来不成立，上面的模型就是例子。

**解释最终答案**

在这个模型里，F 为真，G 为假，所以二者不等价。G 总能推出 F，但 F 推不出 G。

**检验推理**

如果 Kit 也追 m1，那么 m1 被两只猫都追，G 就变成真。

### 一步步提取量词并检验结果

把量词提到最前面。(a) (∀x P(x)) ∧ (∃x Q(x))。(b) (∀x P(x)) → (∃y Q(y))。然后在论域 {1, 2} 上检验 (b)，其中 P 只对 1 成立，Q 对任何对象都不成立。

**先选择方法**

先确认该变量在另一部分中不是自由的，必要时改名。一次只用一条规则，从前件移出时要把 ∀ 翻转为 ∃。

1. (a) 两个 x 是不同的约束变量。把第二个改名：(∀x P(x)) ∧ (∃y Q(y))。

2. 先移出 ∀x：(∃y Q(y)) 中没有自由的 x，规则给出 ∀x (P(x) ∧ ∃y Q(y))。再移出 ∃y：P(x) 中没有自由的 y，规则给出 ∀x ∃y (P(x) ∧ Q(y))。

3. (b) 把 ∀x 从前件移出，它翻转：∃x (P(x) → ∃y Q(y))。再把 ∃y 从后件移出，它保持不变：∃x ∃y (P(x) → Q(y))。

4. 检验 (b)。在论域 {1, 2} 上，P 只对 1 成立，Q 对任何对象都不成立：原式的前件为假，因为 P(2) 不成立，所以原式为真。在结果式中取 x = 2：P(2) 为假，所以对任何 y，蕴含都为真。二者都为真。

**解释最终答案**

(a) 变成 ∀x ∃y (P(x) ∧ Q(y))。(b) 变成 ∃x ∃y (P(x) → Q(y))。在检验模型中，(b) 的两边都为真。

**检验推理**

若 P 对 1 和 2 都成立而 Q 对任何对象都不成立，原式是“真蕴含假”，为假。结果式中每一对都是 P(x) 为真、Q(y) 为假，每个蕴含都为假。二者都为假。

### 在小模型上检验翻译与提取规则

Jack 想在相信自己的翻译之前先检验一下。他在 Python 里保存了一个小模型：一个人名列表和一个有序对集合。Python 的 all 和 any 分别扮演 ∀ 和 ∃。前半部分在例子中的“敬佩”模型上检验五个英语句子。后半部分在所有只有 1 到 3 个对象的模型以及空模型上检验提取规则。

```python
from itertools import product

# Part 1. English sentences checked on one small model.
people = ["Leon", "Mia", "Emma", "Jack"]
pairs = {("Leon", "Mia"), ("Mia", "Emma"), ("Emma", "Mia"), ("Jack", "Mia")}


def admires(x, y):
    return (x, y) in pairs


sentences = [
    ("Everyone admires someone", all(any(admires(x, y) for y in people) for x in people)),
    ("Someone is admired by everyone", any(all(admires(x, y) for x in people) for y in people)),
    ("Someone is admired by everyone else",
     any(all(admires(x, y) for x in people if x != y) for y in people)),
    ("Nobody admires themselves", all(not admires(x, x) for x in people)),
    ("Exactly one person admires Emma",
     any(admires(x, "Emma") and all(x == z for z in people if admires(z, "Emma"))
         for x in people)),
]
for text, value in sentences:
    print(f"{text}: {value}")

# Part 2. Test quantifier-extraction rules on every model with 0 to 3 objects.
# A model is a subset for P, a subset for Q and a truth value for R.
rules = [
    ("(all x P) and R  =  all x (P and R)",
     lambda D, P, Q, R: (all(P[x] for x in D) and R) == all(P[x] and R for x in D)),
    ("(exists x P) or R  =  exists x (P or R)",
     lambda D, P, Q, R: (any(P[x] for x in D) or R) == any(P[x] or R for x in D)),
    ("(all x P) -> R  =  exists x (P -> R)",
     lambda D, P, Q, R: ((not all(P[x] for x in D)) or R) == any((not P[x]) or R for x in D)),
    ("(exists x P) -> R  =  all x (P -> R)",
     lambda D, P, Q, R: ((not any(P[x] for x in D)) or R) == all((not P[x]) or R for x in D)),
    ("(all x P) or (all x Q)  =  all x (P or Q)",
     lambda D, P, Q, R: (all(P[x] for x in D) or all(Q[x] for x in D)) == all(P[x] or Q[x] for x in D)),
    ("(exists x P) and (exists x Q)  =  exists x (P and Q)",
     lambda D, P, Q, R: (any(P[x] for x in D) and any(Q[x] for x in D)) == any(P[x] and Q[x] for x in D)),
]
for label, rule in rules:
    verdict = "holds on every model with 1-3 objects"
    for size in (1, 2, 3):
        D = range(size)
        for p, q, r in product(product([False, True], repeat=size),
                               product([False, True], repeat=size), [False, True]):
            if not rule(D, p, q, r):
                verdict = f"fails: {size} objects, P={list(p)}, Q={list(q)}, R={r}"
                break
        if verdict.startswith("fails"):
            break
    empty = "" if rule(range(0), (), (), False) and rule(range(0), (), (), True) else "  (fails on 0 objects)"
    print(f"{label}: {verdict}{empty}")
```

```text
(exists x P) and (exists x Q)  =  exists x (P and Q): fails: 2 objects, P=[False, True], Q=[True, False], R=False
```

**按执行顺序理解**

1. people 和 pairs 就是整个模型：一个论域和一个关系。admires(x, y) 判断这一对是否在关系中。

2. 每个句子都写成嵌套的 all 和 any，顺序与量词的顺序一致。生成器里的条件“if x != y”扮演 ∀ 后面的蕴含 x ≠ y → ……。

3. 每条规则是一个函数，在一个模型上计算等式两边。一个模型由两个真值列表 P 和 Q（每个对象一个）以及一个真值 R 组成。

4. 循环遍历所有含 1、2、3 个对象的模型。两边第一次不同的模型被当作反例打印出来。

5. 最后的检查问：这条规则在没有任何对象时是否也成立。Python 里对空集合做 all 得到 True，做 any 得到 False，正如 ∀ 和 ∃ 在空论域上的表现。

**逐步读懂代码**

前五行与例子一致。看第三个句子：去掉条件 x != y，就得到第二个句子，而它为假，因为没有人敬佩自己。正是这个限定把“所有人”变成了“其他所有人”。

测试的六条规则中，四条在所有小模型上都成立，两条立刻失败。两条合并规则在含两个对象的模型上失败：P 对一个对象成立，Q 对另一个对象成立。这时每个对象都满足 P 或 Q，可是 P 和 Q 都不是对所有对象成立。在同一个模型里，P 和 Q 各自都有见证，但没有哪一个对象同时满足二者。

其中有三条规则在没有对象时也不成立，所以逻辑课通常假设至少有一个对象。通过了最多三个对象的所有模型，只是证据，不是证明。失败则是真正的反例，而通过只是提醒你去找证明。提取规则本身是通过对任意论域进行推理来证明的。

### Leon 的进一步思考

**用能区分两种读法的模型检验翻译**

造一个小到可以手算的模型，让一种读法为真、另一种为假。对储物柜规则，取学生 Mia 和 Jack，储物柜 1 和 2，Mia 拥有 1，Jack 拥有 2。“每个学生各有一个储物柜”为真，“有一个储物柜被所有学生拥有”为假。如果两种读法在某个模型里结果一样，说明这个模型没有起到检验作用。

**提取是改写，所以要逐条规则连着写并标明名称**

一次只用一条规则，把过程写出来。对 (∀x P(x)) → (∃y Q(y))：先把 ∀x 从前件移出，它翻转，得到 ∃x (P(x) → ∃y Q(y))；再把 ∃y 从后件移出，它保持不变，得到 ∃x ∃y (P(x) → Q(y))。要保持量词原来出现的顺序。这个例子里两个量词的先后其实无关紧要，因为 P(x) 和 Q(y) 没有共用变量；但只要有 Admires(x, y) 这样的公式把它们联系起来，顺序就会影响含义。

**论域非空这个假设确实在起作用**

有三条提取规则在没有任何对象的论域上不成立。没有对象时，(∀x P) ∧ R 就等于 R，而 ∀x (P ∧ R) 为真。当 R 为假时，二者不同。后面的程序会演示这一点。逻辑课通常假设至少有一个对象，以保证这些规则成立。如果题目允许空论域，就要把每条规则重新检查一遍。

**注意这个边界:** 把量词从蕴含的前件中移出来，却没有翻转。(∃x Paid(x)) → TripOn 并不等于 ∃x (Paid(x) → TripOn)。前者说只要有人付了款，旅行就成行。后者只要有一个人没付款就为真，哪怕旅行取消了。正确的提取结果是 ∀x (Paid(x) → TripOn)。
